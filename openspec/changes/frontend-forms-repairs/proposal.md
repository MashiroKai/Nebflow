# Frontend forms and background controls

This proposed change implements the current authorized frontend repair request, not a historical accepted specification. It does not change tool prompts or the fallback product contract.

- Provider forms keep their draft after validation, rejection, a missing acknowledgement or a closed connection; only the acknowledgement of that very save closes them.
- Removing a todo tag is submitted; refreshes neither overwrite an open task draft nor carry a draft to another target.
- JeV probe parameters follow the existing backend protocol (adapter id, endpoint, key or key reference); the form's current model is carried as one optional additive field.
- A category model update clears only the pins owned by that category. Other and unknown categories keep theirs; the main slot owns ordinary main conversations.
- The background badge counts active rows apart from retained rows; delegate wake follows the authoritative wakeability; the mobile background conversation keeps its status capsule, details control and single stop control.
