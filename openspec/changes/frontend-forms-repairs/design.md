## Boundaries

Reuse the existing forms, stores and session classification; no new framework or component layer.

- Provider save: `saveProviderWithAck` sends `updateConfig` with a correlation id; the gateway echoes it on `configUpdated` and `error`. Only a matching successful reply confirms; a matching error, a closed socket or no reply within the timeout keeps the draft and the failure is reported on the form. The local config snapshot changes only after confirmation; the follow-up `configData` refresh stays authoritative. The form closes only when the confirm handler returns `true`, closing is idempotent, and the save button is disabled while a save is pending. A JeV or image-generation save that fails on the network reports the failure too.
- Refused save: the gateway's `error` frame for a refused `updateConfig` names the request (`msgType`) and echoes the correlation id. The web client leaves a correlated refusal to the form that sent it and does not treat it as a conversation turn error (no busy reset, no error row). A refusal without a correlation id keeps the generic handling, so other callers of `updateConfig` behave as before.
- Task drafts: a form node belongs to one target (task id, or none for a new task) and to one draft round. A refresh reuses the open node with its value, focus and caret; a different target, or starting an edit or a new task again, rebuilds it. In the mobile scheduled-task drawer every start of an edit or create begins a new round, so reopening the same task does not bring back a dismissed draft. Only an already-editing todo row is reusable, so starting an edit still builds the edit form.
- JeV: the authenticated diagnostic route receives the adapter id, endpoint, optional current model and credential overrides, and persists nothing. `model` is additive: callers that omit it keep stored/default resolution. The form never sends a probe without an adapter: the gateway would otherwise probe its default adapter with the form's other values and report on something the user did not pick.
- Model pins: `ModelRoles.pinOwnerSlot` attributes a pin to a slot (the five slot families; ordinary main conversations to the main slot; slotless background families and blank ids to nobody). A category update clears the in-memory pin and the persisted session model only for pins owned by that slot that differ from the newly effective preferred model. A session choice made afterwards has priority until the next edit of that category. A restart clears every session model, so no pin outlives the process.
- Background: the badge shows the number of active rows, computed over the same row plan as the list (archived store children and flow steps included); retained rows keep the entry reachable. Wake is rendered unless the authoritative freeze block says the delegate is not wakeable. Without a block, every delegate-frozen reason is wakeable, matching the gateway's table, so a live frame and a snapshot give the same answer.
- Mobile background chrome: the capsule, the details control and the single stop control are existing behavior that this change pins with a consumer test. Which metadata rows the details show (the worktree and plugin rows) belongs to `frontend-bgagent-mobile-detail-repairs`.

Open product decision, behavior kept: provider-failure delegate reasons (`llm-failure`, `cancelled-by-quota`) show a wake button while their copy says the engine recovers by itself. The gateway marks them wakeable. Hiding the button would need the gateway's wakeable reading and its wake gate to change together with the frontend classification, so this change keeps the current behavior and only removes the dependence on the data source.

Runtime verification against a real isolated instance remains necessary, including real reconnects, a rejected config and the mobile drawer path.
