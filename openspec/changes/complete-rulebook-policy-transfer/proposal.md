## Why

The first rulebook draft shortened the engineering instructions but did not fully preserve several effective contracts. Some permission and acceptance wording also changed meaning. Human-owned AGENTS.md cannot be reduced safely until those gaps are identified and covered without copying its historical narrative.

## What Changes

- Preserve effective prompt, workspace, isolation, coordination, recovery, merge and release requirements in task-routed rulebook references.
- Make AGENTS.md human-only without an agent-edit exception; distinguish commit, merge, push and deployment permissions.
- Retain existing conditional background admission and all-web-file acceptance rather than silently broadening permissions or narrowing checks.
- Publish an exact migration map distinguishing preserved rules, approved proportional workflow changes, historical material and unresolved external contracts.

## Capabilities

### New Capabilities
- `rulebook-policy`: semantic preservation, task routing, human ownership and explicit migration coverage.

## Impact

The reusable implementation belongs in the separate Stand dev source repository. The user explicitly authorized direct simplification of AGENTS.md after the initial source-only scope was proposed; preserve its original snapshot and apply only that file-specific authorization. Installed plugins, live prompts and host configuration remain unchanged. No additional runtime gates or product behavior changes are introduced.
