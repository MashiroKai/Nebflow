# Stand 轻量工作树与多设备测试

## Why

Stand 开发经常同时保留多个分支。Git 已在同仓 worktree 之间共享对象历史，每个检出的源码目录和每次构建生成的文件仍会占用本机磁盘。测试同时受单机资源和套件隔离条件限制。开发者希望继续在一个工作区编辑，同时借用闲置设备验证当前改动。

## What Changes

R1 把同一份不可变输入同时用于本机工作树和远端测试。本机先在经验证支持克隆的 macOS APFS 卷上复用干净基线，以写时复制创建独立 Git worktree。提交测试作业时，Stand 固定当前工作文件的内容及删除记录，为快照分配可校验的标识。快照和作业结果分别记录。

远端设备由用户启用算力共享，接收端按自己的槽位、空间和工具条件接单。先把一组自足 Playwright 测试完整卸载到一台设备，再将同一输入的用例分给两台合格设备，每台保留一个测试 worker。能否接单、执行位置、产物和终态通过同一个任务记录查询。

## Impact

首批修改面涉及托管工作树的创建入口、设备间已校验文件传输、作业暂存与回执、测试清单和合并报告。现有工作树仍通过 Git 维护，项目所属设备继续持有开发者正在编辑的文件和权威分支。临时输出、构建缓存和用户文件分别计量和回收。

R1 验收比较新增工作树的物理占盘、提交到取回完整测试报告的时间，以及开发机在此期间的资源占用。R2 再验证按读取物化的原生文件系统、更多平台和 Scala 套件。此次交付为提案，实施任务及实机验收均在后续批次执行。
