# 实施清单

## R1 · 轻量 Git 工作树

- [ ] 盘点工作树创建入口，在相同提交上分别记录普通工作树和 APFS 克隆的文件数、源码逻辑大小、卷上新增物理占用。分列首次基线、后续工作树、构建输出和每设备缓存。
- [ ] 实现干净基线、写时复制、独立 Git HEAD 和 index，以及中途失败的恢复。验证两棵树并行编辑、暂存、删除和提交互不影响，原有树可继续工作。不支持克隆时报告实际采用的后端。
- [ ] 核对项目指定的 worktree 和临时交付布局。对并发创建、使用中的快照和未交付内容验证保留、引用释放与清理预演。

## R1 · 冻结输入与远端执行

- [ ] 为提交时的工作目录生成不可变清单。覆盖已跟踪改动、删除、任务声明的新文件、执行位与符号链接；并发编辑时重采或显式失败。验证分别暂存和未暂存的改动按工作目录可见内容进入测试。
- [ ] 实现按缺失内容传输和哈希验证，明确测试输入、依赖缓存与可丢弃暂存的边界。验证路径安全、跨平台冲突、权限、空间不足和内容不匹配时的报错与回收。
- [ ] 实现设备主动加入和退出、环境匹配、接收端原子预约槽位、每次尝试独立暂存以及取消和终态回执；验证双提交竞态、设备离线和迟到结果。
- [ ] 在一台闲置设备运行自足 Playwright 套件，把用例、失败截图和状态回收到提交会话。通过一个只存在于未提交改动中的必败用例，核对远端拿到的确是本轮输入。
- [ ] 在两台符合相同环境约束的设备上分片，每台一个 worker。以单机收集清单检查用例并集、唯一性和跳过结果；缺少任何分片时整轮给出未完成状态。
- [ ] 对照同一快照，分别记录本地单机、单机卸载和双机分片的冷、热缓存端到端时间，分解排队、传输、执行和回收开销，记录发起机负载。按主规格的数值门槛判定并保存原始证据。

## R2 · 通过 R1 验收后另行立项

- [ ] 在目标平台验证真正的读时物化后端，覆盖原生进程、目录枚举、首次读取、断线、一致性、文件监听和写入隔离，用同一份输入对照 R1。
- [ ] 扩展到其他文件系统和设备；对 Scala `testOnly` 按套件验证隔离数据根、独立进程、特殊 JVM 分组、工具链一致性及重复编译成本。
