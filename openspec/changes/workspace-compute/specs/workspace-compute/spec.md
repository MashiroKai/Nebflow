## ADDED Requirements

### Requirement: [WCP-REQ-001] R1 工作区使用独立的 Git 状态和可写文件

Stand SHALL 保留项目现行的工作树路径、分支约束、交付目录和审计规则。新增的 APFS 后端使用 `git worktree add --no-checkout` 注册工作树，再使用同卷、不可变的检出种子和写时复制创建工作文件，初始化与目标提交一致的独立索引。每棵树独立持有 HEAD、索引和工作文件。种子只包含该检出配置下的项目输入。平台能力或 Git 检出语义无法满足时，管理入口使用普通 Git 工作树并报告实际后端。

#### Scenario: [WCP-SCN-001] 两棵树从同一基线独立编辑

- **WHEN** 从同一提交创建两棵 APFS 工作树，在第一棵树中原地改写、暂存、重命名、删除文件并提交
- **THEN** 两棵树起始内容、可执行位和符号链接与标准 Git 检出一致，起始状态干净；第二棵树和种子的内容、第二棵树的索引和 HEAD 保持各自初始值
- **AND** 第一棵树可从项目管理入口和需要其工作目录的节点入口找到；交付物和过程证据按项目规则落在树外

#### Scenario: [WCP-SCN-002] 存量树及后备路径继续工作

- **WHEN** 打开已有普通工作树，在不支持同卷克隆的卷上新建工作树，或在初始化过程中中断并再次创建
- **THEN** 存量树中已暂存、未暂存和未跟踪的文件可以原样使用；新树交付完整、干净的目标基线，或报告失败和该次创建所剩的资源
- **AND** 后备方式可从结果中核对；重试须辨认此前尝试的资源所有权，保留用户已有分支、文件和工作树注册

### Requirement: [WCP-REQ-002] R1 计算设备按账号、授权及容量准入

Stand SHALL 依据已有账号和已认证设备身份发现候选设备，要求设备所有者允许该设备为该项目或授权范围贡献算力。执行设备在每次认领时校验授权，按自身可提供的运行环境和容量预约任务。用户可以暂停贡献或撤销授权。

#### Scenario: [WCP-SCN-003] 用户控制同账号设备贡献

- **WHEN** 同账号有已启用、仅登录和已暂停的设备，另有其他账号设备，用户提交需要特定运行环境的任务
- **THEN** 只有已授权且环境相容的设备可以接受任务；容量已满时显示排队或约束无法满足
- **AND** 暂停或撤销后停止新的认领，显示在途任务的状态；其他账号的设备和未授权设备均无法读取本次快照

### Requirement: [WCP-REQ-003] R1 任务读取固定的项目输入

Stand SHALL 在发起端记录输入清单和内容标识，覆盖基线提交、相对于该基线的工作区内容（含删除）、任务指定的未跟踪输入、文件模式和符号链接目标。项目外内容和凭据须受输入授权边界约束。接收端可复用已有内容，缺少或损坏的输入须在执行前补全并校验。一个任务的所有分片和重试引用同一快照。

#### Scenario: [WCP-SCN-004] 未提交的修改可以复测

- **WHEN** 固定一份包含新文件、已修改文件和删除项的输入，随后作者继续编辑；远端缓存已有部分内容，另一块内容校验失败
- **THEN** 远端根据清单补齐并验证原快照，校验失败的内容经修复后才能使用；得到的工作文件反映快照时的改动
- **AND** 快照外的本地配置、凭据及指向工作区外的链接内容不随项目输入传输；接收端拒绝使物化目标越过工作区的路径

### Requirement: [WCP-REQ-004] R1 按可迁移任务选择执行设备

Stand SHALL 接受声明了输入、运行步骤、环境约束、产物与可重试性的任务。引擎可以自动选择设备，也接受显式固定的设备约束。需要同一进程、目录、端口或临时状态的步骤须保持在同一执行上下文。既有 Bash、文件工具和已绑定设备的会话沿用原路由契约。

#### Scenario: [WCP-SCN-005] 适配设备并隔离同机测试

- **WHEN** 测试包含独立分片，以及必须共同使用一个隔离实例的步骤，又有其他任务同时请求同一设备
- **THEN** 引擎为独立分片选择满足约束且有容量的设备，共享实例的步骤在同一设备和工作区完成；每次执行拥有自己的可写输出、进程、端口和数据根
- **AND** 固定设备无法满足约束时显示原因；普通交互 Bash 和现有设备工作区的读写仍按原配置执行

### Requirement: [WCP-REQ-005] R1 各次执行可区分，终态可追溯

Stand SHALL 持久记录任务、快照、执行尝试、实际设备及租约归属。重复交付可以安全确认；同一任务仅发布当前有效尝试的最终结果。失联时应报告所知状态，只允许符合重试声明的任务再派发。取消后协调端停止派发，执行端只回收本次尝试拥有的资源。

#### Scenario: [WCP-SCN-006] 断线、迟到结果和取消

- **WHEN** 执行设备认领后断线，协调端重启；可重试分片在另一设备重新执行，原设备随后回传结果；用户取消另一任务
- **THEN** 同一任务的不同尝试可查询；迟到结果不能覆盖有效结果，测试断言失败保留原始退出状态；不可自动重试的任务保留待确认状态
- **AND** 取消通过任务编号关联至所属执行；离线时显示尚待确认，执行设备恢复后可核验其进程及端口回收情况

### Requirement: [WCP-REQ-006] R1 汇总输出并保护用户数据

Stand SHALL 把退出状态、日志、执行设备、快照标识、产物清单与其校验信息关联回发起任务。协调端按计划分片清单核对结果。设备回收工作区、缓存和暂存结果时须识别活跃租约、在用引用、未确认交付和现有工作树的所有权；交付与证据继续遵循项目保留和审计规则。

#### Scenario: [WCP-SCN-007] 核验完整性并回收已释放资源

- **WHEN** 一次测试收到重复分片结果、缺少另一分片或指定产物，随后补齐并核对；设备触发回收
- **THEN** 缺失、失败、损坏的分片或指定产物各有可见状态，全组成功须有全部必需分片和产物的有效结果
- **AND** 回收只触及符合保留策略、已释放的资源；在用或待确认的产物、用户工作树、未提交改动和常驻实例仍可按原方式使用

### Requirement: [WCP-REQ-007] R1 用真实设备验证磁盘和测试耗时

Stand SHALL 按本提案 design.md 的口径及门槛分别验收同机工作树占盘与两台真实设备协作的收益。测试内容、环境要求和通过条件须可复核；设备准备、排队、传输、执行和收回结果都计入端到端耗时。

#### Scenario: [WCP-SCN-008] 同输入比较工作区和单双机执行

- **WHEN** 从同一快照分别测普通检出和 APFS 写时复制，并用相同测试清单测基准单机与双机执行，分别记录冷缓存与热缓存
- **THEN** 记录磁盘实际新增量、工作树创建耗时、测试端到端耗时、分片覆盖、退出状态及产物；报告注明平台、工具链、样本与偏差，并逐项对照 design.md
- **AND** 结果缺失、用例清单不同或平台差异改变了测试语义时，该轮不能用于宣称提速或验收通过

### Requirement: [WCP-REQ-008] R2 按需物化维持工作区语义

R2 的可选虚拟文件系统 SHALL 展示快照的完整目录视图，按需读取内容，将每个工作区的修改、创建、删除和重命名独立保存。按需读取、缓存及回收遵守相同的授权和快照边界。启用后须用既有 Git、构建器和测试入口验证；平台能力不满足时应可使用完整物化方式。R2 是否启用按 design.md 的阶段条件评估。

#### Scenario: [WCP-SCN-009] 工具访问尚未物化或已被本地修改的文件

- **WHEN** 两棵虚拟工作树引用同一快照，工具先列目录并读取一个尚未加载的文件，再对第一棵树执行原地改写、重命名、删除并运行 Git 与构建工具
- **THEN** 两棵树可见同一初始命名空间，读取返回校验通过的内容，后续访问遵守各树自己的写入与删除；另一棵树的结果与初始快照一致
- **AND** 断线读取未缓存内容返回可诊断的失败；恢复后可继续读取；切换到完整物化时保留可见的工作区修改和 Git 状态
