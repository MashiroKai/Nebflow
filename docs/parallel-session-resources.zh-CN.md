# 并行会话资源预分配规范（zh-CN）

- **目的**：zcode 四会话审计共性风险 4 的沉淀——「并行任务预分配 worktree/实例/端口」。多个 agent 会话与作者在同一台机器、同一批仓库上并行工作时，**资源面（git 检出、端口、实例、构建产物）不预分配 = 互扰**。
- **适用面**：多会话并行窗（含作者本人与会话并行）内的所有 agent 节点；单会话独占窗可放宽，但本件的铁则（§3「先验身再 kill」、§4 冲突预防）任何窗口都适用。
- **状态标注**：§2 端口表为「**约定值待作者核**」——语义列是约定建议，现状列是 2026-10-14 16:4x 实测 `lsof` 快照；实例生灭频繁，执行时以现场实测为准。
- **出处**：互扰实例台账见 §0；配套操作检查单见 `docs/production-ops-checklist.zh-CN.md`（B/C/D 节）。

## 1. worktree 约定（每会话一具）

- **每会话一 worktree**：凡会产生提交的执行位，开工即建 `.nebflow/worktrees/<批次名>`（例：`guard-norms-batch`、`site-main`）；分支同名或按 `feat/`、`bug/`、`fix/`、`test/` 前缀（AGENTS.md 第 2 条）。🔴 禁多会话共享同一工作树写代码。
- **起支起点 = 建位那一刻的 main tip**（AGENTS.md 第 11.1 条）：`git rev-parse main` 的 sha 逐批记入任务书基线栏；🔴 禁复用旧 worktree 起点、禁从别支拓扑起支。
- **共享检出（主仓根）= 作者面**：会话不把主仓根当自己的工作树；发现作者正在共享检出上并行写（assembly、切分支、提交）→ **立即迁移独立 worktree**（P3 正面先例），不以「先跑完这一步」为由继续共用。
- **worktree 用后清理**：合并/弃用后 `git worktree remove`，先核零未提交改动（9da47683 先例：逐 worktree 确认干净后才清理）。
- 批内 main 落了影响编译的修复 → 立刻重锚新 worktree（AGENTS.md 第 11.2 条），禁原位 rebase/reset。

## 3. 「先验身再 kill」铁则

1. **归属证据三件套＋父链**（与检查单 B1 同源，此处为并行场景完整版）：
   - ① 启动时刻 `ps -p <pid> -o lstart=` ↔ 该实例的启动记录/pid 文件时刻；
   - ② cwd `lsof -p <pid> | grep cwd` ↔ 该实例自己的隔离 home；
   - ③ 命令行 `ps -p <pid> -o command=` ↔ `--home/--port` 参数匹配目标实例；
   - ④ 父链 `ps -p <pid> -o ppid=` ↔ 心跳 daemon / launcher 形态符合预期。
   四项全对上才准 kill；任何一项对不上 = 停手上报。
2. **环境表宿主 PID 零信号**（AGENTS.md 第 9 条第一道防线）：kill 前核对目标 pid ≠ 环境表宿主 PID。
3. **保留段零触碰**：§2.1 保留段端口上的任何进程，禁 kill/禁 signal/禁 restart——不管「看起来多像残留」。
4. **kill 单 pid、禁批量拼、禁吞错**：审计 S3 事故机制（`kill $(cat pid.txt) 95305 2>/dev/null` 硬编码附带生产 pid）；一条 kill 一个经验身 pid，错误输出必须可见。
5. **判活二次确认**：`ps -p <pid>` rc 语义（0 存活/1 确证不存在/≥2 无法确证 ⇒ 停手）；pid_start 仅参考（§7.1 v2 修正先例）。
6. **收尾三查**：kill 后①目标端口 LISTEN 已空；②宿主 8080 监听集合与启动前快照一致；③pid 文件/临时目录清掉（9da47683 正面先例：验身→kill→端口释放→临时目录清除）。

## 4. 同仓并行写冲突预防

- **sbt 构建互斥**：同一 git 目录同时刻至多一个 sbt 进程。`clean`/`assembly` 属**重动作**（换树重编＋覆盖 target 产物）——并行窗内先问后跑：确认没有其他会话/作者正依赖当前 target 产物（跑实例、跑 verify）才执行；默认**不跑**，等占有方收口，或迁移到自己的 worktree 内构建（P1 互扰直接教训）。
- **sbt 增量编译陈旧坑**：跨分支切换/git 舞蹈后，sbt 增量状态可能不重编改动文件（P1 中「classes 停在补丁前」实测）——部署前强制 `clean` 全量重编，并用字节级核对（如 `grep -a` 类常量/字符串）确认 jar 里是预期类再上实例。
- **git main 并发推进**：合并预检（merge-tree/merge-base）必须在**临界区内取读数**（锁后重读，§7.1 P4 原则）；执行中发现 main tip 被推进 → 对新 tip 重跑预检（P4 正面先例），禁拿旧读数直接落。
- **分支切换纪律**：切换前保存进度（AGENTS.md 第 2 条）；共享检出（作者面）🔴 禁会话代切分支。
- **任务书预分配义务**：派发时把本批占用的资源面写进任务书——worktree 名、分支名、QA 端口、实例 home、构建产物路径；并行会话各认各段，冲突即停手问分发器。这是本规范的主旨：**互扰预防靠派发时分配，不靠事后互让**。
