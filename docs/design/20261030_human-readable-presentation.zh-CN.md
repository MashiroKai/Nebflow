# 人类可读呈现——输出分层与汇报范式设计稿

## 词条

- 人面子（human face）— 产出物中面向人类读者的那一层：结论、关键数字、图，行话禁入；本文核心概念之一。 ^term-human-face
- 机器面（machine face）— 产出物中面向执行者的那一层：完整细节、代码锚、验收读数，消费方是后续 agent 与校验器，不求人读。 ^term-machine-face
- 看板存档面（board/archive face）— 产出物的扫视与考古层：结构化摘要卡片、可检索存档，消费方是作者日后回看与图谱视图（[[glossary#^graph-view]]）。 ^term-board-face
- 过滤层（filter fence）— 呈现机制：agent 自由生成全文，但只有按指定围栏格式框起的内容默认呈现给用户，框外折叠为「细节」抽屉。 ^term-filter-fence
- 关键数字（key numbers）— 人面子必备件：核心 ≤4±1 个量化读数（加严已批 2026-10-30 14:43，超出进 Findings），是作者判断「要不要展开细节」的依据。 ^term-key-numbers
- 方案档案（profile）— 一组呈现参数的命名档：人面子长度、折叠默认、图密度、提醒节奏、监督颗粒度五参数（可扩）；agent 按档下笔，同一任务在不同档下呈现不同；作者核心裁定「方案不能单一」的落点（§6）。 **【作废 2026-10-31 16:13】** 方案档案体系整体退役（§6 作废批注、§11）——本词条内容仅存档。 ^term-profile

## 1. 问题与依据

作者 2026-10-30 12:52 令（要点转写，原意保留）：

1. visual-report 产出的报告可读性差——字太多不像给人看的，人类偏好图片等视觉形式汇报；
2. 回复风格术语泛滥难懂，有效信息难找；
3. 要一个**理论/原则**指导「产出文字如何适合人类阅读、关键信息如何呈现」；
4. 作者提议具体机制：**输出过滤层**——agent 自由生成，只有按指定格式框起来的内容才呈现给用户，框外默认隐藏/折叠；
5. 受众必须分层：很多文档面向执行 agent 需要细节，给人看的和给机器看的要分开。

反面素材（reports/ 抽样三份，行数/字数/结构均已核）：

| 报告 | 行数 | 约字数 | 开头 | 高频行话（行计数） | 图 |
|---|---|---|---|---|---|
| `20261029_schedule-revival-batch-report.md` | 66 | ~5,400 | 溯源元数据（作者令/分支/commit），无结论 | spec×14、会话/session×12、批×10 | 无 |
| `20261030_misc-ops-batch/REPORT.md` | 66 | ~4,300 | 同上 | 批×11、delegate×5、merge×4 | 无 |
| `20261029_thinking-config-batch-report.md` | 61 | ~5,200 | 同上 | spec×10、commit×3 | 无 |

三点诊断：**无结论先行**（结论埋在正文中段）、**行话直入人眼**（spec 读数、merge、worktree、考古、钉死 等内部语零翻译）、**无视觉层**（三份合计 0 图，证据全靠嵌套长句）。注意这不是「写短一点」能解决的——细节是执行 agent 的刚需，删不得；问题是**细节和结论混在同一呈现层**，人被迫用读机器面的方式读人面子。

## 2. 受众分层模型

### 2.1 三层定界

| 层 | 内容 | 消费方 | 呈现要求 |
|---|---|---|---|
| 机器面（[[#^term-machine-face]]） | 完整细节、代码锚（文件:行号）、验收读数、偏离申报 | 执行 agent（后续 delegate 节点、引擎、check_wiki_docs 校验器） | 完整、精确、可机检；不求排版 |
| 人面子（[[#^term-human-face]]） | 结论一句话、关键数字（[[#^term-key-numbers]]）、关键图表、下一步 | 作者 | ≤8 行、BLUF、零行话、有图 |
| 看板存档面（[[#^term-board-face]]） | 标题级摘要、状态（✓/open）、可检索归档、图谱节点 | 作者扫视＋日后考古 | 一眼一卡，点开进全文 |

核心原则：**同一份产出分面呈现，不是写两份**。机器面一个字不删，只是默认折叠；人面子不是摘要尾巴，是呈现默认值。

### 2.2 现有产出归位与缺口

| 现有产出 | 现状归位 | 缺口 |
|---|---|---|
| visual-report wiki-docs 报告（docs vault 内） | 机器面全文＋存档面（图谱自动索引） | **人面子缺位**：没有摘要层，作者必须读全文才能知道结论；零图 |
| delegate 回贴（节点最终文本） | 机器面混人面子：回贴即交付，但按机器习惯写（回贴纪律五元素=文件+证据，正是机器面规格） | 人面子未分离；无框内/框外之分 |
| Nebula 聊天回复 | 同人面子缺位：流式全文直出，术语随写随出 | 无 BLUF、无过滤、无术语护栏 |
| 批报告（reports/） | 存档面＋机器面细节 | 人面子头缺位（§1 反面素材）：无结论段、无关键数字块、无图 |

缺口收敛成一句话：**四个产出都只有机器面，人面子与看板摘要靠读者自己从机器面里捞**。过滤层就是补这个缺口的呈现机制。

## 3. 过滤层机制设计（主候选，作者提议认真做）

### 3.1 格式约定

围栏块（fenced code block）信息串约定（外层用 ~~~~ 只是为了在本稿内嵌套示例，实际写 ``` 即可）：

~~~~markdown
```human
## 结论
一句话结论。

**关键数字**：改 4 文件 · 46/46 断言绿 · 耗时 1h
![[report-chart.png]]
```
（框外：完整细节，正常生成……）
~~~~

- 围栏信息串 = `human`（人面子围栏；命名未决，见 §9）。一文档可多个框（结论框、图框），按序呈现。
- 框外内容**照常生成、不限制**——这是过滤层与「写短点」的本质区别：agent 自由度不变，变的是呈现默认值。
- 纯文本降级：无渲染支持的面（外发邮件、纯文本通道）框内框外都正常显示，围栏只是一行标记，信息无损。

### 3.2 前端渲染形态

- **框内 → 卡片化呈现**：围栏内容渲染为「结论卡」（标题行＋关键数字行＋图表区），不是灰底代码块。
- **框外 → 折叠抽屉**：默认收进一个「细节 (N 行)」`<details>` 抽屉，点开看全文。仓内 `<details>` 折叠已有两处先例（`js/diffRender.js:120`、`js/flowMapArchive.js:1083`），交互形态不是新发明。
- **关键接合点——单管线五面**：聊天渲染走 `js/utils.js` 的 `renderMarkdownWithMath()`（utils.js:284），```mermaid 围栏在该管线内被整体换为占位 div＋异步渲染（utils.js:353-365），且注释明确列出共用者：canvas md viewer、wiki docs、聊天气泡、flow 卡片、report 卡片。**过滤层围栏照此加一个后处理 pass，五个面一次全收**，这是选围栏形态的第一理由。
- 与 Pop 卡片/Canvas 的接合：框内可写 Pop 卡片引用与 `![[附件]]` 内嵌（附件定义见 [[glossary#^attachment]]），图表点开进 Canvas；框外折叠态提供「在 Canvas 中打开全文」入口。Canvas 卡片化呈现参照 [[20261028_canvas-ask-mode-design.zh-CN]]。

### 3.3 备选对比与取舍

| 备选 | 机制 | 取舍 |
|---|---|---|
| **A. 围栏过滤层（选定）** | ```human 围栏＋管线后处理 | 既有机制（mermaid 先例），零新解析语法；单点接合五面；降级无损 |

| C. 双文档产物 | report.md ＋ summary.md 两文件 | **部分采纳**：存档面不需要两文件（报告头模板=同文档人面子段即可达成，见附录 A）；且双真源漂移是仓内已有否决先例（frontmatter `terms:` 否决，见 [[20261029_123653_term-citation-batch1-spec__delegate-nebflow-dbfd1ffc.zh-CN]] 裁定 1）；聊天回复根本无「文件」可拆。仅当外发渠道（邮件/IM）只要摘要时，才派生单段人面子文本 |

## 4. 人类可读汇报范式（理论/原则层，回应作者令③）

逐家给「借什么／怎么落」。主推荐 = ②，因为它天生就是受众分层，与 §2 模型同构。

### 4.1 BLUF／倒金字塔（军情简报、新闻写作）

- **借什么**：Bottom Line Up Front——第一段就是结论＋行动请求，细节按重要性递减排列，读者随时可停。
- **怎么落**：人面子首段硬性 ≤3 行：「做了什么／结果如何／要不要你动手」。报告头模板首段、聊天回复首段同规（附录 A/B）。倒金字塔同时是框外折叠的理论背书：折叠点之后的内容按重要性递减，作者点开抽屉也先看到要紧的。

### 4.2 放射学报告 Impression + Findings 两段制（主推荐）

- **借什么**：放射科报告分两节——**Impression**（印象）：结论与建议，写给开单医生，≤5 行，可独立阅读；**Findings**（发现）：逐条证据明细，写给复核者，多长都行。两个受众、一份文档、天然分层，正是「人面子/机器面同文档分面」的成熟行业范式。
- **怎么落**：批报告与调研稿模板从「交付清单→考古→根因→读数→遗留」改为 **Impression → 关键数字 → Findings → 遗留** 四段（附录 A）：Impression＝人面子，Findings＝机器面，关键数字＝两层的铰链。delegate 回贴同构：结论段（=Impression）先行，五元素报告降格为回贴尾段的机器面清单。

### 4.3 Progressive Disclosure（渐进呈现，三层）

- **借什么**：信息分三层——摘要（永远可见）→ 展开（按需）→ 全量（深入时）。读者不被一次性信息量淹没。
- **怎么落**：这就是过滤层的交互理论：框内卡＝第 1 层，「细节」抽屉＝第 2 层，Canvas 全文/原文档＝第 3 层。三层各层有明确归宿，不是「折起来」三个字了事。

### 4.4 Tufte 一图一结论（数据墨水比）

- **借什么**：每个主张配一张图，图旁一句话注结论；图表的信息墨水占比最大化，装饰零容忍。
- **怎么落**：visual-report 报告模板增设「关键图表」区：人面子至少 1 张图（现状 0 张），图注 = 结论句而非「如图」。图进 `docs/attachments/` 并以内嵌附件语法引用（`!`＋双方括号包文件名，附件纪律见 [[glossary#^attachment]]），点开进 Canvas。提醒：一图一结论是**人面子义务**，不是全文义务——Findings 层保留表格读数（机器面），不强制配图。

### 4.5 各家关系

倒金字塔定**段落序**（结论在前），Impression/Findings 定**节结构**（两层分面），渐进呈现定**交互层**（折叠），Tufte 定**图表义务**（人面子有图）。四者不互斥，分别落进模板的四个空。这份「各管一段」的拼图即作者令③要的「理论/原则」。

## 5. 认知科学原则（补强研究章，作者令 2026-10-30 13:26）

> 结论先行：§4 的四家范式是「呈现术」，本章给「为什么」——六条认知科学原则（认知负荷／注意力残留／ADHD 友好／多媒体学习／学习加速边界／注意力伦理），每条按「一句话机制 → 我们场景的具体规则 → 出处」落笔。原则不是装饰：既有规范（≤8 行、关键数字原 3-7 个，14:43 加严为 ≤4±1）在本章拿到工作记忆理论的量化锚点，新增四条硬规范（未决项带默认建议／人面子零教学引导／聚合浮出／角标可行动判据）全部由机制直接推出。出处给到作者/概念名/年份；联网核实与书内知识逐条标注置信度。作者初心（帮人拓展认知、加速学习、减少注意力负担）在本章逐条对回。

### 5.1 原则清单（机制→规则→出处）

**P1 认知负荷理论（Cognitive Load Theory）**

- **机制**：工作记忆容量极有限——Miller 1956 的 7±2 被 Cowan 2001 修正为 4±1 组块（chunk）；呈现方式造成的「外在负荷」（extraneous load）挤占本可用于理解的心智资源——术语堆、长句嵌套、无分段都是外在负荷的直接来源。
- **规则**：
  - 人面子 ≤8 行【维持】——8 行 ≈ 4 个语义组块（结论／关键数字／图／下一步各占一），与 Cowan 4±1 对齐，既有上限站得住。
  - 关键数字 3-7 个【加严·已批 2026-10-30 14:43】——核心数收紧为 ≤4±1 个（= 一个组块上限），超出的进 Findings 表格（§9-8，加严生效）。
  - 每条行话 = 一个未解码组块，对非专业读者是双倍负荷——§7 术语纪律由此从文风偏好升级为认知规范。
  - 框外折叠 = 把外在负荷改造成「按需支付的内在负荷」：读者点开抽屉时带着明确问题，此时的负荷是自愿且有偿的。
- **出处**：Sweller 1988；Sweller, van Merriënboer & Paas 2019；Miller 1956；Cowan 2001。置信度：高（Sweller 体系与 4±1 修正经联网核到方向性材料，题录细节为书内知识）。

**P2 注意力残留与开环外置**

- **机制**：任务未闭合时，部分注意残留在旧任务上、拖累后续任务表现（attention residue，Leroy 2009）；未完成事项被大脑优先保持、挥之不去（Zeigarnik effect，Zeigarnik 1927）；GTD 的解法是把「开环」（open loop）外置到可信的外部系统，大脑才肯放下（Allen 2001）。
- **规则**：
  - 待办收件箱 = 开环外置器：承诺一经出现即刻 `Schedule(kind="todo")` 入账（引擎持久，会话压缩/重启不丢），「别忘了 X」从工作记忆搬进系统。
  - 可信性是硬约束：入账必须伴随归宿——每日 09:00 汇总浮出 → done 销账，均为既有语义（`ScheduledTaskModel.scala:31-39`）。只收不闭环的外置是失败的：Zeigarnik 不消退，还新增一个「系统会不会丢」的新开环。
  - 人面子必答「要不要你动手」（BLUF 第三问）= 给作者一个闭合判定；未决项显式列出且带默认建议 = 替作者闭合——每个没有下文的未决项都是一个 residue 源。
  - 与 #1128 在飞批（待办收件箱）直接相关：该批若只做收纳不做「闭合回路呈现」（浮出 → 行动 → 销账），本机制只发挥一半。
- **出处**：Leroy 2009（OBHDP，联网核到概念锚）；Zeigarnik 1927（原文题录联网核到）；Allen 2001。置信度：高。

**P3 ADHD 友好设计（单任务／切换成本／选择负荷）**

- **机制**：ADHD 的核心损害在执行功能与工作记忆（Barkley）；任务切换有可测量的成本（task-switching cost，Rubinstein, Meyer & Evans 2001）；选项数与决策时间线性增长（Hick's law，Hick 1952）；选项过多反而抑制行动（Iyengar & Lepper 2000 果酱实验；Schwartz 2004 选择悖论）。注意：ADHD 友好不只服务诊断者——切换成本与选择负荷对所有人是连续谱，ADHD 友好档 = 把默认值放在谱的友好端（参数化落点见 §6.2）。
- **规则**：
  - 单任务呈现【维持】：一条人面子只给一个动作请求，多动作拆成「主行动 + 其余进抽屉」。
  - 减少上下文切换【新增】：批内不中途打扰，批完成聚合一次浮出；报告一次给全（Impression＋Findings 同文档），不让作者在多处拼装信息。
  - 外化记忆【维持】：收件箱＋看板＋报告存档 = 工作记忆外置（与 P2 同根）。
  - 视觉锚点【维持】：人面子至少 1 图（§4.4）——图是低工作记忆成本的注意锚。
  - 选择克制【新增】：未决项不开放罗列——每条带默认建议，作者只做确认/否决，把 Hick 负荷从「生成选项」降到「二选一」。
- **出处**：Barkley 2012（书内知识，置信度中高）；Rubinstein et al. 2001、Hick 1952、Iyengar & Lepper 2000、Schwartz 2004（书内经典，置信度高）。

**P4 多媒体学习（Mayer 原则集）**

- **机制**：人经视觉/言语双通道加工且各通道容量有限；外在加工（extraneous processing）挤占必要加工。Mayer 十二条减荷原则（Mayer & Fiorella 2014）中与报告图务/排版直接相关的五条，逐条映射。
- **规则**：
  - 连贯性 coherence【维持】：人面子零装饰——无客套、无表情、无「如图所示」类冗余句。
  - 信号 signaling【维持】：关键数字加粗、未决项编号、Findings 小标题——读者注意被引导到结构关键点。
  - 空间邻近 spatial contiguity【新增·排版细则】：图注紧贴图下方；数字与含义同句（「改 4 文件」而非「文件数：4，见下文」）。
  - 分段 segmenting【维持】：Findings 按子任务分段加小标题，长表格进折叠，不一次倾倒。
  - 冗余 redundancy【新增·排版细则】：图与文不重复承载同一信息——图给趋势、表给精确值，各管一段（与 §4.5 互证）。
- **出处**：Mayer 2001/2009/2014；Mayer & Fiorella 2014（章节题录联网核到）。置信度：高。

**P5 学习加速及其适用边界（敢划线）**

- **机制**：自己产出比复读记得牢（生成效应，generation effect，Slamecka & Graf 1978）；边做边解释「为什么」增益最大（自我解释，self-explanation，Chi et al. 1989）；分散练习优于集中（Ebbinghaus 1885；Cepeda et al. 2006 元分析）；适度困难利于长期保持（desirable difficulties，Bjork & Bjork 2011）——但脚手架对专家反转为负荷（expertise reversal effect，Kalyuga, Ayres, Chandler & Sweller 2003）。
- **适用**（落进规范）：
  - 生成效应 → 结论段必须 agent 自己生成——模板给结构不给句式；抄模板句式 = 复读，记忆与校验价值双失【附录 A/B 的「<…>」占位即此意，理由补强】。
  - 自我解释 → Findings 保留「根因/为什么」段：不是罗列读数，是解释因果链——作者读报告本身就是学习面（作者初心「加速学习」的直接落点）。
- **不适用**（划线，防生搬硬套）：
  - 间隔重复/测验效应：产出物是任务汇报不是课程材料，不套抽认卡式复习机制；作者的间隔复习由周报/考古自然承担（§6.5），不新造机制。
  - desirable difficulties 只进「作者主动学习面」（考古/复盘/设计稿深读），**绝不进人面子**——人面子是最小摩擦面，加困难 = 加外在负荷。
  - 专家反转：Kai 是专业用户，教学气泡/分步引导/新手向导对他是纯外在负荷——人面子**零教学引导层**【新增硬规范；唯一例外 = §6.2 备考冲刺档，该档学习者身份压过专家身份】。
- **出处**：Slamecka & Graf 1978；Chi et al. 1989/1994；Ebbinghaus 1885；Cepeda et al. 2006；Bjork & Bjork 2011；Kalyuga et al. 2003（题录联网核到）。置信度：高。

**P6 注意力伦理（反注意力劫持）**

- **机制**：可变比率强化时间表产生最强、最耐消退的查收行为（variable-ratio schedule，Ferster & Skinner 1957）；通知与角标把「未读数」做成迷你 Zeigarnik 开环，驱动强迫性查收（P2 机制的恶意用法）；伦理立场：设计应服务用户目标而非占用时长（Time Well Spent 运动，Harris 2016 起；Fogg 行为模型，Fogg 2009——能力/动机/触发三要素可被善意或恶意地拨动）。
- **规则**：
  - 角标克制【新增】：徽章只报「需要作者行动」的量（待批准/待销账/待拍板），不报「有更新」——判据 = 闭合相关性，不是新鲜度。
  - 浮出节奏【新增】：批级聚合一次浮出，不逐节点打扰（一次弹窗 = 一次上下文切换，P3/P6 合力）。提醒只走 Schedule 既有面（条件触发、空转降频，`ScheduledTaskModel.scala:41-71`），不新造催促通道。
  - 文案反悬念【新增】：通知/浮出文案给结论（「X 批完成，46/46 绿，无需动手」），不给悬念（「有 3 条新消息」）。
  - 立场红线【新增】：本系统的优化目标是「作者完成任务的速度」，不是打开次数；任何以留存/回访为目标的呈现设计一票否决。
- **出处**：Ferster & Skinner 1957（书内经典，置信度高）；Harris/Time Well Spent（运动性引用，置信度中）；Fogg 2009（书内，置信度高）。联网仅核到方向性材料，未核到原始题录。

### 6.1 为什么必须多档（裁定依据）

三条依据，全部出自 §5：

1. **原则相互有张力，取舍靠人**：图密度——P3 视觉锚点要高图，P1 负荷与 §4.4 数据墨水比要低图；监督颗粒度——P2 闭环要细，P6 不打扰要粗。张力没有全局最优解，只有按人、按状态的最适配解。
2. **专家反转是状态量**：Kalyuga 效应不只发生在新老手之间，也发生在同一人的不同任务间——Kai 写代码时是专家，备考时是学习者。备考冲刺档是唯一允许教学引导层的档（P5 红线的正向利用）。
3. **认知状态是时变量**：忙/闲、冲刺/常态，同一作者也要换档；显式换档靠自觉，所以要有校准路兜底（§6.3）。

### 6.3 匹配机制三路取舍

### 6.5 健身/学习计划跟踪回路（目标→拆解→提醒→打卡→周报）

统一五段回路，健身/学习/学习材料准备三类计划共用：

1. **目标入账**：作者一句话（「帮我跟踪健身计划：每周三练，增肌」）→ agent 拆出计划文档（目标＋指标＋周期）；计划每条可执行项入账 `Schedule(kind="todo")`，name = 稳定键（如 `fitness-checkin`）。
2. **拆解**：计划 → 原子可打卡步（「今天：深蹲 5×5」一条 todo）。拆解粒度 = 档「监督颗粒度」参数：ADHD 档细到单步，深度工作档周级。学习材料准备 = 材料清单即 todo 集（每份材料一条，每日浮出勾销，完成率即进度）。
3. **提醒**：走 Schedule 既有浮出面（每日 09:00 汇总注入；条件触发/空转降频防打扰），节奏 = 档参数；文案守人面子规范（BLUF＋可行动＋零悬念，P6）。
4. **打卡**：作者回「done/练完了」→ done 销账（既有语义）。缺卡处理：连续缺卡**不指责**（注意力伦理），只带调整建议（降频或重拆）呈作者确认——不擅自改计划。
5. **周报**（落位已批 2026-10-30 14:43，§9-12）：**引擎生成**——每周一次批级聚合报告，经**待办收件箱浮出**，**可归档 reports/**（纯过程文件；趋势图存 docs/attachments/ 供 vault 索引）。模板即 §3/§4 实例化：Impression =「本周打卡 N/M，趋势↑/→」；关键数字 = 打卡率·连续天数·负荷；Findings = 逐日记录；图 = 打卡热力图（一图一结论，P4）。周报同时是 P5 学习面——作者读周报 = 复盘（自我解释的负载面），作者初心「加速学习」的第二落点。备考冲刺档加周测＋错题回炉循环（复用周报面，不新造机制）。

## 11. output 标签规格（作者令 2026-10-31 16:13「output 块语法批」；16:16 修订：标签式）

### 11.1 语法与语义

- **形态**：成对标签 `<output>…</output>`，纯 ASCII 定界，内容可多行 markdown；一文本可多块，按序拼接呈现。匹配为源文本级平衡判定（≥1 对且全部按序配对，禁嵌套）——与 ```human 的 `_humanFencesBalanced` 流式闸同构。
- **语义**：标签内 = 写给人看的全部；标签外 = 机器面（推理、工具叙述、验收细节），照常生成不限制——变的是呈现默认值，不是 agent 自由度（§3.1 过滤层本质不变）。
- **降级**：无渲染支持的面（纯文本/外发）标签只是一行标记，信息无损；**未包裹的历史内容照常全显，不吞历史消息**。

### 11.2 双面落地（同管线、两处语义）

| 面 | 行为 | 落点 |

| 管线透明面（canvas md viewer / wiki docs / flow 卡 / report 卡） | 标签不现形，块内照 markdown 渲染，框外内容照常显示（非聊天面不做摘除） | `utils.js renderMarkdownWithMath` 源级提取 pass（占位符先行 → 恢复渲染）；散标签（流式中间态/手误）转义为字面文本，防 marked 裸 HTML 块吞文 |
| 聊天摘除面（聊天气泡） | 正常态**只渲染块内内容**（框外正文摘除；思考/工具过程行本就折叠）；点 turn-header badge 展开 ⇒ 过程行揭开＋气泡切**原文全量**（escapeHtml 纯文本，`<output>` 语法原样现形）；再点收回 | `js/outputTag.js`（applyOutputFace / setOutputExpanded）＋ `chat.js finishAi` ＋ `persistence.js` 历史重建两腿 ＋ `turnGroup.js`（toggle 换面；零过程行的 output 轮也立 header——badge 是框外原文唯一展开入口） |
