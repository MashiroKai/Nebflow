# 人类可读呈现——输出分层与汇报范式设计稿

> 结论先行：本稿给三层受众模型（机器面／人面子／看板存档面）定界，把作者提议的**过滤层**（围栏块过滤：框内呈现、框外折叠）定为呈现机制主候选（接合点 = 仓内 ```mermaid 围栏的既有渲染先例，单管线五面一次收），把**放射学 Impression+Findings 两段制**定为汇报范式主候选（天然就是受众分层）。分期：一期纯约定零代码（模板＋prompt 纪律，本稿附录直接可用），二期才动产品（前端过滤层渲染＋visual-report skill 约定修订）。只设计不实施，呈作者拍板。

## 词条

- 人面子（human face）— 产出物中面向人类读者的那一层：结论、关键数字、图，行话禁入；本文核心概念之一。 ^term-human-face
- 机器面（machine face）— 产出物中面向执行者的那一层：完整细节、代码锚、验收读数，消费方是后续 agent 与校验器，不求人读。 ^term-machine-face
- 看板存档面（board/archive face）— 产出物的扫视与考古层：结构化摘要卡片、可检索存档，消费方是作者日后回看与图谱视图（[[glossary#^graph-view]]）。 ^term-board-face
- 过滤层（filter fence）— 呈现机制：agent 自由生成全文，但只有按指定围栏格式框起的内容默认呈现给用户，框外折叠为「细节」抽屉。 ^term-filter-fence
- 关键数字（key numbers）— 人面子必备件：3-7 个量化读数（改了几个文件、几条断言绿、耗时、规模），是作者判断「要不要展开细节」的依据。 ^term-key-numbers

## 1. 问题与依据

作者 2026-10-30 12:52 令（要点转写，原意保留）：

1. visual-report 产出的报告可读性差——字太多不像给人看的，人类偏好图片等视觉形式汇报；
2. 回复风格术语泛滥难懂，有效信息难找；
3. 要一个**理论/原则**指导「产出文字如何适合人类阅读、关键信息如何呈现」；
4. 作者提议具体机制：**输出过滤层**——agent 自由生成，只有按指定格式框起来的内容才呈现给用户，框外默认隐藏/折叠；
5. 受众必须分层：很多文档面向执行 agent 需要细节，给人看的和给机器看的要分开。

反面素材（reports/ 抽样三份，行数/字数/结构均已核）：

| 报告 | 行数 | 约字数 | 开头 | 高频行话（行计数） | 图 |
|---|---|---|---|---|---|
| `20261029_schedule-revival-batch-report.md` | 66 | ~5,400 | 溯源元数据（作者令/分支/commit），无结论 | spec×14、会话/session×12、批×10 | 无 |
| `20261030_misc-ops-batch/REPORT.md` | 66 | ~4,300 | 同上 | 批×11、delegate×5、merge×4 | 无 |
| `20261029_thinking-config-batch-report.md` | 61 | ~5,200 | 同上 | spec×10、commit×3 | 无 |

三点诊断：**无结论先行**（结论埋在正文中段）、**行话直入人眼**（spec 读数、merge、worktree、考古、钉死 等内部语零翻译）、**无视觉层**（三份合计 0 图，证据全靠嵌套长句）。注意这不是「写短一点」能解决的——细节是执行 agent 的刚需，删不得；问题是**细节和结论混在同一呈现层**，人被迫用读机器面的方式读人面子。

## 2. 受众分层模型

### 2.1 三层定界

| 层 | 内容 | 消费方 | 呈现要求 |
|---|---|---|---|
| 机器面（[[#^term-machine-face]]） | 完整细节、代码锚（文件:行号）、验收读数、偏离申报 | 执行 agent（后续 delegate 节点、引擎、check_wiki_docs 校验器） | 完整、精确、可机检；不求排版 |
| 人面子（[[#^term-human-face]]） | 结论一句话、关键数字（[[#^term-key-numbers]]）、关键图表、下一步 | 作者 | ≤8 行、BLUF、零行话、有图 |
| 看板存档面（[[#^term-board-face]]） | 标题级摘要、状态（✓/open）、可检索归档、图谱节点 | 作者扫视＋日后考古 | 一眼一卡，点开进全文 |

核心原则：**同一份产出分面呈现，不是写两份**。机器面一个字不删，只是默认折叠；人面子不是摘要尾巴，是呈现默认值。

### 2.2 现有产出归位与缺口

| 现有产出 | 现状归位 | 缺口 |
|---|---|---|
| visual-report wiki-docs 报告（docs vault 内） | 机器面全文＋存档面（图谱自动索引） | **人面子缺位**：没有摘要层，作者必须读全文才能知道结论；零图 |
| delegate 回贴（节点最终文本） | 机器面混人面子：回贴即交付，但按机器习惯写（回贴纪律五元素=文件+证据，正是机器面规格） | 人面子未分离；无框内/框外之分 |
| Nebula 聊天回复 | 同人面子缺位：流式全文直出，术语随写随出 | 无 BLUF、无过滤、无术语护栏 |
| 批报告（reports/） | 存档面＋机器面细节 | 人面子头缺位（§1 反面素材）：无结论段、无关键数字块、无图 |

缺口收敛成一句话：**四个产出都只有机器面，人面子与看板摘要靠读者自己从机器面里捞**。过滤层就是补这个缺口的呈现机制。

## 3. 过滤层机制设计（主候选，作者提议认真做）

### 3.1 格式约定

围栏块（fenced code block）信息串约定（外层用 ~~~~ 只是为了在本稿内嵌套示例，实际写 ``` 即可）：

~~~~markdown
```human
## 结论
一句话结论。

**关键数字**：改 4 文件 · 46/46 断言绿 · 耗时 1h
![[report-chart.png]]
```
（框外：完整细节，正常生成……）
~~~~

- 围栏信息串 = `human`（人面子围栏；命名未决，见 §7）。一文档可多个框（结论框、图框），按序呈现。
- 框外内容**照常生成、不限制**——这是过滤层与「写短点」的本质区别：agent 自由度不变，变的是呈现默认值。
- 纯文本降级：无渲染支持的面（外发邮件、纯文本通道）框内框外都正常显示，围栏只是一行标记，信息无损。

### 3.2 前端渲染形态

- **框内 → 卡片化呈现**：围栏内容渲染为「结论卡」（标题行＋关键数字行＋图表区），不是灰底代码块。
- **框外 → 折叠抽屉**：默认收进一个「细节 (N 行)」`<details>` 抽屉，点开看全文。仓内 `<details>` 折叠已有两处先例（`js/diffRender.js:120`、`js/flowMapArchive.js:1083`），交互形态不是新发明。
- **关键接合点——单管线五面**：聊天渲染走 `js/utils.js` 的 `renderMarkdownWithMath()`（utils.js:284），```mermaid 围栏在该管线内被整体换为占位 div＋异步渲染（utils.js:353-365），且注释明确列出共用者：canvas md viewer、wiki docs、聊天气泡、flow 卡片、report 卡片。**过滤层围栏照此加一个后处理 pass，五个面一次全收**，这是选围栏形态的第一理由。
- 与 Pop 卡片/Canvas 的接合：框内可写 Pop 卡片引用与 `![[附件]]` 内嵌（附件定义见 [[glossary#^attachment]]），图表点开进 Canvas；框外折叠态提供「在 Canvas 中打开全文」入口。Canvas 卡片化呈现参照 [[20261028_canvas-ask-mode-design.zh-CN]]。

### 3.3 备选对比与取舍

| 备选 | 机制 | 取舍 |
|---|---|---|
| **A. 围栏过滤层（选定）** | ```human 围栏＋管线后处理 | 既有机制（mermaid 先例），零新解析语法；单点接合五面；降级无损 |
| B. metadata 标签段 | 文档头 YAML 式摘要块（如 `summary:` 段） | **弃**：marked 不渲染 front-matter（文档头元数据块，见 [[glossary#^front-matter]]）；摘要与正文两处维护必漂移；聊天回复无「文档头」可挂 |
| C. 双文档产物 | report.md ＋ summary.md 两文件 | **部分采纳**：存档面不需要两文件（报告头模板=同文档人面子段即可达成，见附录 A）；且双真源漂移是仓内已有否决先例（frontmatter `terms:` 否决，见 [[20261029_123653_term-citation-batch1-spec__delegate-nebflow-dbfd1ffc.zh-CN]] 裁定 1）；聊天回复根本无「文件」可拆。仅当外发渠道（邮件/IM）只要摘要时，才派生单段人面子文本 |
| D. 全文折叠不分框（现状改良） | 只把长回复默认收起，无框内概念 | **弃**：无框则 agent 无落笔锚点，「什么是给人看的」仍靠模型自觉，纪律落空 |

选定理由一句话：**围栏是仓内已被 mermaid 验证过的机制，过滤层把它从「图」推广到「人面子」，接合面只有一个（utils.js 渲染管线），其余全是约定。**

## 4. 人类可读汇报范式（理论/原则层，回应作者令③）

逐家给「借什么／怎么落」。主推荐 = ②，因为它天生就是受众分层，与 §2 模型同构。

### 4.1 BLUF／倒金字塔（军情简报、新闻写作）

- **借什么**：Bottom Line Up Front——第一段就是结论＋行动请求，细节按重要性递减排列，读者随时可停。
- **怎么落**：人面子首段硬性 ≤3 行：「做了什么／结果如何／要不要你动手」。报告头模板首段、聊天回复首段同规（附录 A/B）。倒金字塔同时是框外折叠的理论背书：折叠点之后的内容按重要性递减，作者点开抽屉也先看到要紧的。

### 4.2 放射学报告 Impression + Findings 两段制（主推荐）

- **借什么**：放射科报告分两节——**Impression**（印象）：结论与建议，写给开单医生，≤5 行，可独立阅读；**Findings**（发现）：逐条证据明细，写给复核者，多长都行。两个受众、一份文档、天然分层，正是「人面子/机器面同文档分面」的成熟行业范式。
- **怎么落**：批报告与调研稿模板从「交付清单→考古→根因→读数→遗留」改为 **Impression → 关键数字 → Findings → 遗留** 四段（附录 A）：Impression＝人面子，Findings＝机器面，关键数字＝两层的铰链。delegate 回贴同构：结论段（=Impression）先行，五元素报告降格为回贴尾段的机器面清单。

### 4.3 Progressive Disclosure（渐进呈现，三层）

- **借什么**：信息分三层——摘要（永远可见）→ 展开（按需）→ 全量（深入时）。读者不被一次性信息量淹没。
- **怎么落**：这就是过滤层的交互理论：框内卡＝第 1 层，「细节」抽屉＝第 2 层，Canvas 全文/原文档＝第 3 层。三层各层有明确归宿，不是「折起来」三个字了事。

### 4.4 Tufte 一图一结论（数据墨水比）

- **借什么**：每个主张配一张图，图旁一句话注结论；图表的信息墨水占比最大化，装饰零容忍。
- **怎么落**：visual-report 报告模板增设「关键图表」区：人面子至少 1 张图（现状 0 张），图注 = 结论句而非「如图」。图进 `docs/attachments/` 并以内嵌附件语法引用（`!`＋双方括号包文件名，附件纪律见 [[glossary#^attachment]]），点开进 Canvas。提醒：一图一结论是**人面子义务**，不是全文义务——Findings 层保留表格读数（机器面），不强制配图。

### 4.5 各家关系

倒金字塔定**段落序**（结论在前），Impression/Findings 定**节结构**（两层分面），渐进呈现定**交互层**（折叠），Tufte 定**图表义务**（人面子有图）。四者不互斥，分别落进模板的四个空。这份「各管一段」的拼图即作者令③要的「理论/原则」。

## 5. 术语纪律

问题复述：人面子文本禁入 agent 内部行话；不可避免术语给人话注脚或 hover 释义。

### 5.1 人面子禁入清单（最小集）

| 行话 | 人面子写法 |
|---|---|
| spec 读数 N/N 绿 | 「全部测试通过」＋关键数字（[[#^term-key-numbers]]）一行 |
| merge/合并分支/merge queue | 「已并入主线（排队中）」 |
| worktree | 「工作副本」或干脆不写 |
| chain/节点/delegate 会话 | 「子任务」 |
| commit hash | 框外机器面给，人面子只给链接或「见细节」 |
| 考古/钉死/红线/回贴/落账 | 禁入；人面子用「历史记录确认／已固定／上报」等人话 |

### 5.2 不可避免术语的兜底

- **一期（零代码）**：句内括号一句人话注脚，即 wiki-docs 概念首现纪律（[[glossary#^concept-first-use]]）在人脸面的严格执行——「细节抽屉（点开看完整过程）」。
- **二期**：接词条注册表——人面子术语写词条短形引用（双方括号包词条名，形态见 [[20261029_123653_term-citation-batch1-spec__delegate-nebflow-dbfd1ffc.zh-CN]] §2 裁定 3），hover 出释义气泡；机制底座已建成（`GET /api/wiki/term`＋`nodeJson.terms[]`，同前），前端 hover 是第二批遗留面，本稿不新造机制。

~~~~markdown

```human
~~~~
