## 1. 概述与价值（为什么不是 fork）

Canvas 画布上的每个文件卡获得一个小控件，点击展开一个迷你对话窗，可**针对该文件内容**提问。价值主张（作者原文转写）：把当前窗口的上下文，用**记忆检索、文档图谱**（[[wiki-graph-redesign-design.zh-CN]]）等组装出一个与该文件有关的**专属上下文**。

**作者明确否定 fork 方案**（原文划掉「fork」）：fork = 复制一份文件开独立会话。否定理由：① fork 产生文件双源，问答针对副本，对原件的追问（「这句后来改了吗」）无解；② fork 会话脱离图谱与记忆的归属链——文档图谱的引用边（[[glossary#^citation-edge]]）指向原件，fork 副本成为孤儿节点；③ fork 需要用户手动搬运上下文，而 ask mode 的组装是自动的、随记忆/文档更新而更新的。

三支柱（后续章节逐条展开）：

1. **专属上下文，与主会话分割**：ask 会话的上下文 = 文件全文 + 记忆检索命中 + 文档图谱邻接，**不含**主会话对话历史；§3。
2. **活的上下文**：记忆/文档更新后，**10 分钟冷却**期满自动重新组装；§3.3。
3. **受限的透明分身**：只显示消息气泡（无流程/工具过程），无编辑/编排工具，身份同源、只有发消息一条通道；§5、§6。

## 3. 上下文组装机制

### 3.1 检索源（三路）

1. **文件全文**：当前卡对应文件（版本化快照 + 修改时间）；
2. **记忆检索**：主会话对话历史的建库检索（复用 `tools/stand-recall`：SQLite FTS5 + CJK bigram 影子列 + BM25 `k1=1.2/b=0.75` + 近因加权 τ=30——按该 CLI 现行口径，只收主 agent 会话，排除工具结果/thinking/系统注入）；以文件主题词、文件名、图谱邻接文档名为查询；
3. **文档图谱邻接**：`GET /api/wiki/graph`（WikiIndex 抽取的引用边（[[glossary#^citation-edge]]））取该文件的 1-2 跳邻接文档标题与引用锚段（段落锚（[[glossary#^paragraph-anchor]]）形态），命中的段全文入上下文。

### 3.2 组装管线

`文件全文（截断上限 = 单路预算）→ 图谱邻接段（1-2 跳，去重）→ 记忆检索 top-N 命中（含 ±1 邻句）→ 系统提示（身份章，§6）`，四段拼接为一次性的系统上下文块。每路带来源标签（`文件/图谱/记忆`），应答时要求引用出处（样张②的 cite 徽标即此契约的可视化）。

### 3.3 更新触发与 10 分钟冷却

- 触发源：记忆库增量索引完成（`stand-recall --update`）/ 文件版本变化（mtime+hash）/ 图谱边变化（WikiIndex 重建）；
- 任一触发置「待重组」标记；**冷却 10 分钟**：窗头状态行的倒计时即重组调度可视化（样张窗头 `冷却 mm:ss`）；冷却期满后的下一次交互（开窗/发问）前重组，不主动打断；连续触发合并（防抖语义）；
- 重组只重建上下文块，**对话历史不动**（§4）。

### 3.4 分割边界（与主会话的隔离）

- ask 会话上下文**不含**主会话最近对话历史（主会话历史只能经 §3.1 的检索面间接进入，且以命中片段形态出现）；
- ask 会话自己的对话历史也不回灌主会话上下文（反向隔离）；主会话只能经 §7 的消息通道看到 ask 的转交请求；
- 分割的目的（作者令）：主会话上下文不被文件问答流量污染，文件问答也不被主会话长历史稀释。

## 4. 对话历史与压缩

- ask 会话历史**一直保留**（按 `文件路径 + 会话` 键持久化，随会话面落盘，跨重启复现——收起/关闭不销毁）；
- 压缩阈值**与主会话保持一致**：复用同一条压缩链（引擎 `nebflow.core.compact` 的 `CompactService`，门限取 `CompactThreshold.threshold`——模型有效上下文窗 `effectiveContextWindow` 的比率门限，见 `src/main/scala/nebflow/llm/registry.scala:152`；会话级比率经 `SessionStore.updateSessionCompactThreshold`，`AgentFinishTurn.scala:284` 消费），不另设第二套阈值；
- 超限压缩为摘要：走主会话同款「context compaction required」内联压缩（旧历史压缩摘要 + 文件快照保留），压缩后窗头状态行提示「历史已压缩 · 摘要 n 条」，摘要可展开（透明纪律的边界同 §9-2）。

## 5. 工具面与权限边界

白名单**封闭枚举**，白名单外一律不下发（含 bash/edit/write 等一切编辑与编排工具，作者令点名禁止）：

| 工具 | 形态 | 说明 |
|---|---|---|
| `message_record_search` | 消息检索 CLI 封装 | 包 `tools/stand-recall`（关键词/时间窗/角色过滤/--json），只读 |
| `send_message_to_main_chat` | 单向信使 | 见 §7；ask 会话唯一的对外动作 |

无文件写、无 shell、无任务调度、无 agent 编排；不注册任何 MCP 面。实现上 = 现有会话工具注册面的一个白名单 profile（复用插件工具授权机制的单点裁剪），不新增权限模型。

## 6. 身份与提示词设计

**身份（作者令）**：它自我认同就是主会话的 Agent（同源），不能调度任务给主会话，只有发消息一条通道。用户感知层：窗头标「问这份文件 · 主会话的分身」，不另起人设。

提示词草案全文（实施批按此评审后入库）：

```text
你是 Stand 主会话 Agent 的文件问答分身（ask mode）。你与主会话同源同身份，但：

【使命】只服务当前文件《{file_name}》的问答。用户看到的每一句话，你都要对得起
「这份文件」四个字：答案优先出自文件本身；出自记忆检索或文档图谱邻接的，必须
带来源标注（文件 §节名 / 主会话 日期 / 图谱·文档名）。

【上下文】你的上下文由三路组装（文件全文、文档图谱邻接段、主会话记忆检索命中），
不含主会话的最近对话历史；上下文每 10 分钟随记忆与文档更新重组——被问到「刚才」
类问题时，以检索结果为准，不臆造连续性。

【边界】
1. 你没有编辑、执行、编排类工具；绝不能承诺「我去改/我去跑/我去派任务」。
2. 对主会话只有一条通道：send_message_to_main_chat（转交请求）。仅当用户明确要
   「让主会话处理/跟进/执行」时使用；转交后告知用户「已发送，它可回问」，然后留在
   本窗继续服务。
3. 主会话的回问会以用户消息形态出现（前缀「主会话回问：」），照常作答即可。

【透明】只以消息气泡说话：不描述工具调用过程、不展示检索流水；检索引用以来源
标注内联在答案里。答不出时直说「这份文件与检索范围内没有依据」，并给出最接近
的出处。

【口吻】与主会话一致：简体中文、直接、给结论再给依据；长答案先一句话结论。
```

## 7. 与主会话的通信协议

**消息形状**（`send_message_to_main_chat` 载荷，实施批落为引擎消息类型）：

```json
{
  "type": "ask_handoff",
  "from": { "kind": "ask_session", "file": "docs/…/记忆检索调优笔记.md", "session": "ask:<file-hash>" },
  "question": "语料翻倍后 τ=30 要不要重估？",
  "context_refs": [
    { "source": "file", "loc": "§近因加权" },
    { "source": "recall", "session": "main", "ts": "2026-10-22 21:3x", "excerpt": "…" }
  ],
  "asked_at": "2026-10-28T17:20:00+08:00"
}
```

- 主会话侧呈现：injected 气泡（v1 样张②左栏留档演示过全效果；v2 样张覆盖层内为紫色回执气泡「↗ 已发送到主会话」），带 `来自文件问答 · <文件名>` 来源行；**主会话可回问**「需要我帮你做什么？」（作者令原文）——回问消息走同一条通道反向投递，ask 层以「主会话回问：」前缀的用户消息呈现（提示词 §6 已约定；**v2.1 起按此契约落 user 族气泡**——ask 层的紫色回执气泡随显示面减法退场，转交可见性由主会话侧 injected 气泡独自承担）；
- 回问不自动带 ask 会话历史；主会话需要上下文时用 `message_record_search` 同款检索面（ask 历史入同一检索库的 ask 分区）；
- 频控：单向转交每文件每分钟 ≤1 条（防刷屏），超出时窗内提示「稍后再转」。

## 8. 验收标准（spec 钉什么）

1. **入口**：右下角最靠右入口钮常驻可点（不入顶行）；点击弹输入框、发问后气泡列从按钮位置长出；收起后入口 pulse 提示；入口钮再点/Esc/点击画布空白三通路全通；每文件 session 状态保留、再开复现；**可见性闸（作者缺陷报 2026-10-29）**：入口只在文件型标签页（有真实文件 backing）挂载显示——文件态 tab 入口在场，插件面板/工具面板等非文件型 surface 零残留、切卡离开文件 tab 即隐即收（spec T11 断言）；
2. **UI 纪律**：覆盖层与顶行排他 z 序（`--z-ask-dock` < 顶行）；玻璃值与 token 页 A 表、品牌色/几何/材质与 E 表逐字一致（对照样张 v2）；暗档为基准；
3. **移动手势（#988 兼容）**：ask 层打开时横滑切卡/下滑收起/pan-y 纵滚/卡头 X 四语义全部照旧（surface 归属制断言：气泡列表面横滑零切卡）；入口钮 44×44（命中盒=视觉圆）；
4. **组装**：开窗前上下文三路齐备（含来源标签）；触发源（记忆更新/文件变化/图谱变化）置待重组；10 分钟冷却后下次交互前重组；冷却期内连续触发合并；
5. **压缩**：ask 会话超限走 `CompactService` 同链路（阈值与会话比率同源），摘要生成且历史保留可溯；
6. **工具面**：白名单外工具调用被拒（spec 断言拒绝响应）；`message_record_search` 返回与 CLI 直查一致（同一库）；`send_message_to_main_chat` 消息形状符合 §7 契约；
7. **通信**：主会话收到 injected 呈现 + 来源行；回问可达 ask 窗且带前缀；频控生效；
8. **回归**：桌面/移动 canvas 既有 spec（卡叠、#988 交互）全绿，零回归；
