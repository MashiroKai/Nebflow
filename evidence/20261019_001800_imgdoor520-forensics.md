# #520 图片点不开重现取证 — 根因定位报告

时间：2026-10-18 22:40 – 10-19 00:2x · 执行：取证 delegate（#520）· 纪律：引擎零重启、runtime 只读（临时副本除外）、修复走独立分支

## 结论（一句话）

**不是 429、不是浏览器陈旧页、不是 token 键派生，也不是 Safari。** 作者的控制台经冷启动门户回投落在 relay 源（neblink.nebflow.space），该形态下浏览器的有效凭据是 relay 侧 **15 分钟短期会话**（link-server `neblink_session`，`ACCESS_TOKEN_TTL_SECS=900`），而控制台前端**从不调用** `/api/auth/refresh` ⇒ 登录后 ≤15 分钟，**每个 same-origin `/api/*`**（nf-ticket 铸票、插件面、项目列表…）都被 relay 门 `require_user` **裸 403**（拒绝发生在 relay，**不落隧道帧**），而早已建立的 WS 照常工作 ⇒ 用户感知 = 「图片点了零反应 + 插件面板老要登录 + 项目列表加载失败」；手动刷新之所以「即愈」，是因为刷新重新走进 console_shell 登录腿静默重铸 15 分钟票——**麻醉不是治愈**，15 分钟后必复发。#503 审计在「刚登录的 15 分钟窗内」测试，故不复现。

## 证据链（按排查矩阵）

### a. token 键派生 × 门户回投会话 — **排除**
- 前端唯一凭据腿 = HttpOnly 会话 cookie（`GatewaySessionStore.scala:192` `CookieName = ${lowerName}_session` = `stand_session`；`nfTicket.js:186-195` 铸票走 cookie，Bearer 仅是回退）。localStorage `key('token')` 在 B′ 清理批（`ws.js:433-446`）验证 cookie 后即被主动清除，#500 的 key() 派生全站一致。
- 实测：本地全链 curl —— 本地铸票（`POST /api/auth/console-ticket`，Bearer file-token）→ 303 + `Set-Cookie: stand_session=…` → 携 cookie `POST /api/nf-ticket` **200** → `GET /api/nf-file?path=…&ticket=…` **200 / 2.8MB image/png**（探测时间 22:58）。**引擎侧鉴权/铸票/取字节全部健康。**

### b. Safari 假设 — **排除（且前提不成立）**
- 进程取证：macOS 本机 Safari（pid 633）**零 TCP/UDP 连接**；两枚一次性档案 Chrome（16:31 `/tmp/stand-coldstart-console-profile-65651`、16:37 `…-66171`）也**零连接**，其 cookie jar（只读副本解析）**从未有过任何 neblink.nebflow.space cookie**，历史记录最后停在 21:42（poker/portal）。
- 作者 22:02 原话（引擎 WS 消息日志 stand.log:533）：「我重启了，1是为什么我们还是从 **https://neblink.nebflow.space** 启动…」；KAI（Windows/Edge）此刻持有 **两条到 45.32.62.185:443（relay）的 ESTABLISHED 连接**（netstat 实测）。**作者现役会话 = KAI 上的 relay 源控制台。** 浏览器家族与 #503 审计的 Chromium 同族，纯 Safari 行为差异不成立。

### c. messages.js:2588 回落路径 — **确认（为症状放大器，非根因）**
- 链路逐级静默：铸票 403 → `nfTicket.mintRound` 计熔断 → `ticketUrl` 产**无凭据 URL** → `savedPathBlob`（messages.js:2542-2548）非 ok ⇒ null → 2588/2590 回落 `previewLocalPath` 文本腿 → `pop.readFile` 对二进制图片无意义 ⇒ **全程零可见反馈**；内联 `<img>` onerror 直接摘槽（messages.js:2180）。relay 门拒绝连字节请求都不发生（见 d），前端拿到的是 relay 自己的 `403 {"error":"Invalid or expired token"}`。

### d. 引擎日志 22:02-22:38 窗口 — **429/断路器理论死亡**
- 现役实例（22:00:23 boot）conn-guard 快照 22:03→23:14：`tunnelRejected=0`、`overflow=0`、无 429；`tunnelReq` **平线 14/3min**（22:15 起恒为 14）——作者 22:38 点图、22:45 开插件/项目面板时**隧道零新增帧**。这恰是「拒绝发生在 relay 门、未铸帧」的直接物证。
- 铸票断路器（3 败熔断 15s，nfTicket.js:26-29）机制健康，本窗内无服务端铸票失败记录（服务端根本没有收到铸票）。
- 附带发现：作者设置的 `GATEWAY_CONN_GUARD_TUNNEL_PER_IP_CAP=4096` **没有生效**（快照 `perIpCap=64`，env 名正确 connguard.scala:109，但未传入 22:00:04 的 sbt 进程环境）——与本 bug 无关（隧道零拒绝），如需生效须在**同一启动 shell** export。
- 噪音排除：22:00 起 `WebSocket auth failed from ::1` 每 ~30s 一条 = **Codex 桌面App**（pid 11001，`[::1]:56137→8080` ESTABLISHED）的陈旧凭据重试，与作者无关。

### e. 门户回投链影响 — **确认（根因所在面）**
- consoleUrl = `https://<CONSOLE_DOMAIN>/?ticket=…`，部署取 `CONSOLE_DOMAIN == SITE_DOMAIN = neblink.nebflow.space`（link-server `routes.rs:3147` + `deploy/docker/Caddyfile:125-131`）。
- relay 门：`/api/{*path}`、`/assets/{*path}` catch-all → `console_ingress_http`（routes.rs:3606）先 `require_user`（routes.rs:551-562）：严格校验 15min access cookie（`ACCESS_COOKIE="neblink_session"`、`max_age=ACCESS_TOKEN_TTL_SECS`，routes.rs:186-189/647-658、auth.rs:10），**无滑动、无自动续期**；失败即裸 403、不铸帧。
- 刷新腿存在（`POST /api/auth/refresh`，refresh cookie 30d），但**前端全仓零调用**（web/js grep 无 `auth/refresh`）——15 分钟死窗由此坐实。

## 修复（两处，均已提交）
