## 4. 怎么重放上下文（Q3）

**transcript → 新会话 initialMessages / resume prompt 的链路**（全部单点）：

1. **分类+构造点（boot 路径唯一）**：`NodeEngine.bootRecoveryClaim`（NodeEngine.scala:1137-1242）——读 `resources.sessionStore.loadMessagesForSession(sid)`（:1230），构造 `NodeEngine.ResumeContext`（case class 定义 :6806-6826；普通节点 :1232-1237，loop 双会话 :1208-1217）。**boot 路径上 ResumeContext 只有这一个构造点**；运行期 stuck-recovery 另有一个同底座构造点 `hardResumeNode`（:1508-1570，ResumeContext 在 :1553，R-2 重放封顶 40 条 `StuckRecoveryReplayMaxMsgs`，Defaults.scala:913）——「同一恢复底座」（:1487 注释自述）。
2. **认领**：(a)/(b) 类 `resumeClaim`（:1164-1190）——单事务 CAS 翻 `Running|Interrupted → Pending` + 清 `bgWait` + 清未申报计时（:1170-1180）+ 入 `bootRecoveryQueue`（:1185）+ FlowMapEventLog "claimed (resume)"（:1186-1187）。
3. **慢段启动**：`bootRecoveryStart`（:1247-1250）= 出队 + `startNode(nodeId, Some(ctx))`，fork 于信号量并发 3（`CrashRecoveryConcurrency` 默认 3，Defaults.scala:674；ProjectCrashRecovery.scala:93-103）。
4. **startNode(resume)**（:2374-2379）：resume=Some ⇒ **跳过 buildInput，首轮输入 = `ctx.resumePrompt`**（:2400-2403 `resume.fold(buildInput…)(ctx => IO.pure(ctx.resumePrompt))`）；CAS 翻转/deps 闸门/barrier 复核全套照走（:2366-2372 注释「恢复不绕过任何启动纪律」）。
5. **spawn 链水合**：spawnAndRun（:2576-2616）——`sessionId = resume.fold(新 id)(_.sessionId)`（:2607，**D2：复用旧会话 id ⇒ transcript 单文件续写 + F2 队列重放白捡**）→ runWithAgent（:2814-2816）→ NodeRunner.SpawnParams `initialMessages = resume.fold(Nil)(_.recoveredMessages)`（:3012-3014）。loop 节点同构（spawnAndRunLoop :2623-2690：worker :2671 / verify :2685 双会话各自水合；spawnLoopSession 形参 :3454，透传 :3507）。
6. **resume prompt 文本（唯一构造点）**：普通节点 `nodeResumePrompt`（:6827-6831）——"[system] The process crashed during your last turn and restarted; history restored from disk (N messages; breakpoint = last persisted tool round)… verify them first (git state, key files); do not repeat completed work. Full task text: NodeList(detail=…)"；loop worker `loopWorkerResumePrompt`（:6837-6841）；loop verify `loopVerifyResumeAnnotation`（:6846-6848，verify 输入由 worker transcript 末条 assistant 文本重建）；bgWait 死亡告知段（:6824-6829 `bgSection`）。

**结论**：重放 = 「磁盘 transcript 全量水合进 initialMessages + 一段固定模板 resume prompt 作首轮输入 + 会话 id 复用使后续 turn 继续单文件续写」。构造点唯一（bootRecoveryClaim；prompt 模板唯一 nodeResumePrompt/loopWorkerResumePrompt）。

## 5. 节点与链归属怎么恢复（Q4）

### 5.1 bootRecoveryClaim 三分类（NodeEngine.scala:1137-1242，判定表 ：1191 注释 §3.3）

资格（:1141）：`status ∉ {Running, Interrupted}` ⇒ None（非候选）。

- **(a) checkpoint 完整 / (b) mid-turn**：磁盘上不可区分（:1117-1118 头注释「(a)/(b) —— 磁盘不可区分，统一同路径」）——`sessionRef` 有值 ∧ transcript 可读非空（普通 ：1230-1237；loop worker :1198-1218，verify transcript 可缺，缺则空水合 :1200-1205）⇒ `resumeClaim`：翻 Pending + 清 bgWait/reportPendingSince（:1170-1180）+ 入 bootRecoveryQueue（:1185）+ 事件 "claimed (resume)"（:1186）→ 后果 = 慢段 rehydrate 续跑（§4）。
- **(c) sessionRef 无值 / transcript 缺失损坏空** ⇒ `failClaim`（:1143-1163）：fresh 守卫（仍 ∈{Running,Interrupted} 才处置，:1150）→ `failNode("crash recovery: session transcript lost/corrupt…")`（:1151）→ **写后复核 draining 诚实性**（:1152-1161：failNode 被关机窗口守卫拒写时不得假装已失败，返回 None）→ 后果 = 既有 deliverFailed 链 + 事件 "failed (class c)"（:1154-1155）。
- **None 第三态**：非候选 / 认领事务败给并发状态变更（CAS 拒写 :1180-1182）——留 watchdog 兜底。

### 5.2 interrupted 翻态点

`GracefulInterruptHook.run`（ShutdownState.scala:79-100，注册单点合并 Main.bootGateway/succeedGateway 两处旧钩子）：线程内严格有序 ① `ShutdownState.beginDraining()`（:85，置 draining 守卫——failNode/autoFailDeadRunning 拒写 failed，:17-19）→ ② `interruptRunningNodes(timeoutMs)`（:112-135）：遍历全部挂载项目快照，逐节点 CAS `Running → Interrupted`（+bgWait=None，:140-147；sessionRef/deliveredTo **原样保留** ：109-111 注释）+ WS nodeUpdated + FlowMapEventLog `"interrupted"` 审计（:151-160，事件类型 `InterruptedEventType` NodeEngine.scala:6799）→ ③ `LlmInterface.cancelAllInflightSync()`（:100，token 燃烧防线恒在翻态之后）。整体 deadline 5s（`ShutdownInterruptTimeoutMs`，Defaults.scala:723），超时残余留 Running 走 kill -9 同款 sweep 兜底（:91-94）。
