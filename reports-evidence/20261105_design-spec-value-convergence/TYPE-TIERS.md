# 第二层 · 字号档收敛（13 个档外值 → 7 个目标档）

判据源：`design-scale-spec` 定版 §2.4/§4-③ + 作者令 2026-11-04 20:49。
载体：`font-size:` 声明 **200 处** + `font:` 简写 **322 处** = **522 个改点**
（简写是本体量的 60%：只改 `font-size:` 会得到一个"表格说收敛了、渲染仍在用 11.5px"的假结论）。

## 1. 哪几档被并、依据是什么

| 原值（处数） | 去向 | 依据（不是"数值邻近"，是语义/形态/可读性） |
|---|---|---|
| 7 / 8 / 8.5 / 9 px（6 处，图标盒内字符） | **8px** `--ds-fs-glyph` | **形态保全**：14–18px 固定盒里的 2–3 个字符，11px 实测宽≈18px 必溢出。同「滚动条拇指归 4px 会弄坏形态」一条判据用在字面上 ⇒ 立具名例外槽，禁作正文 |
| 7 / 8 / 8.5 / 9 / 9.5 / 10 / 10.5 px（其余 88 处） | **11px** `--ds-fs-meta` | **可读性硬下限**（SKILL §2 / 定版 §2.4）：11px 以下是判例级回归，不是"更精致"。这是文本档，与上面 6 处图标字形是**两种物**，因此分道 |
| 11.5 / 12.5 px（36 + 33 处） | **12px** `--ds-fs-hint` / `--ds-fs-btn` | 半档是官网 `--st-fs-label/-btn` 的**逐值转录**，客户端没有对应档；12 是最近的既有档（链/钮按语境挑，值恒 12） |
| 14 px（52 处） | **14px** `--ds-fs-subtitle` | **保留档**：定版 §4-③ 明文「不并入 13 或 15：上下都会破坏已定稿的面」。本层只把它令牌化（等值），不动值 |
| 15.5 px（2 处） | **15px** `--ds-fs-title` | 两处都是标题族（字重 500/600 + 负字距）：perception 标题、登录卡标题 ⇒ 归 title，不归 callout（callout 是正文/输入件语义） |
| 18 / 19 / 22 px（6 + 1 + 5 处） | **20px** `--ds-fs-display` | 18px 语义分裂（epub h2 标题 vs 28–32px 盒里的 × 字形）：两族**在档位上同解**为 20（字形 18→20 在 32px 盒里不可辨；epub 22/18/16 三层收成 20/20/16，层级仍靠字重与行距分层，这是既有做法）。取 20 而非 17，是为避免"17 档只为几个字形出生" |
| 26 px（1 处） | **28px** `--ds-fs-title-lg` | 登录用户码大字展示，属大标题族；26 无档、28 是既有档（差值 2px 在等宽数字上只影响字宽，实测无溢出） |

**结果：区间 [7,26] 的目标档 = 7 个** —— `8`（图标字形例外槽）· `11` · `12` · `14` · `15` · `20` · `28`。

## 2. 改前必红 / 改后必绿（机械断言）

断言面：**区间 [7,26]px 内还残留多少档外/未令牌数值**（`layer2-font-tiers.mjs --verify`）。

```
改前：layer2 font-tiers [VERIFY]：区间 [7,26]px 内档外字面量 = 522      → EXIT 1 (红)
改后：layer2 font-tiers [VERIFY]：区间 [7,26]px 内档外字面量 = 0        → EXIT 0 (绿) ✅
```

改点逐值（522）：`10px×126 · 11px×91 · 12px×60 · 14px×52 · 9px×39 · 11.5px×36 · 12.5px×33 ·
13px×24 · 10.5px×22 · 9.5px×8 · 18px×6 · 8.5px×5 · 22px×5 · 16px×4 · 8px×3 · 15.5px×2 ·
15px×2 · 7px×1 · 19px×1 · 20px×1 · 26px×1`。

去向逐槽：`meta 289 · hint 117 · subtitle 52 · body 24 · display 13 · btn 12 · glyph 6 ·
callout 4 · title 4 · title-lg 1`。

跳过（有理由，不是漏）：`13.5px / 14.5px / 21px` = 会话行 / 主对话气泡 / 过渡卡主标题三个
**组件语义具名槽**。裸字面量指到这些槽上会污染语义（一张工具卡的 21px 不是 card-hero）。

## 3. 双档对照截图（375 与 1440，改前 / 改后）

目录：`shots-layer2-pre/` 与 `shots-layer2-post/`（各 6 张：shell / chat / settings × 1440×900 / 375×812，暗档）。

量化差异（`compare-dirs.mjs`，逐像素，tolerance 0）：

| 场景 | 视口 | 差异像素 | 占比 |
|---|---|---|---|
| chat | 1440 | 9,762 | 0.7532% |
| settings | 1440 | 10,664 | 0.8228% |
| shell | 1440 | 9,611 | 0.7416% |
| chat | 375 | 161 | 0.0529% |
| shell | 375 | **0（逐字节 SAME）** | — |
| settings | 375 | **0（逐字节 SAME）** | — |

读数含义（重要）：**手机档几乎不受影响** —— 4/6 张 375 面逐字节不变，唯一变化的 chat-375
只有 161px（一小块徽标文字），因为手机层走 `--mfs-*` 独立桥槽、桌面档值改不到它。
这正是手机章「桌面零命中」纪律的正面证据：本层改的是桌面字阶，手机层被结构性隔离。
