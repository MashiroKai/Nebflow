## 二、v5 模型细节裁定（实施批注意）

- **环含 active**：`buildRing()` 从 v4 的「不含前卡」改为**含全部页签**——`ring[0]=active`（前景位初始 occupant），`ring[r]=TABS[(ai+r)%N]`；pos 浮点，`d = wrapDelta(r−pos, M)`，d=0 即前景位（初始 pos=0=canvas 前景）。v4 报告「环形语义」一节的取模公式不变，只是环的成员集扩了一圈。
- **位姿双支**：`poseOf(d)` d≥0 = v4 露边阶梯**原样**（peek 22·a₁+6·a₂、rotateX 微后仰 −1.6°/级、无 translateZ、无逐级缩放通道——同尺寸铁律不动）；d<0 = **v2 翻落**（y 下坠 30a+40·sin(πa)、前倾 6a+30·sin(πa)、op 0.42/级衰减，×sizeK；**y 从前景基姿 STACK_SHIFT 起落**保证 d=0 两侧连续）。翻过的卡沉到前景下方淡出，绕环从 d>0 背后阶梯回归。z 序改按 |d|（`100−ad·10`），前景卡恒最高。
- **canvas 面板驱动（本版核心机制）**：面板位姿/透明度由 d₀=wrapDelta(−pos, M) 驱动——transform = 缩放基姿 ∘ poseOf(d₀) 相对量；**交接窗交叉淡换**：d₀∈(0.10,0.50) 渐入（环卡从背后回归→面板接管前景）、d₀∈(−0.40,−0.08) 渐出（面板翻落→环卡接管翻落）；两表面位姿恒等、只有 face 交叉，无跳变。面板的环卡（selfCard）alpha = op(d₀)·(1−panelA)，与面板严格互补。驱动期间面板加 `no-trans`（逐帧直写 inline 不吃 CSS 过渡），回前景位（|d₀|≈0）即清 inline 交还 `.stacked` 类基姿（入场动画因此不被驱动杀掉）。deck-layer 的 `.over`（z-60）随 panelAlpha<0.995 自动抬/落——环卡在前景位时整组盖过 canvas；面板 alpha→0 时 `pointer-events` 同步关断（**隐没的面板不得拦截卡组点击**，此为踩过的坑，见 §四.2）。
- **擦洗=浏览、点击=提交**：擦洗全程不换签（canvas 内容保持不动，藏在前景卡之下）；点前景卡（|d|<0.5）才提交换入（v4④ 编排原样：×1/0.85 放大盖区→落位换内容→旧 canvas ghost 缩回卡组深处→卡组收回）；点**深处**的卡（|d|≥0.5）=滚轮语义翻到该卡（v1「点后卡翻到该卡」回归）；canvas 前景位点击 canvas=收回（内容不变）。
- **环流就地收敛（保相位）**：非前景卡被关 = 从 ring 摘除 + 环形旋转把 active 转回环首（pos 同步减位移 `pos −= s`，每张卡的 d 不变=零重排跳动）+ 按 id 重挂 data-r；M 变化引起的环绕重分布只影响深处淡出区。canvas（前卡）被关 = 整环重置（mountRing + pos=0，新 canvas 前景，邻位接管同 `closeTab`）。右键「关闭其他」同整环重置。
- **划走作用于前景面**：canvas 前景=拖面板（v4⑥ 语义，关当前页签）；环卡前景=拖该卡（v2⑥ 回归，关那个文件，同参数：6px 界分 / 20% 区宽或 0.55px/ms 速度阈 / 13° 侧旋甩出 / spring 弹回）；selfCard（canvas 的环卡）不参与拖划（交互走面板）。
- **收回衔接**：轮换态收回（ESC/点空白/再点浮钮）时面板位姿 no-trans 瞬时归位 + `#deck-layer.collapse` 0.18s 整组淡出 + 面板 alpha→1 交叉（face 无跳变），随后解除缩放；内容始终不变（v4⑤ 语义）。
- **浮钮（v5②）**：DOM 从面板子树移到 canvas 区层（面板 docked 父级），CSS 同一条 `.deck-fab` 规则（top 10 / right 12 / 40px 玻璃钮语言逐字不动），加 `z-index:70` 恒高于 deck-layer（z-5/.over z-60）与面板（z-10）；aria-pressed 语义不变；换入飞行等过渡中忽略点击防半程误触。
- **实施批落点更新（canvas.js）**：浮钮挂 canvas 区容器（面板的 docked 父级，**不在面板子树**）；deck-layer 挂同容器内、面板之前（v4 不变）；整区缩放类 `.stacked` 加在 `#canvas-panel`（v4 不变）；数据源 = `tabs` Map，环 = active 起环形序**含 active**；dirty 读 `isTabDirty()`；右键「引用当前页」复用 `refForTab()`；关闭接管同 `closeTab()`；面板驱动/交接窗/就地收敛三个机制见上，实施时建议把 `panelAlphaOf` 的窗口常量（0.50/0.40/0.08/0.32）与基姿常量一起收进单一来源。

**过程中被验收拦下的三处问题（已修，均带教训）**：

1. **翻落支的 y 基线不连续**：初版 d<0 分支直接沿用 v2 的 `y = 30a+40·sin(πa)`（v2 的前景基线是 y=0），而 v5 卡的前景基姿是 y=STACK_SHIFT(8px)——卡穿过 d=0 时跳 8px。修正为 `y = STACK_SHIFT + (30a+40·sin(πa))·sizeK`。教训：**v2 的位姿公式移植时，先对齐两版的前景基线定义再抄系数**。
2. **隐没面板拦截点击**：面板 alpha→0 后其 hit 区域仍跟随驱动位姿存在，会拦截前景卡的 pointer 事件——驱动里补 `pointer-events: none`（alpha<0.02 时）。教训：**透明度驱动的元素必须同步驱动命中测试**，`opacity:0` 不等于不可点。
3. **自动化验收脚本自身的级联期望腐化**：第一轮 16 个 FAIL 全部是脚本按 v4 语义写死的期望值（A4 翻到该卡后前景已易主、A8 起页签数/环成员逐级变化），引擎行为逐项核对后全部正确；改为自校准断言（从 `__demo.state()` 读 M/active 再推导期望）后 58/58。教训：**多组串联的验收脚本，后组的期望必须从前组的实测状态推导，不能从初值手算**。

**环境注**（继承 v2/v3/v4）：无头 chromium rAF 实测 ~36fps，指数趋近收敛时间按比例拉长，自动化等待 ≥2.6s；真实浏览器 60fps 无此现象。
