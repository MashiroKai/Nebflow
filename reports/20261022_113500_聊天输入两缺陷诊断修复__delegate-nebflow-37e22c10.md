# 聊天输入两缺陷 · 诊断修复报告（症状一消息并泡 + 症状二附件大绿块）

## 诊断（症状一：两条独立 send 渲染成一个气泡）

**取证链**（会话 `d7c3cb54-dd90-4f3f-bbf6-e7898c425cff`，2026-10-22 10:49 现场）：

1. **落盘**：`/Users/kaiyu/.stand/sessions/d7c3cb54-….ui.json` 第 **744** 行 = **一条** `UiMessage.User`
   （ts 10:49:27.839，atts=0），text 同时含终端粘贴全文与「[进程已完成] 为什么刚刚stand被强制退出了…」。
2. **线上**：引擎日志 `stand.log:14000` = 10:49:27.840 **恰好一帧** `User message: zsh: suspended…`；
   全天无第二帧携带该文本，无判重丢弃、无排队转投记录。
3. **服务端无合并**：`WebSocketRoutes` 一帧一 `AgentCommand.UserInput`；busy 排队逐件入
   `pendingUserInputs`（AgentProcessing.scala:1361-1384，#569 查而不记）；turn 边界 drain
   严格一次一件（`TurnBoundaryDrains.drainHead`；2026-09-15 作者裁定「禁合并语义」原文在场）；
   一帧 = 一条 ui.json 行。
4. **传输无合并**：`ws.js` `pendingSends` 整帧 FIFO 补发，无拼帧。
5. **渲染无合并**：三条恢复腿（restoreFromStorage / restoreFromBackendHistory / drain 补渲）
   一行一气泡；无相邻用户行合并逻辑。

**结论**：并泡不是合并机制，是 **compose 时两段文本已同在输入框、一帧出线**。三层（服务端/
传输/渲染）均无聚合窗；#569 幂等轨无误伤（当日无 messageDuplicate 丢弃记录）。

**促成缺陷（本批修掉）**：`input.js` 的 **busy 排队腿零会话流呈现** —— 会话忙时发送，气泡不
出现，消息只落在输入框上方小小的排队条里（before 截图实证：会话流空白、两条消息全在
「排队中 (2)」）。作者无从分辨「这条已作为独立气泡在场」，继续在（已被清空的）输入框打下
一条 ⇒ 观感即「两条并成一条、时间戳还相同」（drain 补渲又取 `Date.now()` 而非入队时刻）。

## 修复

### 症状一：每次发送 = 立即自己的独立气泡

- `input.js` busy 排队腿补**乐观气泡**（f1-send-queue 离线腿同款形态）：
  `queueMessage(..., { rendered: true })` + `renderUserBubble(..., { msgId: item.clientMessageId, pending: true })`。
  发送即刻上屏、带「待发送」时钟小标；drain 腿既有 `item.rendered` 分支只摘小标不重渲
  ⇒ 全链每条逻辑消息**恰一气泡**（skill/compact 排队腿不受影响——extra 只加在普通支）。
- **时间戳真值**：`queueMessage` 钉 `ts: Date.now()` 入项、随 `persistQueue` 跨刷新存活；
  drain / sendImmediate 补渲改用 `item.ts`（修前补渲取渲染时刻 ⇒ 排队项时间戳漂移）。
- #569/#570 幂等语义零触碰：真重复投递仍由 clientMessageId 判重收口。

### 症状二：附件卡 = 统一 chip 族

- `chat.css` `.row.user-media .file-card`：气泡绿底无边框大卡（#491 主题三遗留形态 = 大绿块）
  退役；改为与 AskUser 附件卡 / Pop 文件卡同族的紧凑 chip——底 = `--color-surface-2`
  （AskUser 同款中性灰玻璃，亮暗自适应）、细边框 = `--glass-etched-border`（chip 语言正典
  token）、10px 圆角、28px 类型图标档（同 input.css `.att-thumb/.att-file` 尺寸档）、
  max-width 264px、文件名 + 大小 + 类型色 tile 保留。
- 墨水回归 token（修前 `#111`/alpha-black 硬编码随绿底退役）。
- **范围红线**：用户文本气泡本体颜色不动；图片/视频媒体面（气泡剪影）不动；agent Pop 面不动。

## 残余面（不属本批，如实申报）

- compose 时两段文本同框的**键盘级**真因（首 Enter 是否被 300ms `isSending` 静默吞、IME 滞留
  或纯人工节奏）无客户端痕迹可考（零日志面）；本批修掉的是它的**可见性根因**——每次发送立即
  独立成泡后，「发没发出去」不再有歧义，并泡观感失去产生土壤。如需键盘级定谳，可后续给
  send() 早退支加诊断日志（本批未动发送语义）。
- live 排队项在**非活跃视图**发送时不渲染气泡（沿用既有 drain 活跃视图闸），与修前行为一致。
