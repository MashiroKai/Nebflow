## 0. TL;DR

**核心矛盾不是「做得少」，是「到不了」。** 近 8 周主线合入 1064 个批次（峰值一周 307 个），其中 **431 个批次在 9-20 → 10-21 的发版空窗里排队等了 11–31 天**；10-21 一天连发 beta.1/beta.2 后，10-24 又打了一个 tag——但这个 tag **没有 bump VERSION（tag 上 VERSION 仍是 2026.10.21-beta.2）、没有构建 assembly、没有部署**，是个死 tag。作者机器 8 周里实际只吃到 3 个构建（9-20、10-22、10-25-dev 未激活），**昨晚新构建在启动链上连死 14 次（堆转储为证），引擎被迫整夜停在旧 assembly 上**。作者感知的「一个多月没发版」，测量学上的真身是「发版未触达」＋「触达的没冒烟」。

第二矛盾是**门禁执行不均**：7 天窗口 98 份批次报告里，约 26 个代码改动批中 ~17 个「分支内已绿」、8 个「主会话代跑/移交」、个别真留白——#833 批带着编译级缺陷合入 main，72 分钟后才被主会话首跑逮住。

以下 §1 盘点、§2 诊断、§3 给六条建议（每条附成本/收益/前置）、§4 给落地顺序。

### 1.5 实践清单（如实盘点，含短板）

**在位且有效的：**
- **worktree 批次流**：一批一 worktree 一分支，merge 窗 FIFO（hunk 级冲突预判、锁三步法、WorktreeRescue 抢救 reports/evidence、kept 分支零领先守卫）——8 周 1064 批的吞吐就是它的成绩单；
- **spec 门禁 + 验红文化 + Playwright 验收 harness**（假服务/真链路/截图证据入 evidence/）；
- **双段汇报**（delegate merge 轮报工作、finish 轮报合并；今天的 `fef7afcb` 批刚修掉工作结果被覆写的丢失点）；
- **静态门禁脚本族 + ci.yml 静态 gate job + 自托管 runner**（10-21 落地，在线但**零 job 引用，处于闲置**——现有 ci.yml/release.yml 没有任何 job 指到 `[self-hosted, macOS, ARM64]`）；
- **发版 SOP 有文字版**（beta.2 十步链证据留档）、**更新渠道是全数字的**（OSS 指针 + manifest + GitHub prerelease + min-floor 防断更链）；
- **post-mortem 质量**（boot-oom-attribution 的实验矩阵）。

**欠账（本报告 §2/§3 的靶子）：**
- 发版靠人手十步、无机械卡点（→ 死 tag）；发布仅作者明令触发且无固定节拍承诺；
- main 绿 → assembly → 上线 → 换手，**全程无 boot smoke**，换手靠 `bin/current-version` 手工指针 + launchd，无批准动作留痕、无自动回滚；
- 生产运维脚本在仓库外：`~/.stand/bin/` 的 `nebflow-restart.sh`（42.9KB，8 周里 18KB→42.9KB 增长 138%，靠 7 份手工 `.bak` 当版本管理）、`nebflow-autostart.sh`（3 份 bak）、watchdog（3 份 bak）、`stand` 包装脚本——**git ls-files 里一个都没有**；launchd plist `WorkingDirectory=/Users/kaiyu` + 包装脚本不 `cd` = 昨夜 OOM 的环境半边根因；
- 三台机器 JDK 各异（生产引擎 temurin-23、repo/ci 基线 21、KAI temurin-21），KAI 环境污染（HOME 指向 Cadence 目录）无入库机制；
- 维护清账有优秀先例（#816 文件字节单点账本化、#831 旧域清扫带防回归门禁——「清账法」成型）但**无固定节拍**，且磁盘/日志这类物理清账没人管（29GB hprof）。

## 2. 痛点诊断（逐条给数据）

**2.1 发版节奏——病灶不是「没节奏」，是「发版 ≠ 触达」＋「触发仅凭明令」。**
数据：31 天空窗积压 431 批；10-21 单日两发说明「想发的时候发得极快」（93s 构建）；10-24 死 tag 说明「不想发的时候链会静默断」。发布政策（10-21 修正令）取消了自动勤发、一切等作者明令——这个约束应当尊重（红线级），但它把「记得发、发得全」的责任压回了人脑，而 SOP 无卡点，漏一步无人知。

**2.2 部署链断裂——最大痛点，「代码到 main ≠ 到用户」。**
数据：触达延迟中位 16 天（9-20 空窗期）、当前 88 个首批次条目未触达；换手动作（current-version 指针 + 引擎重启）靠人肉；昨夜新构建 14 连死期间，「回退旧 assembly」这个动作也是人肉完成的（02:27:59 launcher 直启 beta.2 jar）。**部署链的每一段都是手工的，所以每一段都可能断，断了只能靠人发现。**

**2.3 上线无冒烟门禁——新构建与生产引擎之间零体检。**
数据：昨夜 14 连死，第一现场就是作者的生产启动链；而归因报告的 E1–E13 证明同样的启动在隔离数据根 + 隔离端口上 5 分钟就能复现/排除。**也就是说：一套 5 分钟的隔离 boot smoke（启动 + 健康端点 + 一轮 fake 对话 + GC 预算断言）本可以在 10-24 白天就拦住这个构建**，14 次生产死亡、15GB 堆转储、一整夜旧版运行都可以不发生。

**2.4 环境漂移——出事靠人肉考古。**
数据：生产运维脚本 0 个在库（restart.sh 7 份 .bak 当版本管理）；launchd plist 工作目录是家目录（OOM 环境根因）；三机三套 JDK；KAI HOME 污染 + sbt 悬案重启不可愈；主树 6 项 untracked 杂散。**这些状态全部活在盘上、不在版本管理里，每次出事都要现场考古**（昨夜的归因报告花了 11 组实验才把「环境半边根因」钉死——如果 plist 和包装脚本在库里且有漂移检查，这一半 10 分钟就能排除）。

**2.5 维护欠账——三源叠加的体感。**
① **触达欠账**（做了没到，§2.2）；② **物理欠账**（29GB hprof + /tmp 60GB + 杂散文件，无人回收）；③ **重复事故欠账**（Sep-28 与 Oct-24 两轮 OOM 同型、启动链问题两度环境性复发，无回溯清单）。#816/#831 已证明清账可以做得很漂亮（单点账本化 + 防回归门禁），缺的是节拍和物理面。

## 3. 建议体系

> 红线对齐声明：**生产部署逐次批准**不动摇——下述流水线一律停在「staged，候批」状态，换手必须作者明令；自动化只负责「备好 + 体检 + 坏了自动退回」，绝不自动升级。

### ① 发版节奏与版本纪律

**做法**：a) 固定节拍承诺——**每周一个 beta 车次**（如周四），作者明令可加发、可跳票，但车次存在本身把「31 天空窗」变成不可能；b) 机械卡点——`scripts/release.sh` 第一件事校验 `VERSION 内容 == 所打 tag 字符串`，不等则拒打（一句话就能杀死 10-24 那类死 tag）；c) 成文「转正规则」：beta 在作者实名机上连续运行 ≥7 天且零 P0/P1 回归 → 作者一句「转正」即切 stable 档（更新渠道 manifest 已有 beta/stable 双指针，零新机制）。
- **成本**：低。一个校验脚本 + 一页 RELEASE.md；半天批。
- **收益**：杀死死 tag 类；节奏可预期；「上一个新版本是一个多月前」在话语上失去存在形式。
- **前置**：无（可与②并行，但②不落地前节奏只解决「发」不解决「达」）。

### ② 部署自动化流水线（main 绿 → assembly → boot smoke → 作者一键批准切换）

**做法**：把 beta.2 批留下的十步链 SOP 从 markdown 变成一条命令 `scripts/release.sh <version>`：VERSION 卡点（①）→ `sbt assembly` → **boot smoke（③）** → sha256/OSS/GitHub prerelease/manifest（照单重放，证据自动落 evidence/）→ 构建产物**staged 到 `bin/versions/staged/`，输出一张「候批卡」（版本、commit、smoke 证据、sha256）** → **作者批准**（一条令/一行 `stand switch <version>`）→ 原子换 current-version + 重启 + **换手后健康探针**（网关监听 + 一轮 fake 对话），探针失败**自动回退 previous-version** 并报警。与「生产部署逐次批准」红线严格对齐：批准前机器永不自行换手。
- **成本**：中。1–2 个批次；SOP 与证据格式都是现成的，主要是脚本化与候批卡。
- **收益**：直接消灭本报告 §1.1/§2.2 的整类问题；发版从「脉冲 + 断链」变成「例行 + 可审计」；回退从人肉 4 小时变成探针 5 分钟。
- **前置**：③（smoke 是换手前的闸门）；launchd/包装脚本入库（④，否则换手自动化仍在脚本外起舞）。

### ③ 上线冒烟门禁制度化（boot smoke）

**做法**：一个 harness：隔离 `STAND_HOME` + 随机端口启动新构建 → 断言网关监听 + `/api` 健康 + 启动日志零 ERROR + **启动期 GC 预算**（昨夜这种风暴在 gc.log 上是 15 秒 29 个周期，一行断言就能逮）+ 一轮 fake-LLM 对话收尾 → 全程 ≤5 分钟。**两处强制接线**：a) ②流水线的换手前闸；b) 作者机器侧：autostart 在拉起新版本前先跑 smoke，失败则直接以 previous-version 启动并留证——14 连死那晚的每一条死命都会变成白天的一条「staged 构建未通过冒烟」记录。素材基本现成（scripts/e2e-*.cjs、verify-console-fastpath.mjs 的隔离实例模式）。
- **成本**：低。一个批内可交付（harness 主体是既有件的组装）。
- **收益**：最高单项——昨夜事故整类（boot 才暴露的问题）前移到上线前；也是②成立的前提。
- **前置**：无。**建议排第一。**

### ④ 环境即代码（launcher / HOME / JDK pin 入库）

**做法**：a) 建仓库目录 `ops/`（或 `deploy/`），入库：`nebflow-restart.sh`、`nebflow-autostart.sh`、watchdog、`stand` 包装脚本、launchd plist 模板（WorkingDirectory 显式指向明确目录——昨夜 v2 已改 `cd`，把正确形态入库钉死）；b) 一条 drift 检查（diff 部署副本 vs 库内版本，不一致即报）挂进静态门禁族；c) `ops/bootstrap-mac.sh` / `ops/bootstrap-kai.sh`：JDK 版本 pin（复用 scripts/check-jdk-baseline.sh 思路扩到运行时）、JVM 旗标文件化（堆大小不再散落在 plist/命令行）、KAI 的 HOME 修正与 launcher 入口；d) `.bak` 文件全部退役。
- **成本**：低。搬运 + 一次对账；一个批次。
- **收益**：同类事故的考古从「11 组实验」降到「5 分钟 diff」；三机环境可重建；KAI 悬案至少不再新增同类污染。
- **前置**：无。

### ⑤ 维护清账节拍（仿 #816/#831 清账法 + 物理面）

**做法**：a) **每周固定一个「清账批」槽位**（如每周一），轮转消费一张显式的欠账清单（TaskBoard 或 reports/debt-ledger 单一真源），每笔清账照 #816/#831 法：单点收口 + 防回归钉 + 报告留档；b) 清账范围显式包含**物理面**：hprof/gc.log 保留策略（事故归因完成后 72h 自动清或归档压缩）、/tmp 调查残留、主树 untracked 杂散（今晚就能清 29GB + 6 项杂散）；c) 回溯钉：每轮事故归因报告的「遗留清理项」自动入欠账清单，不再靠报告尾部自生自灭。
- **成本**：低。节拍是纪律不是代码；清单今晚可建。
- **收益**：「维护欠账」从体感变成可见递减的数字；重复事故（两轮 OOM、启动链复发）有回溯面。
- **前置**：无。

### ⑥ 与 Triple 镜像分发的衔接（OCI 化部署选项）

**做法**：按 `20261022_201856_triplestar-feasibility` 的裁定（容器化属 C2 期 Linux 腿专属优化；两线守独立开发纪律、不建源级依赖），分发面走**制品契约**而非代码复用：把「assembly jar + pinned JRE + 数据根卷契约」打成 OCI 镜像（或先用 digest 清单 + tar），发布流水线（②）每车次产出一个 digest 寻址制品，KAI/DESKTOP 等机器按 digest 拉取换手——发布即「digest 翻转」，回滚即「翻回去」。triple-star 已有的 digest 产物清单纪律可直接作为契约模板。Windows 两台按该报告裁定维持同步+原生，不强制容器化。
- **成本**：中。镜像定义 + 拉取侧换手脚本；待②稳定后再排。
- **收益**：多机触达与主机同链路（彻底关闭「某台机器还在跑三个月前构建」这类漂移）；制品不可变、可审计。
- **前置**：②③落地且稳定运行一段；作者点头容器面进 C2 排期。

## 4. 落地顺序建议（最低成本 × 最高收益优先）

| 序 | 项 | 理由 | 体量 |
|---|---|---|---|
| 1 | **③ boot smoke harness** | 昨夜 14 连死的整类拦截；且是②的闸门；素材现成 | 1 批 |
| 2 | **④ ops/ 入库 + drift 检查** | 几小时的搬运，立刻终结「盘上考古」；②的换手脚本地基 | 1 批（可与 1 并行） |
| 3 | **② release.sh 流水线骨架**（含候批卡 + 批准换手 + 换手后探针自动回退） | 十步链 SOP 照单脚本化；发版从脉冲变例行 | 1–2 批 |
| 4 | **① 版本纪律卡点 + RELEASE.md**（tag==VERSION 校验、周节拍、转正规则） | 数小时；与 3 同批交付最顺 | 数小时 |
| 5 | **⑤ 清账节拍首期**：欠账清单建档 + 物理清账（29GB hprof、/tmp 60GB、主树杂散）+ 事故遗留项回溯钉 | 立刻兑现「维护欠账在还」的体感 | 1 批（首期） |
| 6 | **⑥ OCI 分发** | 待②③跑稳；随 C2 排期 | 中 |

一页话总结给作者：**供给端（写代码、验 spec、查事故）这 8 周的表现远好于您的体感——1064 批、验红文化、满分级 post-mortem 都是真的；真正欠账的是「最后一公里」：发版无卡点、上线无体检、换手靠人肉、环境不入库。四件事（smoke、入库、流水线、卡点）都是一两个批量的活，做完之后「一个多月没发版」这句话在物理上说不出来。**
