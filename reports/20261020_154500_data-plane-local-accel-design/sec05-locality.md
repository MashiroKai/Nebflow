## 5. 本地性位（locality bit）设计（G1）

### 5.1 三值语义

| 值 | 判定 | 字节腿 | 体感目标 |
|---|---|---|---|
| `local` | 源文件在本机盘，引擎可直读（v2.1 指针的 device = 本机 id） | 既有票据路 `/api/nf-file`（零中继） | ≈45ms 即开（已达标） |
| `device` | 源在**其他**设备（v2.1 指针 device ≠ 本机 id），或文件在另一台机器的 worktree/数据根 | 设备通道分块传输（+进度/取消/续传） | 点击同步出标签，进度环，完成后即开；重开=零取数 |
| `server` | 无本机/设备副本，仅服务端持有（好友附件、上传件、社交入站媒体、纯云端资产） | 现状鉴权 HTTP 路直走 | 现状 + 统一进度 + 入账 |

### 5.2 位放在哪（关键决策：写入时判定，读取端不猜）

1. **引擎侧（真源）**：v2.1 文件指针登记制已隐含位——指针 = `(device, path)`，`device == self ⇒ local`，否则 `device`（登记结构锚点见 §2.3）。引擎新增只是**把已有信息投影到下行载荷**：所有携带文件引用的 JSON（消息卡片、Pop/Card 载荷、浏览器列目录、附件清单）统一加字段 `"loc": "local"|"device"|"server"`，由登记制/持有方写入，**不是前端逐次推断**。
2. **前端（消费者）**：取数单点 `resolveBytes(ref)` 只读 `ref.loc` 分流（§4）；`loc` 缺席的旧载荷按兜底规则降级判定（path 可判 local；带 attachment id ⇒ server；其余 ⇒ server），**兜底判定只许保守（宁可走慢腿，不许走错腿拿到错字节）**。
3. **位不随缓存状态改写**：件入账后 `loc` 仍是 `device`——它决定的是「第一次从哪取」，而「要不要取」由账本判序回答（§4 判序在分流之前，作者令「已下载的打开要快」由此满足）。显示层可另行映射角标（本机/远端/云端），与取数位解耦。

### 5.3 各面的位判定来源（写入点清单，锚点=§3 矩阵行）

| 数据面 | 判定 | 写入点（谁落 `loc`） | 现状缺口 |
|---|---|---|---|
| 消息附件卡（设备本机件） | `local` / `device` | 设备面附件组装时按 path 可读性（行 A；canFetchLocalBytes 已是隐式判位） | 无（达标样板） |
| 好友/群附件 | `server` | 服务端附件域天然 server（行 G；收端目前连隐式位也没有——`localFace` 只挂发送侧 `messages.js:2212-2213`） | 收端零本地性（行 G 缺口①） |
| Card/Pop 引用 | `local` | PopTool FileRefs 解析处（行 C；`probeFile` 通过 ⇒ local） | 内联/票腿双族未统一（行 C 缺口②） |
| 文件夹浏览器 | 逐项 | 列目录响应已带可选 `device` 键（行 D，`explorer.js:881-891` 单点分叉）——**即位前身**，缺键=本机 | viewers 不接账本（行 D 缺口①） |
| 插件资产 | `local`（服务的是本机插件目录） | plugin-assets 路由（行 E） | 无缓存策略（行 E 缺口①） |
| 上传件 | `server`（字节在网关 uploads 子树） | uploads 回读路由（行 F） | 回读无缓存/无 Range（行 F 缺口①） |
| 渠道入站图 | `local`（已落本机盘） | feishu/weixin 落盘后引用（行 G） | 不进 web 消息面（行 G 缺口⑥） |
| evidence/reports | `local` | 仓库绝对路径，票腿可达（行 H） | 无登记面/索引（行 H 缺口①） |
| 设备通道取件（浏览腿/分块腿） | `device` | device 键 + 指针 (device,path)（行 I） | 浏览腿无分块/进度/校验（行 I 缺口②） |

判定纪律：`loc` 由**持有事实的一方**写入（引擎组装载荷/服务端域/列目录端），前端只消费 + 保守兜底（§5.2）。已有的两个隐式判位实现（canFetchLocalBytes、列目录 device 键）是本设计的先例证据——位只是把它们**字段化并推广到全载荷**。
