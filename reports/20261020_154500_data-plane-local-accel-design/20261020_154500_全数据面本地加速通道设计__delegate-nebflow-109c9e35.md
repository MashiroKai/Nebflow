## 1.1 作者令（逐字，设计前提）

> 所有的文件，不论是pop的还是我发送的还是其他的数据比如插件项目文件等。都应该有一个本地加速通道……我点击在canvas打开的速度应该非常快和本机速度一致。而我如果是在Windows上……应该有一个下载进度条。然后打开……思想就是要能够区分数据是本地还是其他主机的，而不是全部都走我们的服务器中继

## 1.2 结论（先行）

底盘已经把「本机直读快」做完了（#538/#542 三档：本机全链 ≈45ms、tab-first 零等待出标签、已下载件零取数直渲染）；**真正的缺口是「本地性」目前只是 nf-file/附件两条腿的隐式实现细节，不是全数据面的一等公民**。本设计把本地性提升为一个显式字段（locality bit：`local` / `device` / `server`），让每个文件引用自带分流依据，统一取数管线按位分流——本机直读、跨设备走设备通道（分块+进度+可取消）、仅服务端维持现状——并把缓存账本从「nf-file 专用」推广为全数据面共享，配变更失效与容量治理。

## 2. 现状底盘（勿重建，全部已并 main）

### 2.1 #538 · nf-file 字节腿的浏览器缓存确定性（2026-10-19 并 main）

- 服务端：`GET /api/nf-file?path&ticket` = 票证制本机文件直读面（`src/main/scala/nebflow/gateway/NfFileRoutes.scala:163-231`）；票据铸造 `POST /api/nf-ticket`（同文件 `:247-301`，批量、逐路径裁定、拒绝逐条返回）。
- #538 修的正是「重复打开走中继」：路由此前从不发 `Cache-Control`，浏览器按 RFC 9111 §4.2.1 启发式（≈10% × now−Last-Modified，新图只有几秒）判新鲜，**中继腿每次开图都全量重穿隧道**。修后显式 `private, max-age=300`（`NfFileRoutes.scala:41-61`）：5 分钟内重复打开 0 字节过网；过期后一次条件往返拿 304。`private` 强制——URL 内嵌票据凭据，永不进共享缓存；max-age 300 ≪ 票据 TTL 1800s，缓存条目活不过凭据。
- 服务端钉：`src/test/scala/nebflow/gateway/NfFileRoutesSpec.scala:480-486`（200 腿必带 Cache-Control: private, max-age=300；实测 If-None-Match → 304 ≈2ms）。
- Range 腿（视频 seek 用）：单字节区间协商 206/Content-Range/Accept-Ranges（`NfFileRoutes.scala:64-143`）；多区间/畸形按 RFC 9110 §14.2 忽略回 200；越界 416 + `bytes */size`。

5. **账本入账 → 打开**：整件成功即入账（含 version 读数），`objectURL` 渲染；打开路径全数据面同一条。

## 5. 本地性位（locality bit）设计（G1）

### 5.1 三值语义

| 值 | 判定 | 字节腿 | 体感目标 |
|---|---|---|---|
| `local` | 源文件在本机盘，引擎可直读（v2.1 指针的 device = 本机 id） | 既有票据路 `/api/nf-file`（零中继） | ≈45ms 即开（已达标） |
| `device` | 源在**其他**设备（v2.1 指针 device ≠ 本机 id），或文件在另一台机器的 worktree/数据根 | 设备通道分块传输（+进度/取消/续传） | 点击同步出标签，进度环，完成后即开；重开=零取数 |
| `server` | 无本机/设备副本，仅服务端持有（好友附件、上传件、社交入站媒体、纯云端资产） | 现状鉴权 HTTP 路直走 | 现状 + 统一进度 + 入账 |

### 5.2 位放在哪（关键决策：写入时判定，读取端不猜）

1. **引擎侧（真源）**：v2.1 文件指针登记制已隐含位——指针 = `(device, path)`，`device == self ⇒ local`，否则 `device`（登记结构锚点见 §2.3）。引擎新增只是**把已有信息投影到下行载荷**：所有携带文件引用的 JSON（消息卡片、Pop/Card 载荷、浏览器列目录、附件清单）统一加字段 `"loc": "local"|"device"|"server"`，由登记制/持有方写入，**不是前端逐次推断**。
2. **前端（消费者）**：取数单点 `resolveBytes(ref)` 只读 `ref.loc` 分流（§4）；`loc` 缺席的旧载荷按兜底规则降级判定（path 可判 local；带 attachment id ⇒ server；其余 ⇒ server），**兜底判定只许保守（宁可走慢腿，不许走错腿拿到错字节）**。
3. **位不随缓存状态改写**：件入账后 `loc` 仍是 `device`——它决定的是「第一次从哪取」，而「要不要取」由账本判序回答（§4 判序在分流之前，作者令「已下载的打开要快」由此满足）。显示层可另行映射角标（本机/远端/云端），与取数位解耦。

### 5.3 各面的位判定来源（写入点清单，锚点=§3 矩阵行）

| 数据面 | 判定 | 写入点（谁落 `loc`） | 现状缺口 |
|---|---|---|---|
| 消息附件卡（设备本机件） | `local` / `device` | 设备面附件组装时按 path 可读性（行 A；canFetchLocalBytes 已是隐式判位） | 无（达标样板） |
| 好友/群附件 | `server` | 服务端附件域天然 server（行 G；收端目前连隐式位也没有——`localFace` 只挂发送侧 `messages.js:2212-2213`） | 收端零本地性（行 G 缺口①） |
| Card/Pop 引用 | `local` | PopTool FileRefs 解析处（行 C；`probeFile` 通过 ⇒ local） | 内联/票腿双族未统一（行 C 缺口②） |
| 文件夹浏览器 | 逐项 | 列目录响应已带可选 `device` 键（行 D，`explorer.js:881-891` 单点分叉）——**即位前身**，缺键=本机 | viewers 不接账本（行 D 缺口①） |
| 插件资产 | `local`（服务的是本机插件目录） | plugin-assets 路由（行 E） | 无缓存策略（行 E 缺口①） |
| 上传件 | `server`（字节在网关 uploads 子树） | uploads 回读路由（行 F） | 回读无缓存/无 Range（行 F 缺口①） |
| 渠道入站图 | `local`（已落本机盘） | feishu/weixin 落盘后引用（行 G） | 不进 web 消息面（行 G 缺口⑥） |
| evidence/reports | `local` | 仓库绝对路径，票腿可达（行 H） | 无登记面/索引（行 H 缺口①） |
| 设备通道取件（浏览腿/分块腿） | `device` | device 键 + 指针 (device,path)（行 I） | 浏览腿无分块/进度/校验（行 I 缺口②） |

判定纪律：`loc` 由**持有事实的一方**写入（引擎组装载荷/服务端域/列目录端），前端只消费 + 保守兜底（§5.2）。已有的两个隐式判位实现（canFetchLocalBytes、列目录 device 键）是本设计的先例证据——位只是把它们**字段化并推广到全载荷**。
## 6. 缓存一致性策略（G3）

底盘 = `nfFileCache.js`（§2.2）：字节在 Cache Storage、索引（LRU 序/字节数/时间戳/version）在 localStorage、LRU+256MiB、TTL 30min、配置可调。本节只设计**增量**，不推翻既有形态。

### 6.1 变更失效（mtime/hash 比对）

现状判据 = 纯 TTL（命中不做再验证，`nfFileCache.js:14-17` 有意取舍：nf-file 无条件 GET 再验证=全量重下）。失效增强走**取数时顺带比对**而非命中时再验证，保住「命中零取数」：

- version 已在读数（`size:lastModified`，`nfFileCache.js:290`）。扩展：任何一条腿**因其他原因**到达服务端/源端时（如铸票、列目录、WS 文件事件），顺带回传该路径现值 `{size,mtime}`；前端比对账本 version，不一致 ⇒ 静默淘汰该条（下次打开按未命中走）。
- 事件驱动腿（零成本高价值）：引擎侧已有 FileChangeLedger/filewatch（`src/main/scala/nebflow/core/FileChangeLedger.scala`）与 WS 通道 ⇒ 本机文件变更推一条 `nf-cache-invalidate {path}` 广播，前端按前缀匹配淘汰。设备侧件以对端文件事件为源（设备通道已有事件面则复用，无则 M2 补）。
- TTL 保留为**兜底**（事件丢失时陈旧窗上限），语义不变。

### 6.2 容量上限与淘汰

- 现状 256MiB 全局预算 + LRU 已达标（§2.2）。增量：**按 locality 分桶预算**（local 128MiB / device 96MiB / server 32MiB，可配），防一类大件（如 evidence 视频）把社交图片全挤出局——分桶在现有索引上加 `bucket` 字段，淘汰仍全局 LRU 但只在同桶内选受害者。
- 持久性分级：Cache Storage 面向「设备大件」（重下代价高），会话内存 Map 维持现状（快路）；server 桶可选 `Cache-Control` 让 HTTP 缓存替账本扛短周期件（#538 已给 max-age=300，免重复建设）。

### 6.3 多设备同文件去重

- 账本键从「单键」升为「内容键双索引」：主键仍为取数键（`nf:<path>` / `attach:<id>` / `dev:<deviceId>:<path>`），副键 = `hash:<sha256 前 16 hex>`。跨设备同一份文件（同一 repo 在 Mac/Windows 各一份）只要 hash 相同即互相视为已缓存：`dev:B:<path>` 未命中时可用 `hash` 副键命中的**另一设备条目**直接打开（字节已在浏览器，与它从哪台设备来无关）。
- hash 来源：设备通道分块传输本就逐块校验（§2.4），整件 hash = 校验链的免费副产品，**入账时写入**；local/server 腿无 hash 时以 `size:lastModified` 代位（副键不命中即放弃，不发起额外读取）。
- 冲突面：同一 hash 多键共存时只存一份字节，索引多键指向同一 Cache 条目（引用计数淘汰：全部键出局才删字节）。

### 6.4 明确保留的取舍（申报）

- 命中不再验证（保零取数）——TTL/事件双兜底；
- 多标签并发写索引竞态可容忍（最坏少记一次 touch，`nfFileCache.js:12-13` 申报）；
- 清缓存用户入口仍不做（底盘注记「候作者示」，`nfFileCache.js:234`），本设计建议 M2 一并补（设置面板一个「清空文件缓存」+ 占用读数，`nfCacheStats()` 读数面已备，`:222-232`）。
