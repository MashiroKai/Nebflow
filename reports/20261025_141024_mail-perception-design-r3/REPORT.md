## 三、对 r2 规格各章的修订清单（实施批以 r2+本章为准）

- **§6 验证码**：6.1 rest 态删除（无检测条；等待期 UI=普通 ask 卡）；hit 态=单码片（类名建议 `otpChip`，取代 `otpStrip`）；点击填入交互、时间窗算法（§6.2）与安全边界（§6.4 secret 通道）全部不变；6.3 边界表「窗口到期」行改为「无 UI 表现，仅 agent 侧收到超时事件」；「窗内第二个验证码」= 码片原位换值（仍无列表）。
- **§7 发送**：7.2 画布呈现改为**感知草稿专用结构化编辑器**（画布壳=平台 Canvas face 逐字；内容面=四件套组件）。草稿落盘格式（front-matter+正文）不变，仅为存储形态，UI 永不露出；画布编辑实时写盘语义不变。7.3 一致性守则全部保留（快照停用、409 兜底、放弃撤回、TTL 过期），仅删常驻 dirty 提示。
- **§9 面板**：9.1 条目模型不变；条目契约的 detail 缩为「身份行+启停+配置（+异常 banner）」，statistics/事件日志字段删除；9.3 三展开态按本文样张修订；头部派生状态词删除，异常才显点。
- **§10**：复制配置提示词全文**废除**（两问配置卡取代；授权码仍经密码框入 secrets，纪律不变）。
- **§11 安全**：全部不变（数据面锁定值、secrets、0600 只是不再展示，非放松）。
- **§12 验收断言**：#3 改写为「等待期 ask 卡 DOM 无任何监听/倒计时元素；窗内到达的验证码以单码片出现，点击后码值入框且码片撤出；窗开前到达的不展示」；新增「画布编辑后快照卡『照此发送』禁用且画布发送值为编辑后内容」（合并原 #7 表述）；其余不变。
- **§13 接口面**：不变；仅 `otpStrip` 命名改 `otpChip`，配置卡保存契约简化（非密值自动识别表由引擎写 daemon-config，密值走 secrets 不变）。
- **§14 分期**：不变；P0 的 ask 卡分支按码片形态，P1 Canvas 腿改为「草稿结构化渲染组件」，P2 面板展开区按极简版。
- **§16 设计语言**：token 表零改动，样张全部沿用（暗色实截已核）。

## 四、待作者确认假设清单（本批自定，批样张时顺带拍板）

1. **授权码收集通道改为配置卡密码框直存 secrets**，r2 的「复制提示词 → 对话 secret 卡」流程整体废弃（配置够简单后，对话引导反而绕）。
2. **未配置态主按钮 = 「连接邮箱」**（面板内直达配置卡）；不再保留提示词复制入口。
3. **验证码窗口过期零 UI**：过期不提示用户（本来就没显示过任何东西），只通知代理侧重发；若作者要一句灰字提示可加回，但默认按全隐执行。
4. **服务器/端口自动识别**依赖内置常见邮箱域表（QQ/163/Gmail/Outlook 等）；识别不到的域才需展开「高级」手填——域表覆盖范围属实施批细节。
5. **信任发件人（原白名单）保留在「高级」折叠**；LLM 数据面 / 账单日结时刻 / 验证码窗口宽度三项**零 UI**（值锁定：头部+4KB / 09:00 / 600s）。
6. **预留条目位收敛为 2 个**（文件、日历；Webhook 暂不放出）。
7. **面板移除 [审计日志] 入口**：audit.jsonl 照记（§13 不变），查看入口待定（备选：配置卡高级里一句「导出诊断」，或直接对话问 agent）。
8. **成功/失败回执精简**：去 SMTP 原文码与「以画布文本为准」长注记（保留 Message-ID）；若作者要保留排障原文，失败卡可折一行「详情」。
9. Canvas 邮件编辑器的**实现载体**假定为「平台 Canvas 壳 + 感知草稿专用内容组件」（r2 §7.2 的 openWorkspaceItem 链路换成草稿标记驱动的组件渲染）；若平台 Canvas 只支持纯文件文本面，则需实施批新增草稿渲染分支——设计面两种载体视觉一致，不影响本批样张。
