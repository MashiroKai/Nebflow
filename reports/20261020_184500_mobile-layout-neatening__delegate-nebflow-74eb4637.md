## 0. 基线事实（先回答任务书三问）

**断点从多少 px 起算移动档？** `≤768px`。`MC:28`（`@media (max-width: 768px)`）与 `js/mobile/bootstrap.js:30`（`MOBILE_MQ='(max-width:768px)'`）同源；手机态 = **独立交互层** `body.mobile-layer` + `html.mobile-html-layer`（bootstrap.js:37-68 激活/拆除，桌面零命中）。手机层不是响应式补丁：桌面 DOM 复用、交互面分离（nav/layout/gestures/floats 四控制器）。

**右侧栏在移动档是常驻还是抽屉？** **常驻双态，非抽屉**（r3/r4 形态，ML:110-206 + js/mobile/layoutController.js）：
- 展开态：贴右缘 `right:0`，宽 48px 毛玻璃竖条，7 键（主会话/画板/项目/图谱/插件/用量/设置）+ 收起键，z240（layoutController.js:37-45,105-130）；
- 收起态：整条收缩为 22px 半嵌低调图标（即展开钮），偏好持久化 localStorage（layoutController.js:61-98）；
- 内容让位 = 横向走廊 `--mobile-bar-gutter`：展开 58 / 收起 30（ML:70,83-85），消费点见 §2-C。

**各面板有没有移动适配，还是桌面布局硬缩？** 三档并存：
- ✅ 有专门移动几何：五个页面壳（项目/图谱/插件/用量/设置，ML:247-344 页面栈）、设置/用量内容收编（ML:475-521）、定时/心跳/后台/智能体浮层（ML:594-622）、记忆/规则/搜索/通用模态（ML:625-643）、登录墙（ML:646-648）、输入区（ML:660-663 + MC:74-86 iOS 16px 防缩放/safe-area）；
- ⚠ 桌面布局硬缩（进了手机壳但内部仍是桌面网格）：用量看板 6 列热图（usage.css:73，317px 内容宽下格 ≈50px）、插件/项目/图谱 = 桌面 pane 原样 re-parent（navController.js:57-63 + ML:340-344）；
- ❌ 漏网（完全没进走廊/适配清单）：`#social-overlay`、`#secrets-overlay`、`#lightbox`（ML:625-648 未列）、`.wsp-panel` 目录选择卡（chat.css:3413 `max-width:calc(100vw-48px)`，居中域=全视口而非内容面）。

## 1. 截图缺陷 ①-⑤ → 结构根因（逐条 file:line）

### ① 顶栏 chips 挤压重叠（笨笨/圆点/时钟/层/脑 叠字）
截图实证（放大裁切）：**搜索图标压在会话名「笨笨」上，会话名又压在绿色后台胶囊上**（绿胶囊的圆点被名字盖住，只剩「4」可见；蓝胶囊=智能体「•4」幸存）。这是**必然重叠**，不是偶发：

根因链（四条规则互相抵消）：
1. r4 把 6 个会话工具**整体搬进 header 右簇**（搜索/后台/智能体/定时/心跳/记忆，floatController.js:47 `FLOAT_IDS`，:63-72 挂 `.header-right` 末尾）→ 375 档右簇实测 ≈230px（6 键 24px×4 + 两胶囊 ≈50px×2 + gap + 右 padding，ML:559-585 收敛到 24px 仍不够）；
2. 桌面碰撞链 main.js:3227-3375 本应按优先级藏键（CHAIN main.js:3243，先藏盾→语音→搜索…），终局钳制 `center.style.maxWidth = Math.max(need, safe)`（main.js:3339）；
3. 但手机层**顶回**了藏键：`#mobile-float-actions .nb-header-hide { display:flex !important }`（ML:550-552）→ 6 个收编成员永不隐藏，链只能藏掉盾/语音（未收编，截图里确实没了）后**穷尽**；
4. 又**顶回**了钳制：`#header .header-center { max-width:none !important }`（ML:652-654）→ main.js:3339 的内联 maxWidth 失效；会话名又**永不截断/永不隐藏**（chat.css:87 + 2026-09-07 作者裁定）。
5. 几何放大器：`.header-center` 绝对居中 `left:50%`（chat.css:61-73），包含块 = 手机层已入流的 `#header`（宽 317 = 375-58，ML:223-238）→ 名字中心落在 158px 处，正好砸进右簇首键（搜索 141-153px）与绿胶囊（157px 起）的占位区；z-index:10（chat.css:69）让名字**画在**它们上面 = 叠字。

结论：**单行制在 375px 下「会话名优先 + 6 键全保留」无解**（预算 351px < 名字任意宽 + 230px 簇），必须改双行制或收敛键数（§3.1）。

### ② 「12 任务」汇总卡悬在聊天流中间
- `#top-overlays { margin-top:68px }`（chat.css:2521-2528）是**桌面锚的化石**：桌面 #header 是 absolute 浮卡（chat.css:46-49，top:0+margin-top:16+高≈52 ≈ 68px），68px 把任务带垫在浮卡正下方；
- 手机层 r3 已把 #header 改 **relative 入流**（ML:223-238）→ 这 68px 变成顶栏与任务带之间的**死区**（背景空白），任务带视觉上「悬在聊天流中间」；
- #chat 顶缘被钉在任务带下沿 +2px（chat.css:19-25），滚动的消息在带下被硬裁（连着 ④）。
- 任务带本体：`#task-list` 折叠态=max-height:0（taskList.css:1-7），有任务时 ≤50vh（taskList.css:9-19），卡头=折叠箭头+「N 任务」（js/taskList.js:968-1007）。折叠态仍占一整行卡高，信息密度极低（一行字占一张全宽玻璃卡）。

### ③ 消息文字从栏底下穿过/贴栏
- 走廊契约**存在但全靠散点规则**：#main（ML:212-215）、页面（ML:259）、卡片层（ML:360）、浮层面板（ML:601,612）、模态族（ML:625-632）、登录墙（ML:647）各自写一遍 `right: var(--mobile-bar-gutter)`；漏网面见 §0 第三问（social/secrets/lightbox/wsp）。
- **聊天内容零呼吸**：`#chat { padding: 8px 0 36px }`（chat.css:26）、`.row { margin:6px 0 }`（chat.css:764-768）都**没有水平 padding** → 气泡右缘（user 贴右边）直接顶到走廊线 317px，距玻璃栏左缘仅 10px；截图里绿气泡右缘实测 ≈319px 已经压线。栏的玻璃 blur+阴影贴着正文，读感就是「字从栏底下穿过」。
- 作者拍板：悬空毛玻璃质感保留，但内容区必须有安全边距。

### ④ 消息顶部长文被视口切断突兀
- 裁剪线 = `#chat` 盒顶（任务带下沿，chat.css:16-30），任意滚动位下气泡上半截直接消失，无渐隐掩码、无 scroll-padding 缓冲；叠加 ② 的 68px 死区，切断面上方是一块空白，观感更突兀。

### ⑤ 输入框上方漏出半行原始思考文本（「来缓解. The design is straightforward (」裸奔）
- 流式思考窗 = `.thinking-content { max-height:7.5em; overflow-y:auto }`（chat.css:2806-2821，= 5 行窗，chat.js:3868-3869 单点常量），流式期间自动滚底 → **最后一行原始思考**（中英夹杂的半句话）正好贴在 #chat 底缘=输入卡上沿，透明无底、无标签、无掩码，读感=裸奔；
- 完成后本应只剩 turn-header 摘要行（chat.css:2843 起），但截图时该行处于「流式中/刚折叠」态，裸奔的是思考窗尾行。

## 3. 逐界面 375px 工整化规范

### 3.0 设计基线（全界面共用）
- 栅格：4pt 基准；内容面左右边距 **12px**；卡片间距 8px；卡片圆角 14（对齐 .task-card taskList.css:30）。
- 走廊（右栏让位）单点化：新增 `--nf-safe-right: var(--mobile-bar-gutter)`，**所有** fixed/居中浮层一律 `right: var(--nf-safe-right)`，禁止再逐面写死（修 §2-H 漏网的机制面）。
- 内容呼吸：`#chat` 移动档 `padding-left/right: 12px`（修 ③）。
- 安全区：顶 = `env(safe-area-inset-top)` + 10px（沿用 ML:234）；底 = `max(12px, env(safe-area-inset-bottom))`（沿用 ML:662）。
- 触达：主操作键 ≥44×44；工具键视觉 28-36 但命中面 ≥44（伪元素扩 hit-slop，先例 ctxthresh.js:126-131）。
- 字阶：页名 16/600；会话名 15/600；正文 14.5/1.55；胶囊与 meta 12；caps 标签 10。
- 玻璃 token 不换值：`--glass-bg/blur/border`（sapphire.css:37-41,75-77）= 作者认可的毛玻璃质感。
- 动效：页面/抽层统一 `cubic-bezier(0.32,0.72,0,1) 0.26s`（对齐 ML:267-276）；`prefers-reduced-motion` 全静。

### 3.1 顶栏（修 ①）——单行改**双行制**
375 档预算：内容宽 317-24=293px。会话名不限宽 + 6 工具键 + 2-3 胶囊同排放不进一行（§1-①），且「名字永不截断」是既定裁定 → **双行制是唯一无损解**：

```
┌──────────────────────────────── 375 ─┐
│ 安全区 env(safe-area-inset-top)+10    │
│ Row1 主行 h44: [ring28] 弹性 [会话名≤全宽] 弹性 [状态键36] │
│ Row2 工具行 h40: [任务n][搜索][定时][心跳][记忆] 弹性 [盾] │
│ 底缘 1px 玻璃分隔线（保留现材质）      │
└──────────────────────────────────────┘
```
- Row1：会话名居中弹性、`text-align:center`、**永不截断**（裁定不变）；超宽时允许换行第二行（名行高 20，最多 2 行）而非挤压他键。左端 ctx 环 28px（有数据才显示，现状不变）；右端**状态汇总键**：一个 36px 玻璃圆键聚合 后台/智能体/待答 三胶囊（有内容才显示任一），角标=合计数，点击弹状态抽层（§3.8）——三胶囊不再各自占位。
- Row2：工具键横向排布（每键 40×40 命中、icon 18），左对齐依次 任务/搜索/定时/心跳/记忆，右端 盾（安全模式，恢复可达性）。键多出的未来容量 → Row2 横向滚动或收进「⋯」，本批不引入。
- 实施要点（实施批）：删 ML:550-552 顶回与 ML:652-654 max-width 顶回；碰撞链 main.js 保持不动，改为在**行内**运行（Row1/Row2 各自 fit）；`#header` 高度 44+40+安全区+1 分隔线；bypass 下拉锚点 top 同步（ML:241-244 改两行高）。
- 亮暗双档均沿用现有玻璃/字色 token，零新色值。

### 3.2 任务汇总（修 ②）——收进顶栏，展开改**顶挂抽层**
- 折叠态不再占聊天流：`#top-overlays { margin-top: 0 }`（移动档），任务带退场；
- Row2 首键 = 任务键：图标 + 计数角标「12」（tabular-nums，同 taskList.css:81 口径）；
- 点击 → **顶挂抽层**：自顶栏下沿滑下，`top: header 高度 + 安全区`，`left:12 / right: 走廊线`，`max-height: 55vh`，玻璃卡圆角 14，内容 = 现 task-card 链列表（taskList.js 数据面零改动，仅换容器几何）；下拉遮罩点击收起；展开时 #chat 不位移（抽层为 overlay，非入流）——消灭「展开把正文推着跑」。
- 保留能力对账：折叠记忆、链头点击进 L1、外部执行器 display-only 行为全部随 DOM 迁移保留。

### 3.3 聊天流（修 ③④）
- `#chat` 移动档水平 padding 12px；气泡上限 85%（宽屏 80%→85% 微调，293px 内容宽下 ≈249px 可读宽）；
- 顶部裁剪掩码：`#chat` 顶缘 20px 渐隐遮罩（`mask-image` 或伪元素渐变，亮暗双档取 --color-bg 同色系）+ `scroll-padding-top: 8px`，消除「半行字悬停在裁剪线」的突兀感；掩码只做视觉渐隐，不改裁剪几何（滚动语义零变动，uifix-taskbar-flow 的入流结论不受影响）；
- 时间行/操作行（16:44｜复制｜引用）保持现状左/右贴齐，但随 #chat 一起获得 12px 呼吸；
- 底部：padding-bottom 继续由 JS 按 #input-area 高度写入（main.js 已有 RO），叠加 12px 水平值不冲突。

### 3.4 右侧控制栏三形态对比（作者拍板方向 + 备选）
| 方案 | 形态 | 内容宽(375) | 拇指可达 | 与键盘/手势冲突 | 改造成本 | 判词 |

- A′ 实施要点：走廊消费点全部改读 `--nf-safe-right`（单点，§3.0）；自动半收监听 #chat scroll（rAF 节流，双向迟滞 ≥24px）；收/展动画沿用现 transition（ML:136-141）；`prefers-reduced-motion` 直切。
