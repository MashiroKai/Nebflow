# Parallel Research — 并行调研纪律

## 第一步：正交拆题

把调研问题拆成 N 个（典型 2 个）正交子题：

- 子题**合起来覆盖**整个问题，**互不重叠**，各自可独立从文献/网络来源调研。
- 问题天然单轨时按视角拆：技术 vs 实践、现状 vs 历史趋势、一手来源 vs 对比综述。
- 每个子题一句范围声明：覆盖什么、排除什么。**范围含糊 = 后续重复调研或留缺口**。
- 拆题者不亲自调研——拆完即分发（新架构：分发器把子题写进各检索节点 task）。

## 第二步：并行深挖（每轨一个节点）

- 每轨只查自己的子题；WebSearch + WebFetch 多独立来源（目标 ≥3 个不同来源）。
- **每条论断必须带来源链接——无链接不作论断。**
- 一手来源优先：官方文档、论文、标准、release notes、官方统计；博客/厂商营销/论坛帖是需佐证的二手证据。
- 事实（有来源）与自己的解读**显式分开**，解读明确标注。
- 标注信息发布日期；过时信息必须注明时效。
- 来源冲突时报告冲突与双方链接——不许默默挑一个。
- 范围内无法用可靠来源验证的部分**显式说明**——如实陈述的缺口是发现，编造的论断是缺陷。

每轨产出结构：

```
## Findings
- <论断> — [来源标题](URL)（发布 YYYY-MM-DD）
## Interpretation
- <综合解读，显式标注为解读>
## Gaps
- <未能验证什么、为什么>
```

## 第三步：逐轨核验（barrier 汇合后）

核验者**必须亲自重访来源**——绝不因链接看起来可信而跳过。对每轨每条论断：

1. **可达性** — 实际 fetch 引用链接；死链或付费墙不可达 → 标记。
2. **内容匹配** — 来源真的支持该论断吗？夸大、误读、断章取义 → 标记。
3. **一致性** — 论断间或跨轨矛盾 → 标记。

最低覆盖：每条承重论断（数字/日期/版本相关/引语）都要核；每轨至少 2 个不同来源核到；综合结论要依赖的全部核。

产出：逐条 VERIFIED / FAILED（死链或来源另有说法或被矛盾）/ UNCHECKED（为何没核）+ 总结（哪些论断可靠、哪些必须标注或剔除）。

## 第四步：综合成文

- 合并各轨为**一份**连贯报告，直接回答原始问题。
- 应用核验结论：FAILED → 剔除或以矛盾证据显式更正；UNCHECKED → 标注未验证或省略。**绝不把 FAILED/UNCHECKED 论断当既定事实呈现。**
- 幸存论断每条保留来源链接；结尾附合并来源清单（每条注明支撑哪个论断/章节）。
- **不做新调研**——只综合各轨与核验给到的材料。
- 报告结构：Executive summary（3-5 句直接回答）→ 主题章节（跨轨组织）→ Confidence & gaps（仍未验证/矛盾/无解的部分及原因）→ Sources。
- 需要落盘时写 `~/.nebflow/docs/<域>/`，不落 /tmp。

## 建图注记（分发器参考）

拓扑形状由任务决定，典型即席形态：拆题（分发器自拆，无独立 planner 节点）→ N 个检索入口节点并行 → barrier 核验节点（in=[各检索节点]）→ 综合节点（in=[核验]——核验输入已聚合各轨原文，边最小化）。核验发现某子题需补查 → 触发方再建补查节点。
