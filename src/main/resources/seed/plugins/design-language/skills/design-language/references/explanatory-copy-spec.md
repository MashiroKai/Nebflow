# 解释性文字设计规范与写作要求（explanatory copy spec）

> 作者令（2026-11-18 16:45，逐字）：
> 「而且我们要形成解释性文字的统一设计规范和写作要求在插件里」＋
> 「好的设计应该是自解释的 并且不要有重复的功能和信息」＋（同轮）「解释性文字太多了」。
>
> 本文是 **「解释性文字怎么写、放哪、多长」的唯一规范正文**。
> 可执行面 = `scripts/check-copy-budget.mjs`（前端门禁链 `make frontend-gates` + CI；
> 本文件 §2 长度预算表**是它的数据面**，脚本逐行读）。
> **改判据改本文，改预算也改本文**，脚本只是执行器。

## 0. 单源边界（两条轴，别混）

作者的话里其实有**两条独立的轴**，分别归两个正文，谁都不许越界：

| 轴 | 问题 | 唯一正文 | 机械面 |
|---|---|---|---|
| **轴 1 · 是事实还是教学** | 这句话该不该存在？ | stand-dev `references/frontend/visual-style.md` 铁律 7 / 铁律 8（四类禁止清单＋保留清单＋判定问句） | `scripts/check-self-explaining.mjs`（词表 + 存量基线） |
| **轴 2 · 怎么写、放哪、多长** | 允许存在的那一句，该多长、放哪个位置、用什么语气？ | **本文** | `scripts/check-copy-budget.mjs`（长度预算 + 存量基线） |
| 重复 | 同一句话/同一信息是不是出现了两次 | `references/disclosure-dedup-spec.md` | `scripts/check-ui-structure.mjs` |

> **两轴独立，判定不互相替代**：一条文案可以**是事实但仍然太长**（进本文预算的存量），
> 也可以**很短但仍是教学**（进铁律 8 的禁止清单）。**不许拿「它很短」为教学句辩护，也不
> 许拿「它是事实」为超长句辩护。**

## 1. 位置档：解释性文字只有三处合法落点

### 1.1 三档定义

| 档 | 落点 | 什么时候用 | 判据 |
|---|---|---|---|
| **L1 就地 hint** | 与它所解释的控件**同一行组内**、控件下方一行小字 | 解释「这个值的约束/后果」——用户此刻正在改它 | C1：与被解释控件同一容器（不得跨组漂浮）；C2：一行，不换行成段；C3：走 hint 令牌（12px / muted），不另造字号 |
| **L2 折叠帮助** | 该区块的折叠层 / `details` / 独立子页内的说明段 | 解释「这一组是什么、口径是什么」——读一次就够，不参与日常操作 | C4：必须收起默认不可见（新开 = 收）；C5：展开控件带 `aria-expanded` |
| **L3 独立页** | 独立文档页 / 官网 / 帮助页 | 完整口径、术语表、迁移说明 | C6：**不得**在操作面上重复它的内容（重复 = `disclosure-dedup-spec` U2） |

### 1.2 反例（位置错了，不是长度错了）

**反例 A · 面级说明句铺在页面顶部**：`js/locales/zh-CN.js` 的
`settings.profileReadonlyNote`「以下均为账号服务当前返回的真实读数，客户端不缓存、不代填。」——
28 字，**长度合规**（≤ L2 档 60），但它是**面级口径说明**却放在个人资料面正文里 ⇒ 位置档
判错：应落 L2（折叠帮助）或直接删（读数本身已自解释）。这一条专门用来证明「长度合规 ≠
位置合规」。

**反例 B · 教学句伪装成 hint**：`model.viaSlash`「用 /model 命令编辑」（11 字，短）。
短，但它教用户「去哪儿敲什么」= 铁律 8 的路径指引类 ⇒ 归轴 1，**删或改成状态事实**
（例如把该处显示为「由 /model 管理」这一事实）。**不许**用「它只有 11 字」放行。

## 2. 长度预算表（机检读取；禁改格式）

表格语义：`键名段` = 匹配用子串（**不区分大小写**，逐个 locale 键按 `.` 切分后对**末段**
做包含匹配；表序 = 优先级，先匹配先命中）；`位置档` = §1 的三档之一；`zh 上限` /
`en 上限` = 该档值的**Unicode 码点数**上限（zh 与 en 分开给，因为字符宽度不同）。

| 键名段 | 位置档 | zh 上限 | en 上限 | 说明 |
|---|---|---|---|---|
| notice | L2 折叠帮助 | 60 | 240 | 通告/口径类整段说明 |
| tip | L2 折叠帮助 | 60 | 240 | 状态提示（读一次即可，不参与日常操作） |
| note | L2 折叠帮助 | 60 | 240 | 口径补注 |
| hint | L1 就地 hint | 40 | 160 | 控件下方一行 |
| desc | L1 就地 hint | 40 | 160 | 输入提示 / 占位说明 |
| explain | L3 独立页 | 200 | 800 | 完整口径（独立页承载） |
| help | L3 独立页 | 200 | 800 | 同上 |

> 上限怎么来的：`zh 上限 = 一行小字在 560px 面板内不换行成段的实测上限`（40 字 ≈ 12px
> 字号一行半内）+ 作者「解释性文字太多了」的方向（只给**下限预算**，不是目标长度）；
> `en 上限 = 4 × zh 上限`（同宽英文字符密度经验值）。**超过上限不判「必须删」**，而是
> 「必须收进上一档位置」——L1 超限 ⇒ 收进 L2 折叠；L2 超限 ⇒ 收进 L3 独立页。

### 2.1 排除面（机检读取；禁改格式）

排除面的语义：这些键**不是界面解释文字**（虽然是用户可见字符串），长度由它们各自的规范
约束，不由本文的预算约束。判定 = 键名以该前缀开头即排除。**加一行 = 声称「这类键不是解释
性文字」，必须在批报告里点名理由**（否则就是把预算掏空）。

| 键前缀 | 理由 |
|---|---|
| content. | 内容目录文案（插件 / 技能 / agent 的对外描述），由 catalog 提供给分发器与列表面，长度归各自的描述质量规范；本仓实测最长 392 字，属正当长文 |

## 3. 写作要求（逐条可判，交付前过一遍）

| # | 要求 | 正例 | 反例 |
|---|---|---|---|
| W1 | **一句一事实**：一个 hint 只讲一件事；两句并列 ⇒ 只留决策相关的那句 | 「登录后此设备与账号下其他设备互联」 | 「冻结时段内 agent 在工具执行完成后暂停，不调用 LLM（零 token 消耗），到点自动恢复。期间输入栏与麦克风禁用。」（两句 + 括号补注） |
| W2 | **说约束/后果，不说操作步骤**：能写成「超过 X 会被替换」就不写「请到某页打开某开关」 | 「账号服务暂未提供该接口，当前无法在应用内修改。」 | 「在输入框输入 /model 命令，按会话类别…配置各自的单个模型。」 |
| W3 | **禁括号补注**：`（即…）`「（用于…）」「（零 token 消耗）」式补注要么并入主句，要么删 | 把限定写进主句：「该值与其它设备共享」 | 「…暂停，不调用 LLM（零 token 消耗）…」 |
| W4 | **语气 = 陈述句**：无「请」「温馨提示」「您」；无感叹号；错误先说发生了什么再给一句下一步 | 「看板打开失败——点行重试。」 | 「请您稍候，系统正在处理，请勿关闭页面！」 |
| W5 | **数字与单位**：数字与单位间空格，技术词（`io`、`0600`、`API Key`）保持半角原样，中文界面用全角标点 | 「40 B」「API Key」 | 「40B」「api key」 |
| W6 | **能靠设计自解释就不写**：分组/间距/层级/留白能表达的，不写文字（轴 1 铁律 7 的落点） | 用分组标题区分「通用 / 运行时 / 高级」 | 每组各挂一行「这里是…的设置」 |

**边界判例（两轴分工怎么看）**：`askUser.secretHint`
「该值将加密存入本机 secrets（仅所有者可读）；代理只收到存储指针，看不到明文。」
——42 字，**轴 1 合格**（`visual-style.md` 铁律 8 保留清单把它当「hint 事实句」的正例）；
**轴 2 超限**（L1 上限 40，超 2 字，带括号补注）。处置 = 进预算存量基线，并按批收紧
（拆两句或去掉括号补注），**不因为它是事实就免于长度纪律**。

## 5. 判定面与门禁用法

判定面 = 两处（与 `scripts/lib/locale-entries.mjs` 同一份实现）：

1. `src/main/resources/web/js/locales/*.js` 的**文案值**（单行 `'key': 'value'`）；
2. `src/main/resources/web/index.html` 的文本行。

代码注释不算（语法级剔注释）。

```bash
node scripts/check-copy-budget.mjs                 # 预算门禁（红/绿）
node scripts/check-copy-budget.mjs --json          # 机器读
node scripts/check-copy-budget.mjs --list          # 只列命中（不做基线比较；人工评审用）
node scripts/check-copy-budget.mjs --duplicates    # 同值多键清单（U4 的人工评审输入，不判红）
node scripts/check-copy-budget.mjs --update-baseline   # 重锚存量（只许在把命中降下来时用）
```

存量记在 `scripts/copy-budget-baseline.json`：**只许降不许升**。加一条 = 声称「这句虽超预算
但必须这么长」，必须在批报告里点名理由。

## 6. 人工评审项与待建渲染腿（诚实边界）

| 判据 | 现状 | 为什么 |
|---|---|---|
| W1–W6（§3 写作要求） | 人工（交付/评审前逐条过） | 语义判断，无可靠词表（词表法会误伤真事实句） |
| 轴 1（事实 vs 教学） | 已有机械面 `check-self-explaining.mjs`（词表 + 基线） | 词表只覆盖四类典型；其余靠铁律 8 判定问句 |
| 「同一面首屏可见说明性文字 ≤ 1 条」 | **待建渲染腿**（Playwright，与 `disclosure-dedup-spec.md` §4 同一 spec） | 需要 DOM 事实 |
| 折叠帮助档是否真的收起 | 人工（Q2/C4/C5 走查 + 截图） | 渲染与可访问性事实 |
