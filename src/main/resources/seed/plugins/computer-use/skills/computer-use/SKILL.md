# Desktop Control — 本机桌面观测与操控

本 skill 教节点**在 Nebflow 真实能力面内**去观测和操控 macOS 桌面：哪些动作今天就走得通（给命令原文）、哪些需要平台能力（如实登记，不假装）、哪些永不许可（机械拒绝）。

## 0 · 能力面真相（先读；避免把「暂缺」当「已有」）

| 能力 | 今天的载体 | 状态 |
|---|---|---|
| 已安装应用清单 | Bash（文件系统 / Spotlight） | **可用**（零授权） |
| 运行中应用、窗口清单 | Bash(`osascript` System Events) | **可用**（需辅助功能授权） |
| 屏幕截图（全屏 / 区域） | Bash(`screencapture`) + `Read`（视觉） | **可用**（需屏幕录制授权） |
| 剪贴板读写 | Bash(`pbpaste` / `pbcopy`) | **可用** |
| 打开 / 激活应用 | Bash(`open -a` / `open -b`) | **可用**（零授权） |
| 显示与分辨率清单 | Bash(`system_profiler`) | **可用**（零授权） |
| 辅助功能元素树读取 | 需平台能力 | **暂缺**（见 `references/host-dependencies.md`） |
| 元素级语义动作、像素事件注入（点击/拖拽/滚轮/按键写） | 需平台能力 | **暂缺**（同上） |
| 控制会话（会话级放行、停止开关、审计流） | 需平台能力 | **暂缺**（同上） |
| 对宿主进程 / 宿主应用窗口的任何观测或动作 | —— | **永不**（本包机械拒绝） |

逐项到工具名的对账表见 `references/tool-surface.md`（30 项，含只读/写类分级与今天可用性）。

**读这条表的方式**：可用 = 有可直接执行的命令，命令原文在 §3/§4；暂缺 = **通道不需要发明，但承载它的平台能力尚未就绪**——缺什么、补到什么程度即可用，写在 `references/host-dependencies.md`（必读，禁模糊搁置）。**禁把暂缺项写成「已适配」**：在结果里报「需平台能力，暂缺」并且给出缺什么，是正确姿态；假装已支持是错误姿态。

## 1 · 主循环：观测一次 → 动作一次 → 复核

1. 需要 UI 状态就先观测，不要凭记忆猜当前状态。
2. 一次只发一个动作。
3. 动作之后，需要新状态就重新观测（不是凭动作返回码推断界面已变）。

**跨步不复用标识**：Nebflow 侧没有持久的元素句柄 / `state_id` 概念——上一步拿到的窗口号、元素序号、坐标一律不得直接搬到下一步；每一步重新观测、重新定位。
**同一次动作里不要既走语义路径又走像素路径**：二者只选一条。
**不要为了让某个动作成立而先去激活/抢焦点**——抢焦点本身是一次对使用者的干扰，属 L2 级动作（§6）。
**桌面子任务不得委派**：桌面观测 / 操控子任务**必须由当前节点自己执行，不得交给子代理**——本平台的委派体是脱离插件面的内核（`DelegateTool` 的 kernel「无插件面、无项目上下文」），它挂载不到本 skill、也拿不到 `scripts/` 里的宿主守卫与 dry-run 默认 ⇒ 守卫与演练纪律会随委派一起丢失（子代理既读不到 §4.2 的停手条款，也绕过了 `HOST-PROTECTED` 的机械拒绝）。同理，**不要把桌面动作外包给另一个节点**：本 skill 的纪律只对本节点自己的执行生效。

## 2 · 权限（macOS：两类，授权只能由使用者完成）

| 授权 | 管住什么 | 使用者在哪开 |
|---|---|---|
| 辅助功能（Accessibility） | `osascript` 经 System Events 读进程/窗口、发按键 | 系统设置 → 隐私与安全性 → 辅助功能 |
| 屏幕录制（Screen Recording） | `screencapture`、任何屏幕像素读取 | 系统设置 → 隐私与安全性 → 屏幕录制 |

**平台事实**：macOS 不提供第三方程序化的授权通道——**没有**「调一个接口就把权限拿到」的做法；授权只能由使用者在系统设置里完成，或由系统在首次真实调用时弹窗。因此本 skill 的权限策略是「**引导 + 收口**」，不是「申请 + 重试」。

引导四条纪律（逐条硬）：

1. **只在失败信息显式点名时引导一次**。失败文本里出现 Accessibility / 辅助功能 / Screen Recording / 屏幕录制 才引导；不要从通用失败（超时、找不到窗口、前台限制、能力不支持）反推权限丢失。
2. **引导用 `AskUserQuestion` 呈卡**：本包 `assets/permission-card.json` 就是可直接传参的卡体（问题 + 选项 + 打开哪个设置面板），照它发，不要让使用者在纯文本里找答案。
3. **`denied` / 已失效 ⇒ 结束本回合**：不重试、不再调下一个动作、不承诺「授权后会自动续跑」。
4. **不要为「预检」主动触发授权**：主动探测会弹系统窗打断使用者——这本身就是一次副作用。就绪判断按 §9 的被动探测做（零副作用）。

## 3 · 观测路径（命令原文；`--run` 语义见 §9）

所有观测命令都可经 `scripts/desktop-observe.sh <子命令>` 封装调用；脚本**默认只打印将要执行的命令（dry-run）**，加 `--run` 才真执行。直接写命令也行——纪律一样。

### 3.1 已安装应用（零授权）

```bash
ls /Applications
mdfind -onlyin /Applications "kMDItemContentType == 'com.apple.application-bundle'"
```

### 3.2 运行中的应用与窗口（需辅助功能）

```bash
osascript -e 'tell application "System Events" to get name of every application process whose background only is false'
osascript -e 'tell application "System Events" to tell process "Safari" to get name of every window'
```

注意：`System Events` 只给到进程/窗口这一层；**控件层的元素树读不到**（那是 §0 表里的暂缺项）。窗口几何（position/size）可以要，控件树不要硬要。

### 3.3 屏幕截图（需屏幕录制）

```bash
screencapture -x -t png /abs/path/shot.png            # 全屏（-x 静音）
screencapture -x -R 100,200,640,480 /abs/path/crop.png # 区域（x,y,w,h）= 局部放大的替代手段
```

拿到 PNG 后用 `Read` 读它——`Read` 直接把图片作为视觉内容交给模型，这就是本平台的「看一眼」通道。

**截图纪律**：① 有明确目的才截，不做例行截屏；② 屏幕内容可能含凭据 / 隐私 ⇒ 落盘路径要落在本次任务的临时目录，用完即删并在结果里申报（临时件条款）；③ 不要用截图代替结构化读取——能用窗口清单回答的问题不要截图。

### 3.4 对端设备的截图（跨端面，Nebflow 已有机制）

当目标屏幕在**另一台已配对设备**上时，不要手工搬运文件，用 Nebflow 的既有约定：

```bash
# Bash(device=<对端设备名>) 里执行
screencapture -x -t png "$HOME/shot.png" && echo "NEBFLOW_PULL:$HOME/shot.png"
```

打印 `NEBFLOW_PULL:<绝对路径>` 标记行后，引擎会把该文件回拉到本地 captures 目录，节点在那里 `Read` 它。`# Devices` 段里带 `capture: screenshot via Bash(device=...) ...` 提示的设备就是已被探明可截图的设备。注意：`Bash(device=...)` 只对真远端生效；本机执行不需要它。

### 3.5 剪贴板

```bash
pbpaste                                  # 读
printf '%s' "<文本>" | pbcopy            # 写（写类动作，见 §6 分级）
```

读剪贴板前先想一下：剪贴板里可能有密码。**不为探索而读剪贴板**，只为完成任务的必需项读。

### 3.6 显示与分辨率

```bash
system_profiler SPDisplaysDataType
```

## 4 · 动作路径

### 4.1 可用：打开 / 激活应用（零授权）

```bash
open -a "Safari"                 # 按名字
open -b com.apple.Safari         # 按 bundle id（更稳，避免同名歧义）
```

这条**不需要任何 TCC 授权**。但它会**改变使用者的前台应用** ⇒ 属 L2 级动作（§6）：任务确实需要才做，不要顺手做。激活类动作不得用于「让别的动作成立」（§1）。

### 4.2 暂缺：元素级与像素级动作

`left_click` / `double_click` / `right_click` / `scroll` / `left_click_drag` / `mouse_move` / `type` / `set_value` / `select_text` / `key` / `hold_key` / `perform_action` / `switch_display` 这一族——**通道存在**（系统自带脚本通道 + 辅助功能授权即可发按键），但 Nebflow 侧承载它们的**门控面**（验身 → 白名单 → 审批卡 → 审计）尚未就绪，而平台已裁「对宿主操作 100% 被拒」是任何实现批的合并前置。⇒ 本包**不提供**写类动作的自动执行路径。

需要它们时：**停手**，在结果里写「需平台能力：桌面写类动作门控面未就绪」，并引用 `references/host-dependencies.md` 的对应条目（缺什么 + 补齐判定）。不要用 Bash 手工拼一条等价的系统脚本调用绕过——那是绕过门控，不是适配。

## 5 · 定位纪律（将来写类动作可用时也照此）

两类权威目标形态，**不得混用**：

- **元素**：来自辅助功能树的语义定位（应用 + 窗口 + 控件角色/名字）。
- **坐标**：只能来自**最新一帧**截图上的点，且只提交 `x` / `y`。

规则：

1. 能用元素定位就用元素定位：语义化、精确、不抢焦点。只在语义路径够不着时才回退到像素坐标。
2. **禁止把像素坐标翻译成元素目标**，也禁止把元素目标降级成坐标。
3. 回退到视觉路径时，**丢弃此前所有来源（文本、元素树）里的坐标样数字**——它们不属于这次视觉任务。
4. 局部放大只在目标太小/太模糊、无法确信点时使用；不放进常规流程（本平台的可用替代是 §3.3 的区域截图）。

## 6 · 分级与门控（对齐既有矩阵，不新造档位）

| 级 | 面 | 例子 | 门控 |
|---|---|---|---|
| L1 | 应用级 | 读应用清单、打开应用、截图 | 检查类可自动；写类逐条确认 |
| L2 | 窗口级 | 读窗口清单、抢焦点、切窗口 | 逐条确认 |
| L3 | 桌面级 | 跨应用、显示切换、坐标级注入 | 逐条确认 + 倒计时确认 |

- **检查类 vs 写类**是分级之上更粗的一刀：**读**（清单/树/截图/剪贴板读）与**写**（点击/按键/输入/剪贴板写/抢焦点）——写类动作**一律逐条确认**，不设会话级放行。
- **四层防线**（验身 → 白名单 → 审批卡 → 审计）是平台侧的实现责任；**本 skill 能承担的是其中最低的一层**：目标的机械拒绝（本包脚本已实现，见 §9 与 `references/host-dependencies.md`），其余三层未就绪前，写类动作停在 §4.2。
- **宿主永拒**：宿主进程自身、宿主应用窗口、以及本机服务端口的监听进程——**观测与动作都不许可**，且在审批流之前就被拒（使用者不该看到一张可以伤害宿主的审批卡）。
- **连续失败即熔断**：同一目标连续 3 次失败 ⇒ 停手报因，不要换姿势重试。

## 7 · 失败与重放安全

- **fail-closed**：读不到就说读不到。不要用默认值补齐、不要用上一次的读数充当当前状态。
- **「命令已下发」不可盲重放**：任何写类命令只要已经发出，就当作**可能已经发生**；需要确认时**重新观测**，不要原样再发一次。
- **错误原样读出**：把失败信息原文（含系统给的原因）带进结果，不要转述成「操作失败」四个字。
- **不得绕过的拒绝**：陈旧帧、目标换了属主、窗口被遮挡、权限拒绝、能力拒绝——这几种拒绝是设计的一部分，不许绕过（例如「窗口被遮挡」不要靠移动/关闭别人的窗口来消解，先确认你要操作的是哪个窗口）。

## 8 · 收口（何时必须停）

命中任一条即停手，在结果里给出**读到的原文 + 停手原因**：

1. 目标命中宿主保护区（脚本会以 `HOST-PROTECTED` 拒绝）。
2. 权限 `denied` / 已失效。
3. 同一目标连续 3 次失败。
4. 目标不存在 / 无法观测（不要反复试探）。
5. 使用者拒绝了引导卡。
6. 需要的动作落在 §4.2 暂缺区。

停手不是失败：**如实收口比强行完成更有价值**。

## 9 · 脚本面

`scripts/desktop-observe.sh <子命令> [--run]`

| 子命令 | 作用 | 是否需要 `--run` |
|---|---|---|
| `readiness` | 被动就绪探测：系统/会话/工具可用性/宿主保护区读数（**零宿主副作用**） | 否（恒安全） |
| `apps` | 已安装应用清单 | 否（文件系统面） |
| `running` | 运行中应用 | 是 |
| `windows <应用名>` | 窗口清单 | 是 |
| `screen [--region x,y,w,h] <路径>` | 截图 | 是 |
| `clipboard-read` / `clipboard-write <文本>` | 剪贴板 | 是 |

**两条硬语义**：

- **默认 dry-run**：不加 `--run` 时脚本只打印将执行的命令原文，**一个宿主调用都不发**。这是「先看清再动手」的机械形式。
- **机械守卫常开**：目标命中宿主保护区（宿主进程 pid、宿主应用名）时脚本以退出码 `3` 拒绝（`HOST-PROTECTED`），与提示词纪律同源、可被独立复核。自测：`scripts/selftest.sh`（全部为零副作用断言）。
