# 宿主依赖面与暂缺项登记

本文件回答两个问题：**这个能力面到底依赖宿主什么**、**缺的东西补到什么程度它就能用**。
🔴 禁模糊搁置：每一项都必须给「缺什么」+「补齐判定」。

## A · 四类宿主依赖逐项定性

### A-1 截图链

| 维度 | 内容 |
|---|---|
| 依赖 | ① 屏幕像素读取的系统授权（屏幕录制）；② 一个能把像素落成文件的工具 |
| 今天能到哪一步 | **完整可用**：系统自带截图工具 + 视觉读取通道；跨端另有平台既有回拉约定 |
| 缺什么 | 无（本链已闭合）；**只是授权要使用者开** |
| 补齐判定 | 使用者授予屏幕录制 ⇒ 立即可用。授权缺失时的正确行为 = 引导一次 + 收口（不是重试） |
| 附注 | 截图内容的敏感性由 SKILL §3.3 纪律承担（目的性、临时件、用后即删） |

### A-2 输入控制链（点击 / 拖动 / 滚轮 / 按键 / 输入）

| 维度 | 内容 |
|---|---|
| 依赖 | ① 一套能注入鼠标/键盘事件的系统接口（事件注入）；② 辅助功能授权；③ **平台侧的门控面**（验身 → 白名单 → 审批卡 → 审计） |
| 今天能到哪一步 | 只到「通道存在」：系统自带的脚本通道 + 辅助功能授权即可发按键，**但没有门控面** |
| 缺什么 | 平台能力：**门控面**。具体 = ①执行器侧的验身与白名单（宿主目标在审批流之前被拒）②引擎侧的审批卡（显示动作、参数、红色横幅，写类逐条确认）③审计流（每个动作落一条不可篡改记录）④连续失败熔断 |
| 补齐判定 | 四件齐备，且「对宿主操作 100% 被拒」有回归基准 ⇒ **写类动作转为可适配**（届时本包补写类路径与逐工具 schema，参考 `tool-surface.md` §A 的 18 项 `t1_input`） |
| 未补齐时的正确行为 | 停手 + 报「需平台能力：桌面写类动作门控面未就绪」。🔴 **不得**用 Bash 手工拼等价的系统脚本调用绕过——那是绕过门控，不是适配 |

### A-3 权限申请面

| 维度 | 内容 |
|---|---|
| 依赖 | 系统授权（辅助功能 / 屏幕录制），**只能由使用者在系统设置完成** |
| 今天能到哪一步 | **完整可用（形态已换）**：引导卡（`AskUserQuestion`）+ 使用者手动授权 + 失败即收口 |
| 缺什么 | 无。平台事实：系统**不提供**第三方程序化授权通道，因此「工具内申请权限」这个形态在本平台不可能实现——不是没做，是**做不到** |
| 补齐判定 | 不适用（永久形态差异）。**判定线**：引导卡可发、授权后功能立即可用、失败时收口不重试 —— 三条成立即算适配完成 |
| 附注 | 引导纪律（只在失败点名时一次、`denied` 即终止、不主动预检触发系统弹窗）逐条写进 SKILL §2 |

### A-4 会话隔离面

| 维度 | 内容 |
|---|---|
| 依赖 | 「控制会话」对象：会话级放行、状态句柄、停止开关 |
| 今天能到哪一步 | **无会话对象**。平台节点是一次性的：无跨回合控制会话、无持久元素句柄 |
| 缺什么 | 平台能力：控制会话生命周期（会话级放行集、停止开关）。**注意这是与门控面同批的能力**，不是独立项 |
| 补齐判定 | 会话对象存在且隔离边界可核（会话间不串状态、会话结束即回收）⇒ 转为可适配 |
| 今天的替代语义 | ①「跨步不复用标识」（每个新步骤重新观测）②「停手即收口、不重试」= 无会话对象下的等价纪律（见 `tool-surface.md` §B-2） |
| 隔离增益 | 平台节点的**天然隔离**：一次任务一个会话、无长期常驻进程、结果沿边投递——今天已经是隔离形态，缺的是「会话内」的放行与停止粒度 |

## B · 暂缺项登记（缺什么 + 补齐判定）

| # | 暂缺项 | 缺什么 | 补齐判定（补到什么程度 ⇒ 转为可用） |
|---|---|---|---|
| B-1 | 桌面控制执行器（元素树读取 + 语义动作 + 事件注入） | 一个进程内执行器：它直接持有元素树与事件注入能力，且依赖一套**不可获取的私有运行库**与一个**宿主可执行文件**（二者是源件运行的前提，本平台取不到） | 自建等价执行器（平台侧新做，不是搬运）：具备元素树枚举/属性读/语义动作/事件注入四件，且能对「宿主目标」在动作前拒绝 ⇒ 转为可适配 |
| B-2 | 门控面四件（验身 / 白名单 / 审批卡 / 审计） | 见 A-2「缺什么」 | 四件齐备 + 宿主拒绝有回归基准 ⇒ 18 项 `t1_input` 写类工具转为可适配 |
| B-3 | 控制会话对象 | 见 A-4 | 会话生命周期 + 隔离边界可核 ⇒ 会话级语义（放行集/停止开关）转为可适配 |

| B-5 | 显示切换 | 系统自带命令行通道不存在 | 执行器落点（B-1）后随其暴露该能力，或明确裁定不在平台内提供 |

## C · 门控红线（不可协商，逐条）

1. **宿主永拒**：宿主进程、宿主应用窗口、本机服务端口监听进程——观测与动作都不许可，且在审批流之前拒绝。
2. **写类逐条确认**：不设会话级放行、不设「一次批准＝本任务通用」。
3. **检查类可自动，写类不可**：读操作按任务需要自动执行；写操作缺门控面就不执行（SKILL §4.2）。
4. **失败即收口**：连续 3 次失败熔断；权限拒绝即结束本回合。
5. **不抢焦点**：激活/抢焦点本身是 L2 级动作，需要理由，且不得用来「让别的动作成立」。
6. **不绕过**：不得用通用 shell 通道手搓等价调用规避上述任一条。

## D · 平台面收窄（macOS）

本包只面向 macOS 宿主面：辅助功能与屏幕录制两类授权、系统自带脚本与截图工具、应用启动器。源件覆盖的另一套桌面系统分支在本平台**没有宿主面**（本平台不提供桌面会话）⇒ **不带入、不假装支持**；若将来需要，属独立的宿主面设计，不再属本移植批次。

## E · 本波明确不做（与平台已裁口径一致）

- 桌面操控的**安全层**（四层防线 / 审计 / 熔断实现）——平台已裁为实现批内容，且「对宿主操作 100% 被拒」是其**合并前置**；
- 授权引导的实施（形态已就绪，实施依赖使用者授权，本波只交引导卡与纪律）；
- 与授权面相关的随包材料带入（B-7）。
