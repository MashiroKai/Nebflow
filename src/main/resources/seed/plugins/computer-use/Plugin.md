# computer-use — 插件使用指导（Plugin.md）

> 本文件是 computer-use 插件的**包根使用指导件**（Plugin.md）：**插件分配时注入给 agent 的提示词 = 本文件内容**（作者令 2026-10-21「plugin.md = 插件必要文件机制」批；SKILL.md 回归按需查阅件——面板胶囊点击打开，不再随分配整文注入）。选配判定仍看 plugin.json 的 description；逐 skill 作业指令见各 `skills/<skill>/SKILL.md`（按需查阅）。**本文件是导览不是手册：与 SKILL.md 不一致时以 SKILL.md 为准并回改本文。** 文内路径均为**自包根的文件相对形式**（不使用 `${SKILL_DIR}`）。

## 1. 速览

computer-use 是桌面观测与操控包：节点在 macOS 本机观测桌面（应用/窗口/屏幕截图/剪贴板）与操控桌面应用（打开/激活），按「观测一次—动作一次—复核」主循环与「引导 ＋ 收口」权限策略执行。内含 1 个 skill：

- `skills/computer-use/`——桌面观测与操控纪律：能力面真相表、主循环与定位纪律、权限引导卡、L1-L3 分级与 fail-closed 收口；携带观测脚本、自测脚本、权限卡体与 2 件 references。

**包纪律一句话**：写类动作（点击/按键/输入/抢焦点/剪贴板写）在其门控面就绪前一律不提供执行路径——停手并给出缺什么，比假装完成更有价值；宿主进程与宿主应用窗口永不可入观测面与动作面。

## 2. 安装与启用

- **安装**：本包属 Nebflow seed 官方分发，随实例 seed mirror 自动下发，无需手工安装。
- **启用/选配**：装载为「在位即生效」；分发器按 description 触发词选配（桌面自动化、操控鼠标键盘、点击与输入、程序化按键、屏幕截图、窗口与界面元素读取、剪贴板读写、本机 app 自动化、GUI 验收等），派发时把 SKILL.md 全文注入节点。
- **停用**：面板「更多 → 封禁该插件」/ `POST /api/plugins/computer-use/revoke` / `nebflow plugin revoke computer-use`。
- **内容变更**：包内任何字节改动都会漂移 digest，面板把该包标为「内容已变更」（可见性提示，不拦截装载）。

## 4. 主循环与权限导览（跨件速查）

> 全量口径以注入的 `skills/computer-use/SKILL.md` 为准；本节是速查与指针。

**主循环**：需要 UI 状态就先观测（不凭记忆猜）→ 一次只发一个动作 → 动作后重新观测复核（不凭返回码推断界面已变）；跨步不复用标识（窗口号/元素序号/坐标不搬到下一步）；桌面子任务不得委派（委派体拿不到守卫与停手条款）。

**权限（引导 ＋ 收口，不是申请 ＋ 重试）**：

- 两类授权：辅助功能（窗口清单、发按键）、屏幕录制（截图与任何屏幕像素读取）；授权只能由使用者在系统设置完成——平台不提供第三方程序化授权通道。
- 四条引导纪律：只在失败信息显式点名权限时引导一次；用 `assets/permission-card.json` 呈卡，不让使用者在纯文本里找答案；denied/已失效即结束本回合不重试；不为预检主动触发授权弹窗（就绪判断走脚本的被动探测）。

**分级与门控**：

| 级 | 面 | 门控 |
|---|---|---|
| L1 | 应用级（清单/打开应用/截图） | 检查类可自动；写类逐条确认 |
| L2 | 窗口级（窗口清单/抢焦点/切窗） | 逐条确认 |
| L3 | 桌面级（跨应用/显示切换/坐标级注入） | 逐条确认 ＋ 倒计时确认 |

- 检查类 vs 写类是分级之上更粗的一刀：读（清单/树/截图/剪贴板读）与写（点击/按键/输入/剪贴板写/抢焦点）——写类一律逐条确认，不设会话级放行。
- **写类动作的自动执行路径本包不提供**（承载它的平台门控面未就绪，见 §8 与 `references/host-dependencies.md`）；不要用等价手段绕过——那是绕过门控，不是适配。
- **宿主永拒**：宿主进程、宿主应用窗口、宿主服务端口的监听进程——观测与动作都不许可，机械拒绝发生在审批流之前（使用者不该看到一张可以伤害宿主的审批卡）。

**失败姿态（fail-closed）**：读不到就说读不到，不用默认值/旧读数补齐；「命令已下发」不可盲重放（要确认就重新观测）；错误原文带进结果；同一目标连续 3 次失败熔断停手。停手不是失败：如实收口比强行完成更有价值。

## 6. 选 skill 决策树

1. **目标是网页/浏览器页面** → 不进本包（浏览器页面操作由独立的浏览器操控插件面承担，另配 `browser-use`）。
2. **观测类**（应用清单/运行中应用/窗口/屏幕截图/剪贴板读/显示信息）→ `computer-use`（走脚本面或等价命令；截图有明确目的才截、落在临时目录用完即删；剪贴板不为探索而读）。
3. **动作类**：
   - 打开/激活应用 → `computer-use`（属写类：任务确实需要才做，不得用于「让别的动作成立」）；
   - 元素级/像素级写动作（点击/拖拽/滚轮/输入/按键写）→ 门控面未就绪，**停手登记**（给出缺什么），不绕过。
4. **出图与汇报**（把截图做成报告/图表）→ 另配 `visual-report`；本包只负责按纪律取证截图。

## 9. 维护约定

- **门控红线不放宽**：宿主永拒与「写类动作无自动执行路径」是本包的安全基线；平台门控面落地后按 host-dependencies.md 的补齐判定逐项迁出 §8，不得先斩后奏。
- **能力面真相表**：可用/暂缺状态以 SKILL.md 的能力面真相表为准；状态变化时同步该表、tool-surface.md 与本文件 §8。
- **本文件定位**：Plugin.md 是按需 Read 面——装载器不注入；SKILL.md 是注入面权威，两者不一致时以 SKILL.md 为准并回改本文。
