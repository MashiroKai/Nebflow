# design-spec — 插件使用指导（Plugin.md）

> 本文件是 design-spec 插件的**包根使用指导件**（Plugin.md）：**插件分配时注入给 agent 的提示词 = 本文件内容**（作者令 2026-10-21「plugin.md = 插件必要文件机制」批；SKILL.md 回归按需查阅件——面板胶囊点击打开，不再随分配整文注入）。选配判定仍看 plugin.json 的 description；逐 skill 作业指令见各 `skills/<skill>/SKILL.md`（按需查阅）。**本文件是导览不是手册：与 SKILL.md 不一致时以 SKILL.md 为准并回改本文。** 文内路径均为**自包根的文件相对形式**（不使用 `${SKILL_DIR}`）。

## 1. 速览

design-spec 是设计规格书方法包：节点获得「只设计不实现」的两端纪律——上游产出 UI/UX 设计规格书（检索成熟范式 → 写规格 → 冻结），下游做视觉评审（实现截图对照规格书逐项核对，PASS/FAIL 附证据）。内含 1 个 skill：

- `skills/design-spec/`——角色边界（设计/实现/QA 分工）、四道防线工作流（设计先行 → 规格化实现 → 双重验收 → 教训沉淀）、规格书模板 §0-9、权威范式检索源清单、PASS/FAIL 二值化硬约束。

**包纪律一句话**：只设计不写产品代码（写权限仅用于规格书/评审报告/案例库条目）；视觉评审绝不裸看图下结论——必须截图证据与 DOM 断言交叉验证。

## 2. 安装与启用

- **安装**：本包属 Nebflow seed 官方分发，随实例 seed mirror 自动下发，无需手工安装。
- **启用/选配**：装载为「在位即生效」；分发器按 description 触发词选配（写设计规格书、UI/UX 设计、视觉评审、设计走查、视觉规范制定等），派发时把 SKILL.md 全文注入节点。
- **停用**：面板「更多 → 封禁该插件」/ `POST /api/plugins/design-spec/revoke` / `nebflow plugin revoke design-spec`。
- **内容变更**：包内任何字节改动都会漂移 digest，面板把该包标为「内容已变更」（可见性提示，不拦截装载）。

## 4. 四道防线导览（跨环节速查）

> 全量口径以注入的 `skills/design-spec/SKILL.md` 为准；本节是流程速查。

| 防线 | 环节 | 本包职责 | 关键硬约束 |
|---|---|---|---|
| ① 设计先行 | 上游出规格书 | 检索 1-2 个权威范式提炼可执行规则 → 按模板 §0-9 写规格书 → 展示确认后**冻结**（状态字段 draft→frozen→dispatch→shipped） | 引用全部带链接可追溯；动笔前先读项目视觉铁律（见下「跨包配合」） |
| ② 规格化实现 | 中游 | 规格书是实现的唯一依据；未定义之处指示实现方回问，不自由发挥 | 设计方不碰实现 |
| ③ 双重验收 | 下游视觉评审 | 隔离实例截图（亮/暗主题、关键断点、关键状态）→ 对照规格书逐项核对 → PASS/FAIL 报告 | 截图证据 ＋ DOM 断言交叉验证；结论二值化附证据清单；不碰运行中的活实例 |
| ④ 教训沉淀 | 反馈环 | 被打回的 UI 归因四类（裁定冲突/缺参考/规格缺失/实现走样）入设计案例库 | 案例库条目下次设计必读 |

- **规格书模板 §0-9**：一句话目标 / 参考与依据 / 布局与信息架构 / 交互状态机表 / 动效规范 / 视觉规格（全 token 引用）/ 边界与异常 / 无障碍 / 可断言验收点（≥5 条二值判断，供 QA 转自动化断言）/ 参考链接。
- **检索源与冲突取舍**：权威检索源清单（平台 HIG、成熟产品范式、组件库模式、动效参考）与范式冲突时的取舍口径，全量以 SKILL.md 检索源节为准；冲突时以项目视觉铁律与用户 taste 为准，规格书写明取舍理由。
- **跨包配合（按名引用，注入后自行 Read）**：视觉铁律 `visual-style` 与设计案例库 `design-system`（`nebflow-frontend-dev` 插件）、HTML 卡片规范 `card-design`（`design-cards` 插件）。本包不含视觉规则与案例库本体；`${SKILL_DIR}` 不跨包，正文不写跨包相对路径。

## 6. 选 skill 决策树

- 前端 UI 任务的**上游**（新 UI/交互——弹窗、搜索、列表、面板、动效等——要出设计规格书）→ `design-spec`（防线①）。
- 前端 UI 任务的**下游**（实现完成要视觉验收/设计走查）→ `design-spec`（防线③）。
- 要**直接写前端实现代码** → 不进本包：另配 `nebflow-frontend-dev`。
- 要**产出 HTML 卡片/社交图** → 另配 `design-cards`；图表可视化另配 `visual-report`。
- **功能验收的执行**（冒烟/契约/资源/DOM 断言的自动化）→ 不进本包：QA 域承担；本包只负责在规格书 §8 定义可断言点。
