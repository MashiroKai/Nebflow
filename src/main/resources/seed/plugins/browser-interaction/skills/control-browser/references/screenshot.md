# 截图纪律与取证落盘（screenshot）

截图是**昂贵**的证据通道：先问「结构读取能不能回答这个问题」，答案能 ⇒ 别拍。

## 一、什么时候才拍

满足任一条才拍：

1. 用户明确要求截图 / 要求做视觉测试；
2. 需要判断**视觉**事实：布局、样式、渲染、配色、字体、间距、遮挡；
3. 目标不在**结构观测**里（画布 / 自绘 / 非 DOM 控件），需要瞄准坐标；
4. 需要记录一个**瞬时态**（toast / 加载 / 动画）或页面错误表现。

普通打开或导航一个正常页面**本身不是**截图的理由。
**默认不要**在同一轮里既取结构观测又拍截图。

## 二、必须落盘，且必须读回

```js
import { resolve } from 'node:path';
const path = resolve(outDir, 't3_after.png');   // 命名带测试点编号
await page.screenshot({ path });                 // 全页：{ fullPage: true }
console.log(JSON.stringify({ shot: path }));     // 把绝对路径打出来
```

- 截图**不落盘** = 不是证据（进程退出即消失，报告里引不到）。
- 落盘后**必须用 `Read` 读该图片文件**，视觉验证才算完成。**拍了不看 ≠ 观测。**
- 报告里引用**绝对路径**或其 `file://` URI。载体只返回图片、没暴露路径 ⇒
  以已查看的图作证据，并如实写「未暴露持久路径」——**不要编造路径**。

## 三、常用选项

- `{ fullPage: true }` —— 整页（长页面、溢出/截断类问题用）。
- `{ clip: { x, y, width, height } }` —— 只截一块区域。
- 元素级截图：`await locator.screenshot({ path })` —— 只截该元素（对齐/间距类问题最干净）。

## 四、瞬时态：同一脚本内前后两张

Toast / tooltip / 加载指示 / 动画会在你拍之前消失。要抓到它们，在**同一个脚本内连续**做完：

1. 拍「前」；
2. 执行动作；
3. 等目标状态出现（**优先等具体条件**，固定延时只作兜底）；
4. 拍「后」。

然后**两张都要读**。普通静态内容不需要这套，一张常规截图即可 —— 但**仍必须拍、仍必须读**。

## 五、截图超时

截图超时后**不要**立刻重发同一条截图命令：底层截图可能仍在进行。
先等待，或按明确的「进行中」错误提示处理；错误不清再重试一次。
