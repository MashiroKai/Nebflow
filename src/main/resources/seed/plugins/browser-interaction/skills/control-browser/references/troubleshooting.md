# 失败排查与恢复（troubleshooting）

先一条总则：**先用载体文档化的能力解释和解决，不要因为一次交互失败就去翻实现源码或换控制机制。**

## 一、页面句柄过期 / 不存在 / 已关闭

一个过期或已关闭的页面句柄、空页面列表、或某个辅助模块不可用，
**都不证明浏览器断开了**。恢复路径：

1. 重新列出现有页面（`context.pages()`）并**把完整列表打出来**给下一轮用；
2. 下一轮里按**已验证的** URL/标题匹配目标，再取句柄；
3. 两个来源都找不到该页 ⇒ 才新建页面。

**不要**因为脚本变量没了就以为浏览器没了，也不要凭记忆把页签 id 当目标直接使用。

## 二、动作没生效（最容易被误判的一类）

判断顺序：

1. 看**期望效果**是否出现 —— 不看「有没有报错」、不看「列表是不是非空」。
   原页面的 URL 没变**不等于**点击失败。
2. 期望效果可能在**别处**出现（popup 弹出的新页 / 新状态）⇒ **同一轮**把两个来源都读出来
   （同一脚本内 `context.pages()` 的页面清单（含 popup 新页）+ 目标页自身的状态查询），
   一次决策，而不是先看一个再决定要不要看另一个。
3. 两个来源都没有期望效果 ⇒ 重新观测、换依据，**不要**重放上一次点击。

## 三、定位失败

- 超时 / 严格模式冲突 / 选择器解析失败 ⇒ 重新观测，从新事实重建定位器，并先确认
  `count()` / `isVisible()` 再动作。
- **不要**重试同一个定位器；**不要**猜一个不存在的 role/name/placeholder；
  **不要**用 `first()` / `last()` / `nth()` 掩盖歧义。
- 同一目标连续两次失败 ⇒ 换到最强稳定属性或限定作用域的坐标路径（见 `safety.md`）。

## 四、页面加载失败

超时 / 白屏 / 报错 ⇒ 截图记录当前状态，报出**确切错误**，跳过依赖该页的后续测试点。
**不要**用刷新、前进后退、改窗口大小逃出失败态；也不要换别的手段把流程推过去。

## 五、载体层面不可用

- Node / Playwright / 浏览器缺失 ⇒ **停下**，报确切的安装或加载错误。
- 某个能力没被暴露（如某类事件、某种传输）⇒ 用当前能力面里**实际存在**的替代手段；
  没有替代 ⇒ 如实记「本载体不支持」，**永不伪造成功**。
- 只有明确的「浏览器已断开」错误才需要重新选浏览器并重新读一次其能力说明。

## 六、失败报告的最小信息量

停手时报错必须带：**哪一步**（第几步/哪个测试点）、**期望什么**、**实际得到什么**（错误类型 + 实际值）、
**此前做过什么**、**你判断的成因范围**。只写「失败了」等于没报。
