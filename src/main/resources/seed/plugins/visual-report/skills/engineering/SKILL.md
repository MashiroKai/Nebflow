# engineering — 工程测试报告 skill

visual-report 插件场景之一：把测试 / 实验 / 性能验证结果写成**图真、数准、可判定**的工程报告。公共规范（铁律 / 嵌入路径 / dark-mode / marked v12 兼容 / 降级总则 / 自检模板）一律见 `${SKILL_DIR}/../core/SKILL.md`，本文只写场景增量，禁止复制漂移；工具链接验证总表见 `${SKILL_DIR}/../README.md`。

## 1. 触发条件

任务命中任一即用本场景：

| 类型 | 典型输入 | 典型产出 |
|---|---|---|
| 测试报告 | 单元/集成/系统测试、回归测试、出厂检验（FCT）、可靠性试验（高低温/老化/振动） | 骨架化报告 + 结果图 + 指标判定表 |
| 实验报告 | 电路调试、示波器/频谱仪采集、原型验证（EVT/DVT/PVT）、DOE 对比 | 同上 |
| 性能验证报告 | 指标验证（增益/带宽/噪声/功耗/精度/温漂等）、基准比对、验收测试（SAT/FAT） | 同上 + 逐条通过/不通过结论 |

不命中转对应场景：论文插图 → academic-research；架构/框图 → tech-architecture；仿真波形/PCB → eda；数字时序 → timing；课件汇报 → office / education。

## 2. 报告骨架模板（五节，顺序固定）

```markdown
## 目的
（一段：被测对象 DUT、验证目的、判据来源与版本号）

## 条件与方法
（环境温湿度 / 供电条件 / 仪器型号与精度 / 样本量 n / 方法步骤或引用编号 / 数据口径：实测·拟合·引用）

## 结果图表
（≤3 图，取舍规则见 core §1.3；每图下配一句图注：口径 + 关键条件）

## 指标表
（四列表，填写规范见本文 §3）

## 结论
（逐条判定汇总；不通过项写复测/让步/拦截动作；遗留风险与后续计划）
```

要点：

- 「条件与方法」缺一不可——没有样本量与条件的报告按 §4 红线返工。
- 图表嵌入一律 `![标题](~/.nebflow/plots/....svg)`，路径与白名单见 core §2；默认出图落 `~/.nebflow/plots/`。
- 空节不得删除：没有数据的节写「无数据 + 原因」，保持五节完整。

### 指标表规范（四列，缺一即返工）

| 指标 | 实测 | 判据 | 结论 |
|---|---|---|---|
| 量名 + 单位 + 条件（如「-3 dB 带宽」） | 数据源逐字值 + 单位；多值写区间；标注口径（实测/拟合） | 数值 + 单位 + 出处（规格书章节/验收标准号）；判据先于测试确定 | 通过 / 不通过 / 让步接收；不通过必须带动作行 |

- 判据禁用「正常」「良好」等不可复核词。
- 实测列与图内标注、正文数值同源同值同格式（core §1.2 数值逐字红线）。
- GFM 分隔行列数必须等于表头列数，否则 marked v12 整表渲染失败（core §4）。

### 降级策略

优先级：换已有工具 > 纯文本降级，禁止因缺工具空转、禁止手画 SVG（core §5）：

- matplotlib 不可用 → plotly（viz-venv 已装）→ 纯表格 + 文字描述；
- scipy 缺失 → numpy 多项式拟合替代；
- 图无法生成时，指标表 + 逐条文字结论仍必须完整交付——纯表格不空转。

## 4. 质量红线（违反即返工）

1. **测试数值逐字**：表格、图内标注、正文三处同值同格式；不修约、不写「约」、不脑补缺失值、不改口径；源里没有的数不画不写（core §1.2）。
2. **坐标轴与单位齐全**：每条轴有物理量名 + 单位（如 `频率 (Hz)`、`增益 (dB)`）；单位写在轴标签，不在刻度数字后重复。
3. **样本量与条件写明**：n、温度范围、供电、仪器/方法精度在「条件与方法」与图注中可追溯。
4. **禁止美化掩盖离群点**：离群点如实画出并标注（数值 + 条件）；不删点、不平滑抹峰、不截断坐标轴制造假差异、不换口径让判据「刚好通过」。
5. **图必须真实渲染**：一切图由专业工具生成落盘（core §1.1 铁律）；禁止占位图、禁止把表格截图冒充结果图、禁止用示意图冒充实测数据；演示/合成数据必须在图题与正文显著声明。
6. **单文档 ≤3 图**（core §1.3）：超限按权重取舍并在首屏声明「图预算超限」。
