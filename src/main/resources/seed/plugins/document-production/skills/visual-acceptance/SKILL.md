# Visual Acceptance — 成稿页级视觉验收

用途：交付件已渲染成页面图之后，**逐页**判定「用户会不会看出问题」。判据是用户验收线，不是代码规范线——程序化自检跑绿**不能**替代这一遍。

**边界**：本 skill 只判**已渲染页面**的观感与内容一致性，不改稿、不重渲染、不修代码；代码与契约层审查归 `nebflow-qa` 插件，出图工具链归 `visual-report` 插件。

## 一、前置：先把成稿渲染成页面图

被判对象必须是**页面图**（每页一张 PNG），不是源文件。流程：

1. 用本包的脚本或 `soffice` / `pdftoppm` 把成稿导出为逐页 PNG，落在临时目录。
2. 用 Read 逐张读图（Read 把图片按视觉输入返回）。
3. 逐张读完即写该页判据，不要攒到最后一起写。

🔴 **禁**把 pptx / docx / html / pdf 原件当图片读——那不算验收。🔴 **禁**在正式验收前先"随便看一眼"：预习一遍再正式判 = 同一遍复核做两次，白烧一轮渲染。

## 二、每页判三项（逐页都要过）

1. **视觉资产** —— 每张图/表/图标是否切题、正确、比例自然：无拉伸压扁变形、无破坏性裁切；图表必须**恰好**支持周围文字的主张（图型对、数值对、没有编造），且画得干净——清晰、无截断（轴/图例/标签）、无水印、无粗糙拼凑。风格化处理是设计选择，不算缺陷。
2. **版式与构图** —— 这一页看起来像成品：报告**全部**下列情形——模块互相压盖、内容堆叠或被遮、元素溢出页面或溢出自身容器、模块挤在一起、明显失衡（视觉重心偏、一侧过载另一侧空）。
3. **内容一致性** —— 可读性：无乱码、公式渲染正常、无截断；与用户诉求和参考件一致；严谨域（法律、财务、学术）从严；**给了参考件时，具体数字必须回溯核对来源**。

## 三、按格式的专题重点

- **演示（pptx）** —— 按放映距离判：每页要一眼落定；盯文字与卡片/形状碰撞、卡片或容器半边空（那也是分布不均）、投屏后读不清的图表标签、跨页一致性（页码、页眉、配色）。
- **文档（docx）** —— 按阅读距离判：盯分页事故（近空白页、标题孤行在页底、框线跨页断开）、无页码的目录条目、渲染成空白的图、页眉/页脚/页码跨节连续性。
- **表格（xlsx）** —— 判渲染出的工作表视图：盯列宽不足显示成 `####`、可见错误值、图表类型或标签误导数据、宽表被打印分页切开、仪表盘整体是否成立。
- **PDF** —— 盯内容挤压或越出页边距、多栏版式断流、坏分页（标题或图注落单）、海报与封面的第一眼观感。

## 四、判据与输出

- **只报能说出具体问题的项**，并点名它。
- **一个问题、一个分类、一条记录**：同一根因在一页上带出多个症状时，按主导分类报一次。图/表/图标**内部**的问题归 `Visual`；页面上**元素之间**的问题归 `Design`；**读不通**的文本归 `Content`；违反给定条目归 `Spec`（引用原条目；没给条目就**不得**发明约束）。
- **证据必须具体**：写你看到的，或引原文。禁编造像素值、禁泛泛的美化建议。
- **无法确认** ⇒ 标 `Unverified`，不要猜。
- 输出：**每页一行 JSON，按页码顺序**，通过与不通过都要出。不写散文、不写额外说明。

```
{"page": 3, "verdict": "pass"}
{"page": 4, "verdict": "fail", "issues": [{"category": "Content", "problem": "营收数字与来源矛盾", "evidence": "本页写 ¥12.4亿，参考件 report.pdf 第 5 页为 ¥21.4亿"}]}
```

`category` ∈ `Spec | Content | Visual | Design | Unverified`；任一判据不满足 ⇒ `fail`；无法确认 ⇒ `Unverified`。

## 五、打回后怎么办

判 `fail` 的页修完**重渲染该页**再判一次；判 `pass` 的页不重复渲染。整份交付件的验收结论 = 全部被判页的最终判据，别把「脚本检查通过」当封面。
