# 页面与上下文的生命周期纪律（page lifecycle）

一次调用一个进程的形态下，**句柄不跨调用存活**，但页面/上下文的**存在性**由当前脚本进程持有。
纪律分两层。

## 一、句柄层：不跨调用复用

- 上一轮脚本里的 `page` / `locator` 变量，下一轮**不存在**。
- 每轮开头的动作固定为：重新打开浏览器 → 重新建立上下文 → **重新列出现有页面** →
  按已验证的 URL/标题匹配目标 → 取句柄。
- **不要**凭记忆把某个页签 id 当目标直接用：先列出来，看到事实，再匹配。

## 二、存在层：只关你有意关的

- 页面默认**保持打开**，不因为「这一轮结束了」就关掉。
  完成一个操作批次不等于可以关页面——后续步骤可能还要它。
- 显式 `page.close()` 只在你**有意**关闭那个确切的页面时调用。
- 上下文（`context`）同理：`await context.close()` / `await browser.close()` 是**收尾动作**，
  在脚本即将退出、且确认没有后续步骤需要它时才做。
- **本载体看不到别人的浏览器**：`context` 由本脚本创建（`context.pages()` 就是全部可见页面），
  因此**不存在「用户自己开的页面」**——清单里的每一页都来自本脚本或它打开的 popup，都归你管；
  跨调用要续用某个已经打开的目标时，按已验证的 URL/标题匹配到它再操作。

## 三、收尾三问

脚本退出前问自己：

1. 还有后续步骤需要这个页面吗？需要 ⇒ 别关（或把被测服务留给下一步，把浏览器留给这一步）。
2. 这个浏览器是我这个脚本起的吗？是 ⇒ 关掉它，别留孤儿进程。
3. 我起的被测服务呢？⇒ `trap EXIT` 自清，并给**清理后现读**。

## 四、常见错误

| 错误 | 后果 |
|---|---|
| 每轮脚本结束就 `browser.close()`，下一步又指望页面还在 | 状态丢失，测试点间无法连续 |
| 把上一轮的页签 id 当目标直接用 | 指向错误页面，判断全错 |
| 用新开一个页面「重来一遍」代替排查失败 | 掩盖真实缺陷，结论不可信 |
| 忘记关自己起的浏览器/服务 | 进程残留（判为不合格） |
