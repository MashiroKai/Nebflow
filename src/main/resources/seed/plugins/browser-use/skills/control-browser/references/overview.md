# 载体现状与可用面（overview）

## 一、本平台里「浏览器」到底是什么

没有常驻的浏览器服务，也没有内置的浏览器工具。交互式网页工作在**本平台是这么落地的**：

```
节点会话
 ├─ Bash ──▶ node <脚本.mjs> ──▶ Playwright ──▶ chromium（真实浏览器）
 │                                  │
 │                                  ├─ 结构读取：DOM / 可访问树 / locator 查询
 │                                  ├─ 交互：click / fill / press / selectOption / scroll
 │                                  └─ 截图：page.screenshot({ path: <绝对路径> })
 └─ Read ──▶ 读回截图文件（唯一的视觉通道）
```

三个事实决定了纪律的形状：

1. **每次调用是一个新进程**：脚本里的变量、页面句柄、登录态都不跨调用存活。
   ⇒ 连续性是**页面/上下文本身**，不是脚本变量。每轮重新建立、每轮重新从**当前事实**取目标。
2. **浏览器在脚本进程内**：脚本退出 ⇒ 它开的浏览器就没了（除非你把服务/上下文留给别的进程，别这么做）。
   所以要长期存在的被测服务与一次性驱动脚本**分开**：服务由包装器起、驱动脚本短命前台跑。
3. **视觉只有一条通道**：截图落盘 → 用 `Read` 读该文件。
   **图不落盘不成证据；落了盘不读也不算看过。**

## 二、可用面 / 不可用面（硬边界）

| 面 | 状态 | 说明 |
|---|---|---|
| 打开/导航页面 | ✅ | `page.goto(url)` + 显式确认加载状态 |
| 结构化读页面 | ✅ | DOM / 可访问树 / locator 的 `textContent`、`getAttribute`、`isVisible` 等 |
| 交互（点击/输入/选择/滚动/键盘） | ✅ | locator 终态方法；坐标路径留给观测读不到的目标 |
| 截图取证 | ✅ | 落盘 + `Read` 读图 |
| 视口/响应式 | ✅ | `page.setViewportSize` |
| 控制台错误采集 | ✅ | `page.on('console')` / `page.on('pageerror')`（只读） |
| 只读取页面正文（不需要交互） | ✅（另一种载体） | 内置 `WebFetch`；比开浏览器便宜得多。**反爬 / JS 挑战页**靠它的**分层回退链**（第 1 层 HTTP 直取 → 第 2 层浏览器回退：Obscura → Playwright）；**本机现读：回退层不可用** —— `command -v obscura` rc=1（未安装）+ JVM 侧 Playwright 仅标 `provided`（`build.sbt:64`，不进发行包，运行期按 classpath 探测）⇒ 实际只剩第 1 层（HTTP 直取）可用；挑战页取不到正文 ⇒ 按 `SKILL.md` §五 如实记为**能力缺口**，不要改用别的手段凑结果 |
| 外域站点的**交互式**操作 | ⛔ 暂缺 | 缺容器级隔离面；见 `deferred-capabilities.md` |
| 浏览器与页面内容的**容器隔离** | ⛔ 暂缺 | 同上 |
| 浏览器服务的**常驻**与跨调用复用 | ⛔ 暂缺 | 无 MCP browser server 装载面 |

## 三、判定顺序（每次开工先走一遍）

1. 这次要的是**正文**还是**交互/视觉**？只要正文 ⇒ `WebFetch`，别开浏览器。
2. 要交互或要图 ⇒ 走 Playwright 脚本，并先做开工前自检（`SKILL.md` §七）。
3. 目标是**本地/自有**（localhost、127.0.0.1、你自己起的静态服务、仓库内页面）还是**外域**？
   外域的**交互式**操作 ⇒ 记「暂不可用」，不要用宿主直连凑结果。
4. 需要视觉证据 ⇒ 截图必须落盘并读回。

## 四、与相邻能力的分工

| 需求 | 归属 |
|---|---|
| 关键字检索线索 | 内置 `WebSearch` |
| 某 URL 的正文（只读） | 内置 `WebFetch` |
| 原始 HTTP 请求/响应（自定义头、方法） | 内置 `Curl` |
| 打开页面并与之交互、截图、验收 | 本 skill（Playwright 脚本） |
| 把浏览器流程**委派**给别的会话/子会话 | **不行**：委派体拿不到本 skill（注入面只到被挂载的会话）与你的脚本进程 ⇒ 证据链断裂，见 `SKILL.md` §二 |
| 出自图/图表/汇报件 | 另配可视化汇报类插件，不要在这里做 |
| 仓库内检索 | `Grep` / `Glob`，不联网 |

边界一句话：**交互归这里，检索归检索工具，只读正文归抓取工具，出图归出图插件。**
