# 视口 / 响应式与设备尺寸自测（viewport）

## 一、什么时候才动视口

**只有**测试点明确要求响应式或设备尺寸验证时才调整；其余情况保持默认视口。

用视口调整去做「让内容能显示出来」是**逃出失败态**——那是禁止的。
测试点结束后把视口恢复原值。

## 二、怎么定

```js
await page.setViewportSize({ width: 375, height: 812 });   // 设备尺寸
const size = page.viewportSize();
console.log(JSON.stringify(size));
```

- 宽高是 **CSS 像素**。
- 尺寸要在**页面打开前**通过 `newContext({ viewport })` 定，或打开后用 `setViewportSize` 改；
  两种方式都可，但**同一测试点内保持一致**并在报告里写明用了哪个尺寸。

## 三、常用尺寸档（按需启用，不要默认全跑）

| 档 | 尺寸 | 用途 |
|---|---|---|
| 桌面默认 | 1280×800 | 常规功能与布局验收的默认档 |
| 桌面宽 | 1920×1080 | 大屏布局一致性 |
| 平板 | 768×1024 | 断点附近 |
| 手机 | 375×812 | 窄屏溢出/换行/触控目标大小 |

## 四、纪律

- **一个测试点固定一个视口**；报告中每个测试点标注其所用视口。
- 视口变化会让此前取得的**定位依据与截图全部过期** ⇒ 换视口后重新观测，别复用旧定位器。
- 视口截图就是该视口的真实渲染 —— 不要用缩放/裁剪去伪造一个尺寸下的效果。
- 不要用改窗口大小绕过失败的交互（同 `web-gui-tester` 的禁止项）。
