## 1. 渐进式披露（progressive disclosure）

### 1.1 定义

**默认只给「当下要做判断」所需的摘要与入口；次要、高级、危险的内容折叠一层或进次级页；
被收起来的东西必须在摘要上留下可见的状态、计数与错误。**

作者给的正面判据是一句反问：**一个日常用户进来，第一屏能不能只做他今天要做的那件事？**

### 1.2 判定问句（逐条可答；任一条答「否」即不合）

| # | 判定问句 | 不合时怎么改 |
|---|---|---|
| Q1 | 第一屏是否只出现**默认路径**要用的控件，其余（高级 / 危险 / 低频）都在折叠层或次级页？ | 把该块包进折叠区或挪进次级页；不是删功能 |
| Q2 | 每个折叠层在**收起状态**下是否仍显示摘要（计数 / 当前值 / 错误）？ | 收起 ≠ 藏起：摘要行必须留下「有几项 / 当前是什么 / 有没有错」 |
| Q3 | 同一屏里是否存在**两个及以上同等权重**的可编辑明细区同时铺开？ | 保留一个，其余折叠（同等权重 = 都是可编辑明细，没有主次） |
| Q4 | 危险 / 破坏性动作是否与常规动作**同屏同权重**并排？ | 收起进次级页，或降为 ghost + 二次确认 |
| Q5 | 折叠层展开后，是否**仍能回到摘要**（同一入口可收）？ | 展开控件必须是可切换的按钮（`aria-expanded`），不是一次性展开 |
| Q6 | 被折叠的默认展开状态是否**只在无用户意图时**成立（新开 = 全收；返回 = 保留）？ | 新开会话默认全收；同会话内返回保留展开状态 |

## 3. 无重复判据（同一功能 / 同一信息 / 同一栏目名只允许一份）

### 3.1 四层拆解（每一层的判据都不相同，别混着说）

| 层 | 规则 | 机检 | 说明 |
|---|---|---|---|
| **U1 栏目名唯一** | 同一容器内，同一**文案键**不得占据 ≥2 个标题槽 | ✅ §3.2 表 1 | 作者点名的「高级 高级」「关于 关于」即此类 |
| **U2 信息唯一** | 同一「信息组」（同一份身份/读数）在同一页面面内只允许有 1 个渲染点 | ✅ §3.2 表 2 | 作者点名的「底部的账户栏 信息重复」即此类 |
| **U2b 信息不重复（设计期要求）** | 同一信息在同一界面 / 卡片内只出现一次；**摘要区与全文区不得重复展示同一事实**；摘要只留**类型标记 + 一句话要点** | 部分（§3.5；机检只覆盖登记面） | 作者令 2026-11-21 10:18「把设计时 信息不重复写进设计文档要求」——设计期就按此写，不等闸抓 |
| **U3 功能唯一** | 同一动作在同一容器内只允许有 1 个入口（返回键在场就不放叉号键） | 人工（判据见下） | 面板族已有作者裁定，见 `panel-spec.md` 引言 (d) |
| **U4 文案键唯一** | 同一句话只允许挂 1 个键；两个键同值 ⇒ 至少一个应改成引用或删除 | 人工（存量 205 组，见 §3.4） | 不做机检的原因见 §3.4 |
| **U5 规范正文唯一** | 同一判据只允许有一份正文，其余处只放指针 | 人工 | 本文 §0 的表就是这条纪律自己的落点 |
| **U6 组件来源唯一** | 同一控件只允许有一份实现（按钮 = `flat-button-spec.md` §5） | ✅ `scripts/check-button-source.mjs` | 指向，不在此展开 |

**U3 的人工判据**（一句话可判）：*把其中一个入口删掉，功能还能不能到达？* 能 ⇒ 它是重复
入口，删；不能 ⇒ 保留。反例形态：顶部返回键 + 同处叉号键；「保存」按钮 + 「确定要保存吗」
二次按钮；同一动作在 header 与 footer 各一份。

### 3.4 U4（文案键唯一）为什么不做机检

实测：`zh-CN.js` 有 205 组「同一文案值挂在 ≥2 个键上」（`en.js` 191 组），其中绝大多数是
**合法的跨面同值**——「保存 / 取消 / 重试 / 关闭」在几十个面板里各是一个键，这是正确的
（同一句在不同语境要能独立改）。**值相同 ≠ 同页重复**；真正的判据是「同一屏出现两次」，
那需要渲染事实（DOM），不是词表能判的。

所以 U4 只做两件事：
1. **人工评审项**（每批新文案过一遍：同值两键中，是否至少一个该改成引用/删除）；
2. **机检代理**（`check-copy-budget.mjs` 的重复报告模式）只列清单供人判，**不判红**。

### 3.5 U2b · 信息不重复（设计期要求，作者令 2026-11-21）

> 作者令（2026-11-21 10:18，逐字）：「把设计时 信息不重复写进设计文档要求」
> ——语境 = 权限卡瘦身；适用面 = **通用化的面板信息设计要求**，不限该卡。

这一条是**设计期纪律**，不是事后评审：写界面时按它排信息，不等闸抓、不等作者看图。
它与 U2 的分工是——U2 判「同一份读数在同页渲染了几次」（渲染点计数，机检），U2b 判
「同一事实在一张卡/一个界面里重复说了几次，尤其摘要区与全文区」（设计判断，人工 + 部分机检）。

**规则（三段，逐段可判）：**

1. **同一信息在同一界面 / 同一卡片内只出现一次。** 一处是权威位，其余处若仍需指向，
   写成指针（一行入口 / 一个 chevron / 一个计数），不重写事实本身。
2. **摘要区与全文区不得重复展示同一事实。** 摘要存在的意义 = 让用户判断「要不要展开」，
   不是把展开后的内容提前念一遍。摘要**只留类型标记 + 一句话要点**（是什么 + 关键状态，
   如「GitHub 绑定：已绑定 @x」）；完整读数、逐字段明细、原始值时只出现在展开区。
3. **重复的判定看「事实」不看「文案」。** 同一事实换一种说法再说一遍仍是重复
   （「已登录」 vs 「当前账号：kaiyu」在同卡内即重复）；反过来，同一句文案在两个不同语境
   各出现一次不算重复（见 §3.4）。

**设计期自检问句（一处一判，答「是」即改）：**

| # | 问句 | 典型改法 |
|---|---|---|
| D1 | 卡头摘要里的每个事实，是否在卡内明细里**又出现一次**？ | 摘要只留类型标记 + 一句话要点，明细承接原文 |
| D2 | 同一事实是否在**两个容器**（卡 / 分组 / 折叠层 / 底部栏）各有一份？ | 留一个权威位，另一处降级为指针 |
| D3 | 一处读数能否**只从另一处推导**（如卡头状态 = 明细里某字段的值）？ | 推导出来的不重写，改为状态派生或直接省略 |
| D4 | 卡片内的「标题 / 副标题 / 状态 / 说明」是否在说同一件事？ | 四者合并到一个槽位（标题承载身份，副标题承载唯一区分事实） |
| D5 | 折叠层**收起**时的摘要，与**展开**后的首行是否同一句话？ | 收起的摘要写「有几项 / 有没有错」，展开后写具体值——两者不同层 |

**机检覆盖现状（诚实口径）：**

- **已覆盖**：同一份「信息组」在同页的渲染点计数（§3.2 表 2，U2）——「两个容器各一份」
  这类硬重复（D2）落在它的口径内，前提是该面已登记；未登记的面 = 未受约束（同 §3.2 尾注）。
- **未覆盖（检查项缺口）**：**摘要区 vs 全文区的重复**（D1/D5）——它需要「哪块是摘要、
  哪块是全文」的语义标注，静态源码判不出；「一处读数是否可由另一处推导」（D3）同理。
  这两类目前只能靠人工评审（§4 表）与设计期自检（上表）挡住。
- 因此本条的效力**主要来自设计期纪律**：写面时按上表走一遍，比事后被闸红或被作者点名便宜。

## 4. 人工评审项与待建渲染腿（诚实边界）

| 判据 | 现状 | 为什么不能静态判 |
|---|---|---|
| U3 功能唯一 | 人工（判据已给，可复现） | 「两个按钮是不是同一动作」要看行为绑定，不在文案/结构里 |
| U4 文案键唯一 | 人工 + 清单 | 见 §3.4 |
| **U2b 摘要区 / 全文区不得重复同一事实** | 人工（§3.5 的 D1/D5 自检问句） | 「哪块是摘要、哪块是全文」是语义标注，静态源码判不出；需下方同一渲染腿 |
| 同一可见文案不得同屏出现两次 | **待建渲染腿**（Playwright：打开设置页 / 我的页，收集可见文本节点，断言同容器内无重复值） | 需要真机跑起来的实例与 DOM，静态源码判不出「同屏」 |
| 首屏可见说明性文字 ≤ 1 条（同一面） | **待建渲染腿**（与上条同一 spec） | 同上 |
| 折叠层收起态必须有摘要 | 人工（Q2 逐条走查 + 截图） | 摘要是否「仍在场」是渲染与可访问性事实 |

> 待建渲染腿的落点已定：`tests/ui-dedup.spec.mjs`（frontend profile）。**本轮只交付静态闸
> 与人工判据**：不建需要实例的测试，避免在门禁链里留一条跑不动的红。

## 5. 与门禁的关系

```bash
node scripts/check-ui-structure.mjs            # 本文件 §2/§3 的判据（红/绿）
node scripts/check-ui-structure.mjs --json     # 机器读
node scripts/check-ui-structure.mjs --list      # 只列命中（不做基线比较）
node scripts/check-ui-structure.mjs --update-baseline  # 重锚存量（只许在「确实把命中降下来」时用）
```

存量记在 `scripts/ui-structure-baseline.json`：**只许降不许升**；加一条 = 声称「这条重复是
对的」，必须在批报告里点名理由。判据口径变更顺序：**本文 → 脚本 → 重锚基线**,顺序反了就是
放水。
