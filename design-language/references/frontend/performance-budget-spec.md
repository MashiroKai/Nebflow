## 1. 网络红线（PERF-NET-*）

**一句话：任何一次网络读取都必须有**体积上限 + 分页 + 压缩**，任何**轮询**都必须有
频率与 payload 上限 —— 不许「一次拉全量、定时拉全量」。**

| id | 要求 | 阈值位 | 判据形态（回填后成闸） |
|---|---|---|---|
| `PERF-NET-001` | 列表型读接口**必须分页**：服务端强制 `limit`（缺省上限由阈值位定），禁无上限全量返回 | 单页条目上限 = **由 perf-fixes 批回填** | 静态：路由处理器必须读 `limit`/`offset` 且有缺省上限；缺省上限字面量 = 数字（禁 `Int.MaxValue` 式「假分页」） |
| `PERF-NET-002` | 单接口响应体**有体积预算**：超预算必须改成分页 / 摘要 + 详情腿，不许一个响应带整棵树 | 单响应 gzip 上限 = **由 perf-fixes 批回填** | 静态：登记表逐路由给预算；渲染腿：诊断批读数超预算即红 |
| `PERF-NET-003` | 文本型响应**必须压缩**（gzip/br），压缩后体积才是预算口径 | 压缩开关 + 最小压缩体积 = **由 perf-fixes 批回填** | 静态：服务端压缩中间件在场且未对小响应设荒谬阈值 |
| `PERF-NET-004` | **轮询有频率上限**：任何 `setInterval`/定时轮询必须具名登记周期，禁「1s 级全量轮询」；能推送就不轮询 | 周期下限 = **由 perf-fixes 批回填** | 静态：轮询点登记表（§5 表 4）逐行核周期常量；未登记 = 红 |
| `PERF-NET-005` | 轮询 **payload 有上限**：轮询只取增量/摘要，禁每次拿全量再 diff | 单次轮询响应上限 = **由 perf-fixes 批回填** | 渲染/网络腿读数 |
| `PERF-NET-006` | 失败不得变成**紧循环**：429/5xx 必须退避（指数或固定下界），禁立即重试 | 退避下界 = **由 perf-fixes 批回填** | 静态：退避实现在场；行为腿 = `tests/delegate-chain-bulk-load.test.mjs` 同族判据 |

> 已落地的先例（可直接引作判据范例，不在本文重写）：重启重连风暴批
> `tests/delegate-chain-bulk-load.test.mjs` —— 「一轮刷新 = 1 行面 + 1 批量摘要 +
> 有预算的详情腿」「缓存复用」「稳态重连零详情请求」「429 退避不成紧循环」四条已具名。

## 2. 加载速度红线（PERF-LOAD-*）

**一句话：首屏有**请求数**与**体积**两道上限，关键读接口有**响应时间**预算；超预算
的处理方式是「先砍请求/体积」，不是「先发再优化」。**

| id | 要求 | 阈值位 | 判据形态（回填后成闸） |
|---|---|---|---|
| `PERF-LOAD-001` | **首屏请求数预算**：首屏（到可交互）发出的 HTTP 请求数 ≤ N，禁碎片化拆包 | N = **由 perf-fixes 批回填** | 渲染腿：`page.on('request')` 计数。**参照基线：打包后首屏 76 文件** |
| `PERF-LOAD-002` | **首屏体积预算**：首屏传输总量 ≤ X（gzip），单文件超预算必须拆/懒加载 | X = **由 perf-fixes 批回填** | 渲染腿：响应体求和。**参照基线：1.07 MB gzip** |
| `PERF-LOAD-003` | **关键读接口响应预算**：首屏必然发出的读接口，P95 响应时间 ≤ T | T = **由 perf-fixes 批回填** | 诊断批读数（本机基线定档）；CI 只做静态预算表在场断言 |
| `PERF-LOAD-004` | **非首屏件必须懒加载**：重面板 / 大依赖（图表、编辑器、媒体查看器）不得进首屏 bundle | 懒加载边界清单 = **由 perf-fixes 批回填** | 静态：登记表逐件核「是否静态 import」 |
| `PERF-LOAD-005` | **冷启动不做全量拉取**：boot 阶段只取渲染首屏所需；其余按需 | 首屏必需集合 = **由 perf-fixes 批回填** | 静态：boot 路径的请求点 ⊆ 登记集合 |

## 3. 内存与渲染红线（PERF-MEM-* / PERF-RENDER-*）

**一句话：长列表**不许全量上 DOM**，交互**不许长帧**；内存增长必须有上界（虚拟化、
回收、取消订阅）。**

| id | 要求 | 阈值位 | 判据形态（回填后成闸） |
|---|---|---|---|
| `PERF-MEM-001` | **长列表渲染约束**：条目数超阈值必须虚拟化/分页/增量渲染，禁一次 `innerHTML` 全量上 DOM | 即渲染条目上限 = **由 perf-fixes 批回填** | 静态：滚动面族清单必须命中「虚拟化或分页」实现点；渲染腿：DOM 节点数上限 |
| `PERF-MEM-002` | **DOM 节点预算**：单面稳态 DOM 节点数 ≤ N（超 = 泄漏或没回收） | N = **由 perf-fixes 批回填** | 渲染腿：`document.querySelectorAll('*').length` |
| `PERF-MEM-003` | **事件/订阅必须可释放**：`setInterval`/`addEventListener`/WS 订阅必须配对注销，页面离开即成对拆除 | 泄漏判据 = 同面进出 N 次节点数不增 | 静态：注销点在场；渲染腿：进出循环后读数 |
| `PERF-MEM-004` | **缓存必须有界**：任何内存缓存（Map/数组）必须有容量或 TTL 上限，禁无界 `Map.set` | 容量上限 = **由 perf-fixes 批回填** | 静态：缓存声明处必须有容量/TTL 常量 |
| `PERF-RENDER-001` | **交互帧预算**：一次交互（滚动/切换/展开）不得产生长帧 | 长帧阈值 = **由 perf-fixes 批回填**（口径参照 Web Vitals long task 50 ms） | 渲染腿：`PerformanceObserver` longtask 计数 |
| `PERF-RENDER-002` | **动画/过渡不许进 hot path**：`transition: all` 与逐帧布局属性写入在滚动/长列表上禁用 | 白名单见 `feat/panel-mobile-perf-diagnostics` 已落档 | 静态：`transition: all` 零命中；渲染腿：滚动期 layout 次数 |
| `PERF-RENDER-003` | **重排/重绘不得由 JS 逐帧触发**：读-写分离，禁在滚动回调里同步改样式 | — | 静态：滚动回调内的样式写入点登记 |

> 已落地的先例：`feat/panel-mobile-perf-diagnostics` 提交 `b4849685f`（手机面板 hot-path
> `transition: all` → 显式白名单，7 处，行为零变）—— 本规范 §3 `PERF-RENDER-002` 即把它
> 从「一次性修复」固化成**常驻红线**。

## 4. 插件要求（作者原话「同时也规范到我们插件要求里」）

**红线对插件同样生效，且插件是**下发给别人的**运行面 —— 预算不达标不许以「示例/演示」
为由放行。**

| id | 要求 | 阈值位 |
|---|---|---|
| `PERF-PLUGIN-001` | 插件随包下发的脚本/资产计入**首屏体积预算**（§2 `PERF-LOAD-002`）；超预算件必须由插件自己懒加载，不得让宿主首屏背 | 单插件首屏增量 = **由 perf-fixes 批回填** |
| `PERF-PLUGIN-002` | 插件 manifest/description/Plugin.md 不得声明「不计预算」式豁免；豁免只许在本文 §6 具名登记 | — |
| `PERF-PLUGIN-003` | 插件若自建轮询/MCP 长连，必须遵守 §1 `PERF-NET-004/005/006`（周期与退避上限同档） | 同 §1 阈值位 |
| `PERF-PLUGIN-004` | 插件的 `scripts/` 验收件必须有执行预算，禁无上限扫描（宿主 CI 会被它拖住） | 单脚本超时 = **由 perf-fixes 批回填** |

## 7. 与性能修复批（`feat/panel-mobile-perf-fixes`）的对齐契约

**本批（正文骨架）与修复批（阈值 + 实现）是两半，接口固定如下，两边都不许改形状：**

1. **stable id 不变**：`PERF-NET-001..006` / `PERF-LOAD-001..005` / `PERF-MEM-001..004` /
   `PERF-RENDER-001..003` / `PERF-PLUGIN-001..004` 一经落文即冻结；新增只能追加编号，
   禁重排、禁改语义。
2. **阈值格形状不变**：「由 perf-fixes 批回填」是**占位符**，替换时只许换成「数值 + 单位」，
   禁顺手改列名/增删列（闸按列位读）。
3. **状态位交接**：修复批回填完毕把 frontmatter `status:` 从 `draft` 改 `active`，并在
   本文件 §8 追加一行「回填提交 = <sha>」。
4. **闸随后出生**：阈值落地后新增 `scripts/check-perf-budget.mjs`（§5 表 1–4 逐行读），
   注册进 `scripts/run-checks.mjs` 的 `static` 档；本文 §9 届时替换成本文机检节。
5. **本批不做**：不写闸、不采基线、不改任何产品代码 —— 只有正文。
