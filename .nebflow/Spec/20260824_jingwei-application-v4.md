## 一、商业计划书概述（正文）

### （一）创业项目概述与立项依据

#### 1. 项目的立项依据（项目背景与拟解决的真实问题）

大语言模型（LLM）解决的是"大脑"问题：Kimi、GLM、DeepSeek 等模型本身只提供推理能力，并不能独立完成一项任务。真正的智能体（AI Agent）是 **LLM + Harness** 的组合——Harness 为模型搭建"身体"，使其具备持续规划、调用工具、处理反馈、完成长任务链的能力。Cursor、Claude Code 等产品之所以区别于纯对话模型，正是因为它们各自实现了不同的 Harness。**Nebflow 做的正是 Harness 层**：它不是重新定义 Agent，而是改变人与 Agent 的交互方式。

当前主流 Agent 产品（以 Visual Studio Code 为代表）均以"多会话并行"组织交互：用户按任务创建独立 Session，每个 Session 上下文隔离、并行管理[4]。这种多信息入口模式存在三个普遍问题：

**① 注意力切换的认知债。** Agent 任务常需 10 分钟以上持续运行，用户被迫多开 Session 并行推进。但人脑无法瞬时切换注意力——每次切换都需要回忆该会话的上下文、重新判断下一步，这种频繁切换对注意力的损耗远超一般认知[1]；长期使用会明显降低人对单一事务保持专注的能力。

**② 并行任务的上限。** 即使忽略认知债，人能够同时指挥的任务也受注意力广度限制（实际感受约 5 个）。超过上限后，用户会频繁遗忘"哪个会话还在等我输入"。

**③ 跨会话失忆。** 不同 Session 的上下文相互隔离：用户在 A 会话交代的事情 B 会话不知道，用户必须充当"传话人"手工补充上下文。这从根本上限制了 Agent 的自主性——没有任何一个会话拥有完整上下文，Agent 无法自动发现任务、跨项目自动协作。

Nebflow 采用与主流产品相反的**单信息入口**设计：所有任务从**一个**持续会话窗口接入（如同"总机"统一转接，而非"对讲机"各自占频），由系统在后台完成任务的规划、派发与执行。单入口带来的本质差异是：**这一个会话拥有全量记忆，越用越懂用户**。它直接消解上述三个问题——不存在跨会话，无需补充上下文；用户一次性交代全部任务，系统自行规划并持续盯进度；Agent 可同时稳定跟踪 10-20 个任务（实测并发效率较人工多会话提升 200%~400%）。

随着 LLM 能力持续提升，Agent 产业正由单次问答走向持续规划、工具调用与长任务自主执行，long-horizon agent、multi-agent orchestration 与 long-term memory 已成为研究热点[1]-[3]；开发者调查显示 84% 的开发者已在使用或计划使用 AI 工具，但 46% 不信任其输出准确性[5]，"持续委托复杂任务"仍有巨大空间。Nebflow 面向这一缺口，提供以单会话、长时程自主工作、多智能体编排、长期记忆为核心的 Agent 协作平台。

#### 2. 项目产品/服务内容、创业目标，以及拟解决的关键技术与产品问题

**交叉学科特色。** 本项目是人工智能、大语言模型与软件工程交叉的产物，其核心价值源于**把 AI Agent 能力与一线科研工作流深度融合**。项目负责人就读于地球和空间科学学院行星科学与探测技术专业，长期从事空间探测载荷电子学与数据处理：包括探测器前端 FPGA 逻辑开发、束流实验数据采集与离线分析、CZT/SiPM 等新型辐射探测器读出电子学研究。这些工作的共同特征是**多项目并行、单任务周期长（数月级）、数据—代码—论文复合工作流**——恰是当前多会话 Agent 模式的痛点场景。Nebflow 以单入口多任务协同解决该问题，属于"单一学科（AI Agent）技术成果应用于多个领域（空间探测、高能物理实验、软件开发等）"的典型交叉应用，并反向以一线科研需求驱动产品形态设计。

**产品与服务内容。** Nebflow 是一款单会话多任务协同 Agent 平台。用户只需在一个持续会话中提出多个目标，主 Agent 负责理解、拆解与调度，通过 Delegate（任务委派）、Flow（工作流）与 Team（团队协作）三种粒度把独立或关联任务分配给多个 Agent 并行执行，在统一上下文中共享信息、持续推进与汇总结果。系统具备长期记忆（用户/Agent/项目三级持久化）、上下文压缩、MCP 工具接入、权限管理与跨设备通信能力，可长时间自主运行，形成"持续工作的科研助理"。

**拟解决的关键问题：** ① 通过单会话减少多窗口切换与重复交互，消除注意力切换的认知债；② 通过多 Agent 编排实现并行任务上限从"人盯 ~5 个"提升到"系统盯 10-20 个"，并发效率提升 200%~400%；③ 通过三级持久化记忆使历史信息跨任务自动调用，Agent 具备完整上下文与自主派发能力。面向的典型场景：科研人员文献检索+代码分析+数据处理+结果分析+报告撰写的复合工作流、探测器电子学的 FPGA 开发迭代、束流实验多环节数据管道等。

#### 3. 拟采取的技术路线与实施方案及可行性分析

技术路线采用"单会话交互层 + 主 Agent 规划层 + 多 Agent 编排层 + 长期记忆层 + Flow 工作流层 + 工具连接层"六层架构（沿用 v3，见原稿）。用户输入目标后，主 Agent 完成理解与规划，根据任务结构选择 Delegate、Flow 或 Team 进行协作；系统通过共享上下文、任务状态、持久记忆以及验证、重试机制支撑长任务连续运行。

产品开发按"单会话核心交互—长期记忆—多任务并行—Delegate/Flow/Team 编排—长时程自主任务—科研助理场景—行业应用"推进。现有原型已实现 Multi-Agent、Flow、任务委派、三级记忆、上下文压缩、MCP、权限管理和跨设备通信等主要模块，并形成 Web UI、CLI 及 Agent Runtime 基础（详见"创业基础"）。

测试围绕三条核心能力：一是长时程任务测试（持续运行时间、阶段完成率、异常恢复率、目标保持能力）；二是多 Agent 编排测试（并行吞吐量、任务依赖处理准确率、结果汇总质量）；三是单会话与长期记忆对照测试（任务切换次数、重复输入次数、任务完成时间、历史信息调用准确率、用户操作负担）。用户验证面向高校科研人员与开发者，优先选取"FPGA 开发 + 束流数据处理 + 论文撰写"等负责人所在的真实科研场景开展。

### （二）创业基础

项目已完成较大规模的软件原型开发，形成公开 GitHub 代码仓库。Nebflow 已具备 Web/CLI 双端使用、多模型接入、工具调用、多 Agent、Flow、MCP、长期记忆、权限控制及跨设备协作等核心能力；持续版本迭代，具备完整的架构文档、问题管理、自动化测试与版本发布体系。产品已在负责人自身的行星探测科研工作中投入日常使用（束流实验数据处理、FPGA 工程辅助等），形成"真实场景驱动"的开发验证闭环。

前期市场分析表明：AI coding assistant 正快速 Agent 化，GitHub Copilot、Cursor、Claude Code 等已形成成熟市场；同时开发者对更低成本、更高准确率、更强数据安全性的需求明显。项目选择"本地优先 + 模型开放 + 多 Agent + 工作流 + 跨设备"差异化方向，计划通过开源社区、开发者试用及高校科研用户反馈验证市场需求。
