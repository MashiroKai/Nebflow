### 修复：产品语义为基线，按 |dx| 分派（`edgePathD(g, phase)`）

产品对照：`src/main/resources/web/js/flowMapTab.js` `edgePathD()`（控制点竖向偏移、`M x y C x y′ x₂ y′ x₂ y₂` 形）+ `src/main/resources/web/css/flowMap.css` 三档边样式（`.flow-edge.fm-edge.delivered/inflight/idle`）。产品布局是「层为行、层内横排」→ 层间边天然 dx≠0 → 产品曲线可见；原型 v3.3 网格布局链内边 dx=0 → 同一公式退化为直线。**公式没病，是输入全是对齐边**——故修复落在按 |dx| 分派：

| 边类型 | 形状（v3.4） | 参数 |
|---|---|---|
| 跨列边（\|dx\|≥1） | 产品样式不变：控制点 x=端点 x（竖直切线），竖向控制距随 \|dx\| 放大 → **更大的弧** | `dy = max(0.45·len, min(0.55·\|dx\|, 0.75·len))`，下限 24；0.75·len 上限防控制点交叉导致曲线上飘回勾 |
| 同列边（\|dx\|<1，本快照 18/18） | 控制点**同向水平相位偏移** k → 弧顶横向偏差 0.75\|k\|≈15px 柔和括弧弧；相邻边方向 ± 交替 → 链内连线呈连续波流 | `\|k\| = clamp(0.30·len, 16, 40)`，dy=0.75·len（标准行隙 66px → 49.5，端点切线倾角 atan(k/dy)≈22°，入卡出卡仍近竖直） |

保持不变：端点=上游卡底中心→下游卡顶中心（实测卡高回填 + WS 重算）、产品状态色/宽度（delivered sapphire/0.75 w2 实线 / inflight 行军蚁 5 4 / idle border w1.5）、deps 虚线 3 4 与空心箭头、箭头卡顶缘 −4px、hover 邻接边高亮。确定性：phase 由边序（快照序）决定，无随机源。

### 布局考虑连线美观：分析结论 = 布局零改动（三项杠杆逐一评估）

| 候选杠杆 | 评估 | 结论 |
|---|---|---|
| 减少不必要的长距离跨列 | 链间无跨链边（布局不变量）+ 链内重心序（4 轮下沉）已把宽链层内折返最小化——同口径实测 maxDx=0（无跨列边）、v3.3 与 v3.4 交叉数同为 0 | 无杠杆可取，现状已最优 |

## 修改④ 布局 v3.3（历史）：圆形渐扩网格（紧凑填满，含 v3.2 空白根因）

### 根因注记（v3.2 为何「空白多」）

v3.2 行带打包把每条行带**撑满固定画幅宽**（宽行带决定 W=3484px），节点少的行带（如 1 节点的链尾行）按同一宽度居中 → 左右大片空白；且行带间 90px 呼吸隙逐层累积（H=2310px）。作者 12:27 意见直指此点：轮廓要「像一个圆或者方形这样逐渐扩张」。

### 算法（伪代码级，步骤 1-4 与 v3.1/v3.2 相同）

```
输入：节点表 NODES（out + deps 建有向边 up→down）、目标比例 R = 视口/stage（钳制 [1.2, 2.2]）
1-4. 无向连通分量 → 链；链内最长路径分层（Kahn + 松弛，空 Set 兜底）；逐层重心序（4 轮下沉）
5. 链排序：高度↓ → 宽度↓ → 快照序
6. 选列数 C：行数 Rn = max(最长链层数, ceil(N/C))；行距 = V_SPACING 180（产品值不变）；
   列距 p = clamp(round((R×H − NODE_W)/(C−1)), 174, 252)；
   可行域：画幅比例 W/H ∈ [1.0, 2.2]（保持横版）→ 取包围盒面积最小的 C（平局：空格少 → C 小）
7. 列填充：链依次放入「窗口最大高」最矮的列窗（宽 w 链占 w 邻列，平局取左）→ 列高差 ≤ 1
8. 圆形轮廓：列按 高度↓ 从画幅中心向两侧交替排布（最高列居中）+ 各列垂直居中
   （列顶行 = floor((Rn−列高)/2)）→ 轮廓自中心向外渐扩；列高全等时 = 方形网格（统一实现）
9. 落坐标：列 x = slot×p；链内 level 向下递进（y = (列顶行+链落行+lv)×180）
不变量：链内相对层级完整保留（上游 y < 下游 y，竖直连线）；链间无跨链边 → 重排不影响总边长；
       全部决胜落快照序（确定性）。本快照实测：C=8 / Rn=10 / p=252 / 列高 [5,5,6,10,6,6,5,5]。
```

### 对齐让步（作者「紧凑填满」优先，按任务约定记录）

| 让步项 | v3.2 | v3.3 | 理由 |

| 链顶对齐行带顶 | 同带各链第 0 层对齐成行 | 取消——各列垂直居中，行 = 网格行 | 链顶对齐是行带语义的一部分，与「列高均衡填充」互斥；紧凑优先 |
| 「行带」语义 | 行带 = 一条水平工作流行 | 行 = 网格行（同 y 节点可能分属不同链/不同层） | 同上；层级方向性改由「链内边两端纵向递进」保证（L1 断言保持） |
| 行档数 | 9 档（3 带 × 3 层） | 10 档（Rn=10 由最长链决定） | 行档数改由数据（最长链层数）决定，不再断言 ≥6 固定值 |

## 修改① 布局 v3.2（历史）：层级纵排 + 行带打包（含 v3.1 根因修复）

### 根因注记（v3.1 为何「平的」）

v3.1 布局 Kahn 分层入度统计写的是 `(ups.get(id) || []).size`——**空数组没有 `.size` 属性（得 `undefined` 而非 0）**，入度 0 的节点永远进不了拓扑队列 → 全部节点 level=0 → 任意边两端同层 → 连线全部退化为水平直线，整图「平的」（盘上实测 9/9 条边全水平；v3.1 回归 24/24 全绿但**没有方向性断言**，未拦截）。v3.2 改用空 `Set` 兜底，分层恢复生效（当前快照 L0=28 / L1=6 / L2=3）。

### 算法（伪代码级，v3.1 步骤 1-4 不变；5-7 由柱状打包转置 90°）

```
输入：节点表 NODES（out + deps 建有向边 up→down）、目标纵横比 R = 视口/stage 比例（钳制 [1.2, 2.2]）
1. 无向连通分量 → 链集合（快照序发现）
2. 链内最长路径分层：Kahn 拓扑 + 松弛（level[y] = max(level[x]+1)；空 Set 兜底修复；有环防御）
3. 链内逐层重心序：4 轮下沉扫描（平局落快照序）
4. 链度量：h = 层数（纵向跨度），w = 最宽层节点数；链排序：高度↓ → 宽度↓ → 快照序
5. 行带打包（「链入最窄行带」= v3.1「链入最矮柱」的 90° 转置）：
   试 k = 1..min(K,8) 条行带；链依次放入当前最窄行带（平局取低索引）；
   候选评分：|W/H − R| 最小（平局取小画幅）→ 确定性选出 k
6. 落坐标：行带自上而下堆叠（带间 90px 呼吸隙）、带内链从左到右并列（链间 90px）、
   链内层级向下递进（lv × V_SPACING）、链顶对齐行带顶（同带各链第 0 层对齐成行，行带语义干净）
不变量：链间无跨链边 → 打包方式不影响总边长；
       链内相对层级完整保留（任意链内边两端呈纵向递进，上游 y < 下游 y）。
```
