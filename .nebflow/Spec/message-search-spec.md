## 0 · 一句话目标

把搜索弹窗从「空态等输入的搜索工具」升级为**微信式的「检索窗口」**——打开即浏览最近消息，栏目条按内容类型正交筛选，搜索词在选中栏目范围内渐进匹配，日期改为锚定栏目条的日历气泡弹层、选日即**定位锚点**（非筛选），结果流以锚点为中心双向连续加载、跨日无缝 [R1 2026-08-17 用户裁定]。

### 提炼的可执行规则（微信范式 → 本次设计约束）

1. **打开即浏览**：默认态 = 最近内容倒序列表，不是空态提示文案
2. **栏目 = 内容类型筛选**：栏目条置于搜索框与结果区之间；未选栏目 = 全部类型范围
3. **检索在栏目范围内完成**：选中栏目后搜索词仅在该类型内匹配；切栏目**保留搜索词**并重搜
4. **日期是定位锚点，不是筛选条件** [R1 2026-08-17 用户裁定]：点「日期」弹日历气泡，选定后列表**滚动定位**到该日消息位置（不过滤、不截断时间范围）；以锚点为中心双向连续加载，从 5 号滑到 6 号中间不断、不重新全量查询
5. **日历交互四要点**：锚定弹层（非独立窗口/非原生 input）、年/月下拉、周一起始（zh）、未来日期禁选、单选 + 取消/确定

### 2.1 栏目结构裁定（核心决策）

| 栏目 | 语义（匹配规则，落到 normalizeMessage 输出） | 微信对应 |
|---|---|---|
| **全部** | 不加类型过滤（默认激活） | 未选栏目的隐式全部态 |
| **图片** | 消息携带 ≥1 个 `attachment.type === 'image'`（协议事实：`UiMessage.User.attachments: List[Json]`，protocol.scala:245-247——图片/文件仅存在于用户消息） | 图片与视频 |
| **文件** | 消息携带 ≥1 个非 image 附件 | 文件 |
| **Pop** [v3.2 更名] | `kind === 'tool'` 且 `cleanToolName(label) ∈ {'Pop', 'Card'}`——Pop 工具（Canvas 展示）产出；`'Card'` 为更名前历史消息的兼容匹配（Card 工具已停用，v3.2 前栏目名为 Card） | —（Nebflow 语境新增，对应微信「小程序/视频号」这类平台特有类型位） |
| **日期** | **非内容栏目，是定位动作** [R1]：点击弹日历气泡（§5），选定后列表滚动定位到该日（锚点），**不过滤内容**；锚点与内容栏目共存（例外见 §3 [R1 组合裁定]） | 日期 |

**裁定理由**：微信栏目全部是「内容类型」，Nebflow 语境下用户消息的产物是图片/文件附件，agent 侧的独特产物是 Card 卡片；链接/音乐/视频号在 Nebflow 无语义对应物，不凑数（克制原则）。「工具调用」不设独立栏目——既有 tool select 已覆盖且更细（具体工具名+计数），栏目条与 select 形成「粗筛→细筛」两级，不重复造。

### 2.2 栏目 × session 的组合裁定（正交共存）

- **两个维度正交，AND 语义**：栏目筛内容类型，scope 筛会话广度。`scope=all` 时结果仍按会话分组（`.search-group-header` 组头不变），栏目过滤作用于组内条目；某会话在该栏目下 0 命中 → 该组头不出现
- **默认 scope 保持 `current`**（不改为 all）：微信窗口本就锚定单会话（「与某人的聊天记录」），Nebflow 弹窗默认当前会话与之同构，且免去打开即全量抓取的性能代价；切 `scope=all` 即全局浏览（已验收的分组聚合不变）
- **tool select 联动规则**：栏目=全部 时 tool select 可用（细筛）；栏目∈{图片， 文件， Card} 时 tool select **禁用**（`disabled` + `aria-disabled` + title=`search.toolDisabledHint`）——语义互斥或已收敛，禁用比"可选但出空结果"更少困惑
- **agent select 不联动**：任何栏目下均可用

### 2.3 进入即有内容（默认浏览态）

| 项 | 规格 |
|---|---|
| 触发 | 弹窗打开（`openSearchModal`）立即执行一次 kw 为空、栏目=全部、无日期的查询——即现状 `triggerSearch` 的 `!kw && !hasFilters → showIdle()` 分支改为**执行浏览查询** |
| 展示内容 | 当前 scope 内**最近消息时间倒序**（不带时间戳的 tool/ask 类排尾部，沿用现状排序规则）；浏览态无 mark 高亮，摘要取消息开头 180 字符（highlightPreview 的 kw 空分支现状已支持） |
| status 行 | 浏览加载中显示 `search.progress(done,total)`；完成后显示 `search.results(n)`（复用既有 key，不加新状态文案） |
| 旧空态文案 | `search.hint` **不再出现于打开态**；仅保留在……（裁定：彻底移除打开态 hint，无结果一律走 §3 空态分支） |
| 每次打开重取 | Spotlight 模式保留：每次打开是全新浏览查询，不缓存上次结果 |

## 3 · 交互状态机表（搜索词 × 栏目 × 日期三维组合）

三维状态记为 `(kw, tab, date)`：**kw 与 tab 是筛选维度，组合语义 AND；date 是定位维度（锚点），不参与过滤** [R1 2026-08-17 用户裁定]。

| 状态 | 条件 | 视觉表现 | 退出路径 |
|---|---|---|---|
| 浏览态（默认） | kw 空 + tab=全部 + date 无 | 最近消息倒序列表；栏目条「全部」激活 | 输入 / 切栏目 / 选日期 |
| 栏目浏览态 | kw 空 + tab≠全部 + date 无 | 该类型内容倒序；**无独立"栏目计数"徽标**（微信无此设计，克制） | 切回全部 / 输入 / 选日期 |
| 栏目内检索态 | kw 非空 + tab 任意 | 搜索词仅在当前栏目类型范围内匹配；结果摘要 mark 高亮（现状逻辑不变） | Esc 清空 kw → 回到栏目浏览态 |
| 日期锚定态 [R1] | date 有（任意 kw/tab） | 「日期」栏目激活且标签变为锚点日期（locale 短格式，如「8月17日」）+ 行内 × 清除符；**列表不过滤**——以锚点日为中心双向连续加载：向列表顶部方向加载更晚、向底部方向加载更早，跨日无缝（5 号滑到 6 号不断、无全量重查） | 点 × / 弹层内「清除日期」→ 回默认浏览流（定位回最新）；Esc 不清除锚点（见键盘契约） |
| 空态·栏目无内容 | kw 空 + 当前 (tab,date) 组合 0 条 | `.search-hint` 显示 **`search.emptyCategory`**（新 key，见 §6 清单） | 切栏目 / 清日期 |
| 空态·搜索无结果 | kw 非空 + 0 命中 | 沿用 v2.1：`search.noResults` + `search.noResultsSuggestion`（key 不变） | 输入变更 / 切栏目 / 清日期 |
| 搜索中 | 任何维度变更后 300ms debounce 到期 | 沿用 v2.1：旧结果降透明度 0.5 + status 进度 | 完成 → 对应结果态 |
| 错误态 | fetch 抛错 | 沿用 v2.1：`search.failed` + 重试按钮（.glass-control） | 重试 / 维度变更 |
| 日历弹层开 | 点「日期」栏目 | 气泡锚定栏目下方（§5）；弹窗本体保持打开 | 确定 / 取消 / 点弹层外 / Esc → 关弹层（不关弹窗） |

**关键行为裁定（标注微信依据）**：

1. **切栏目保留搜索词**——微信行为（用户原文"检索是在标签下完成的"），切栏目立即按新范围重搜（复用 300ms debounce + requestId 竞态）
2. **日期选中后「日期」栏目进入激活态**（标签=日期文本 + ×），点 × 清除锚点、恢复标签「日期」且列表回默认浏览流（定位回最新）——微信隐式行为（日期生效后栏目即其入口），本规格显式化 [R1：语义从"清除筛选"改为"清除锚点回浏览流"]
3. **[R1 2026-08-17 用户裁定 · 组合语义] 筛选与锚点正交共存，不互斥禁用**：搜索词/内容栏目（图片/文件）激活时选定日期 → 锚点作用于**筛选后的流**，定位到该流中时间戳 ≤ 锚点日 23:59:59.999 的第一个条目（即"从该日起向更早浏览"的起点）；若流中条目全部晚于锚点日，定位到流尾（最早处）。理由：筛选是内容维度、锚点是时间定位维度，二者正交——主场景"找 5 号发的那张图"= 图片栏目 + 定位 5 号，互斥禁用会砍掉该场景，且与微信"标签下检索 + 日期定位"并行的用户心智不符。**唯一例外**：Card 栏目下 Tool 消息 ts 恒 0（§6.1），锚点定位恒无意义 → Card 激活时「日期」栏目禁用（`aria-disabled` + title=`search.dateDisabledInCards`，新 key 见 §6.2），切回其他栏目即恢复
4. **Esc 扩展为三段式**（v2.1 两段式之上加一层，语义显式化）：① 日历弹层开 → 仅关弹层；② kw 非空 → 清空 kw 回浏览态（**不清栏目、不清日期锚点**——栏目/锚点是导航状态不是输入内容）；③ 其余 → 关弹窗
5. **打开弹窗时状态全重置**：kw 空、tab=全部、date 无（Spotlight 每次全新会话，与 v2.1 一致）
6. **键盘契约沿用 v2.1**（↑↓/PageUp·Down 导航、activeIndex 显式语义"渲染完成瞬间 =0"、Enter 跳转、focus trap、弹窗开时背景快捷键静默），新增可聚焦元素（栏目条、日历弹层控件）纳入 trap 循环；栏目条支持 ←/→ 在栏目间移动（ARIA tablist 模式）

## 4 · 动效规范

| 动效 | 触发 | 参数 | reduced-motion |
|---|---|---|---|
| 弹窗入场 | 打开 | 沿用 v2.1 `modalIn` 0.2s `cubic-bezier(0.16,1,0.3,1)` | 0.01s 瞬现（不变） |

### 6.3 数据获取模型 [R1 2026-08-17 用户裁定 · 新增]：从「查询」到「查询 + 锚点定位 + 双向分页流」

v3 模型 = 单次查询（kw/栏目/日期变更 → 全量重查，200 截断兜底）。v3.1 按锚点语义拆分三种模式：

| 模式 | 触发 | 数据行为 | 约束关系 |
|---|---|---|---|
| **初始浏览态流式加载** | 打开弹窗 / 切栏目（kw 空） | 请求最新一页（单页 ≤200）；滚动至底部 sentinel 且渲染批次耗尽 → `before` 游标取更早一页，DOM 增量追加，**不重查已加载区间** | 并发 4 不变；浏览总量不设硬顶（分页增量受控） |
| **锚点跳转** | 日历弹层选日点「确定」（kw 空） | 以锚点参数请求"锚点页"（时间戳 ≤ 锚点日 23:59:59.999 的最新一页，单页 ≤200）→ 列表替换式重渲（**全流中唯一一次替换加载**）；此后**双向分页**：向上触顶 → `after` 游标取更晚、向下 sentinel → `before` 游标取更早；跨日（5 号滑到 6 号）只是游标自然延伸，无特殊分支、无全量重查。**「触顶」触发面** [2026-08-17 设计评审 F-1 补条款]：scroll 监听 + **wheel-up/上拉触摸溢出兜底**——锚点重渲后列表常生于 scrollTop=0（滚轮在顶端不产生 scroll 事件），向上的 wheel/touch 手势在 scrollTop≤2 处即视为触顶信号直接触发 `after` 分页 | 每方向维护一个游标；游标耗尽（到顶/到底）即停，不再发请求 |
| **检索态（kw 非空）** | 输入/切栏目（kw 非空） | **保持 v2.1 一次性查询不变**（300ms debounce + requestId 竞态 + 200 截断 + status 截断提示）；日期锚点在检索结果流内**客户端定位**（滚动到首个 ts ≤ 锚点日的条目），不发额外请求 | 既有抓取约束原样保留；截断提示仅存在于此模式 |

**裁定理由**：① 浏览/锚定是"逛"，分页流匹配无限时间线；检索是"找"，一次性有界查询匹配精确心智，二者不混。② 200 从全局截断改为单页上限后，浏览态不再丢失历史（v3 下 >200 条即被截断且无从到达），同时每页仍受 200+并发 4 保护，后端压力模型不变。③ 锚点页一次替换重渲是可接受的（用户主动跳转的预期就是"带我去那里"），除此之外一切滚动加载均为纯增量——这是 B13 连续性断言的可执行口径。
