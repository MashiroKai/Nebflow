① 根因定位

缺口环 AgentControl cancel → 会话注销 → WS 广播：第三环整体缺失
  • 面板行由 agentStart 创建（main.js L1948，status='Processing'），只被 agentDone（L2056，done+2s 移除）或会话级 done（L954，node-/dispatcher- 同帧删行）清理。
  • 取消路径零出口：分发器 ProjectActor.dispatcherBridge 的 Failed|Cancelled 分支只做「清 registry + Stop agent」（ProjectActor.scala L299-300）——无任何 WS 帧；node 走 NodeEngine 桥 → resultDeferred(cancelled) → cancelNode，只发 nodeUpdated（Flow Map 契约帧，载荷仅 nodeId，无 agent sessionId，面板无法映射行）。
  • 面板 cancelAgent 的应答 cancelAgentResult{ok:true} 只发往发起连接且注释明确「ok=true is silent」（managePanel.js L86-87）——而报告场景走 AgentControl 工具路径，连该帧都没有。
  • 结果：幽灵 Processing 行滞留至刷新（activeAgents 快照重拉后 registry 已清，行消失）——与报告现象完全一致。

④ 改动清单（文件级）

  • core/node/NodeRunner.scala — 新增 emitSubagentPanelDone：构造 {type:'agentDone', agentId} 帧并经 routeSubagentWsSend 注入三键（唯一帧构造点）。
  • core/project/ProjectActor.scala — dispatcherBridge 增 rootSessionId 参数；Failed|Cancelled 分支拆除前补发面板帧（dispatcher 全取消/失败路径唯一汇合点）。
  • core/tools/AgentControlTool.scala — doCancel 增 notifyWs 参数（默认 None 兼容既有调用）；node-* Flow 会话发 Cancelled 后补发；工具路径传 ctx.wsSend。
  • gateway/WebSocketRoutes.scala — cancelAgent 面板路径传连接 wsSend 进 doCancel。
  • core/processor/TaskStuckWatcher.scala — Flow giveUp 分支 node-* 经 wsHub 补发（dispatcher 由桥覆盖，不重发）。
  • web/js/main.js — done 处理器 node-/dispatcher- 分支删行后立即按 agentDone 2s 收尾同款模式（setActiveView→updateBgAgentIndicator→还原）刷新归属桶徽标与打开中面板（修复删状态不渲染的滞留）。
  • 新增 src/test/.../ProjectSessionCancelPanelFrameSpec.scala（3 测试）+ tests/subagent-panel-cancel-realtime.spec.mjs（3 测试）。

⑤ 遗留问题

  • node-* 会话崩溃（AgentEvent.Failed）路径仍在 NodeEngine.scala（禁改域）——面板行会滞留；恢复需在 NodeEngine 桥 Failed 分支补同款帧（deps 轨道合并后一行接入 emitSubagentPanelDone 即可）。
  • Flow Map UI NodeCancel 路径在 NodeTools.scala（禁改域）——该路径取消后面板行滞留（Flow Map 卡片本身经 nodeUpdated 实时，主界面可见）；同款一行接入可修。
  • bgagent-dedupe.spec.mjs 1 例既有失败（clean HEAD 复现）：zh-CN i18n 中文化后 spec 断言仍期待英文 "running"——spec 自身需修，属 i18n 域，未越界代改。
  • 「重启」场景：node-/dispatcher- 单次会话按设计拒绝 restart（cancel + 重新触发），Delegate/SubTask restart 经 supervisor respawn 重发 agentStart 自然刷新——均无面板缺口，无需改动。
