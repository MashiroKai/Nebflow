# 用户知识泄漏检测模式库（#338 门禁的数据源）
#
# 「数据与逻辑分离」：本文件只声明检测模式；check-user-knowledge.sh
# 读取本文件构造 grep 正则，脚本内不再硬编码模式。新增/删除模式在此
# 维护（随代码走、不进 gitignore，公开后随仓发布）。
#
# 语法：每行一个 grep -E 正则；`#` 开头的整行为注释；行内 `#` 起为
# 行尾注释（模式本身禁止含 `#`）；空行忽略。匹配大小写不敏感（调用侧
# grep -i）。分层标记行 `# === STRICT ===` / `# === WIDE ===` 切换层级。
#
# 分层语义（见脚本 header 的安全设计说明）：
#   STRICT — 高置信泄漏，fail-fast。作者用户名/机构网关/自有公网 IP/
#            API key 形态/个人邮箱。默认与 CI 的 src/main Scala 门禁
#            只应用这一层（对合法产品代码零误报；src/test/ 豁免）。
#   WIDE   — 通用形态，多为合法代码里的占位/示例/产品目录名（非泄漏），
#            仅 --all 全仓参考扫描列出并标注 [review]，不阻塞门禁。
#
# 已知判别（2026-09 校准）：
#   - `kaiyu` 同时覆盖 `/Users/dev`、`kaiyu` 用户名等作者专属字面。
#   - `/Users/[A-Za-z]` 会误中合法产品路径 `/Users/you`（占位）、
#     `C:/Users/name`（Windows 示例）、`/api/users/...`（REST 路由），
#     故放 WIDE；真正泄漏的 `/Users/dev` 已由 STRICT 的 `kaiyu` 覆盖。
#   - `10.`/`192.168.` 私有网段会误中 macOS 版本号 `10.15.7` 与
#     设备示例 `192.168.1.200`，故放 WIDE 并要求四段完整 IP。
#   - `\.nebflow/` 是产品运行时数据目录名（README/ci.yml/源码注释大量
#     合法引用），非泄漏源，放 WIDE 仅供人工复核。
