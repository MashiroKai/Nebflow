ℹ Demo 设计说明

这是什么

Nebflow「Personal Agent」方向的概念 demo：不改任何源码，视觉复刻 src/main/resources/web 的聊天界面（同一套 design tokens / 气泡 / 选项卡语言）。

记忆模型变更

  • Agent.md / agents/Nebula/memory.md → Soul.md（我是谁，由用户在 Onboarding 中定义，随时可改写）
  • User.md 保留（你是谁，共同书写）
  • 项目级 memory.md 退役：不再创建、不再注入 dispatcher / node 提示词；跨项目事实统一进 User.md

命名去硬编码

  • 现状：Nebula 写死在 BuiltinAgents.Names 与 SchemePolicy.NebulaName
  • 方向：首启由用户命名 → 写入 Soul.md + agent displayName，标题栏 / 会话列表 / 提示词全链路引用新名

Onboarding 扩展

  • 现有 onboarding.js 四步（问候 → Q1/Q2 → 凭据卡 → probe 硬门）扩展为六幕：命名 → 模型 → 期待 → 边界 → 大五人格 → 用户画像，收尾是「书写仪式 + 重生问候」
  • 真实实现建议：模型接通后，问卷段改由 LLM 对话式追问（demo 为脚本卡片）；probe 硬门沿用
